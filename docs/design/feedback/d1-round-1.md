## Designer 的推薦
**B 集章冊，晚上診斷借用 C 的逐句對照版面**（保留 B 的配色與印章數字）。理由：B 最符合「活潑＋遊戲化鼓勵」，蓋章直接對應 PRD 早中晚三格打卡（AC-21），不需要新增徽章或點數功能；離 Duolingo 和 Apple 健身圈最遠；不用新字型。B 的弱點是閱讀頁偏吵，C 的逐句對照剛好補上。

- **改過的地方**：A 進度圈太粗會壓到中間的「23」→ 改細並縮小數字；A 下方分頁列被內容蓋住（z-index）→ 修正；A 把黃色里程碑條併進深藍計分板，少一個色塊；A 拿掉「下一步」卡右上角的裝飾圓（減一件配件）；A 未完成步驟的圓圈改深一點（圖形對比 4.0:1）。B 第 3 個數字章被另一個 class 塗黑 → 修正；Mastered 集點圓點太大 → 固定尺寸並移到左欄；「早」章改黑字（螢光粉配白字只有 3.09:1）；拿掉按鈕的錯位陰影（減一件配件，只留紙張的錯位）。C 電腦版右側欄數字被隱藏 → 修正；主句螢光筆不再斷行。

## 驗收檢查（§15.8）
- **360 寬沒有橫向捲動**：用 box 上的 Google Chrome headless，透過 DevTools Protocol 設定 `Emulation.setDeviceMetricsOverride`（mobile=true），讀 `document.documentElement.scrollWidth` 和 `clientWidth`，並列出右邊超出畫面的元素。6 個畫面在 360、412、768、1280、1440 都是 `scrollWidth == clientWidth`，沒有超出的元素（A、B 手機診斷的語塊列是刻意的區塊內橫向捲動，不會讓整頁捲動）。
- **點擊區 ≥ 48×48**：同一個腳本在手機模式量所有 a、button、input、label 的大小；6 個原型畫面沒有小於 48 的（隱藏的原生 checkbox／radio 由外層 48px 以上的 label 承接）。比較頁本身的參考連結是句中的文字連結，不在此限。
- **鍵盤與滑鼠**：所有可點元素有 `:focus-visible` 外框；電腦版有 hover 狀態；診斷頁數字鍵 1～5 勾選語塊（原生 JS），快捷鍵在畫面上有提示。
- **減少動態**：所有動畫（進度圈填滿、蓋章、螢光筆劃過、按鈕回饋）都包在 `@media (prefers-reduced-motion: no-preference)` 裡。
- **字型**：沒有 CDN 或字型服務；A、C 的 woff2 放在各自的 `fonts/`，附 `OFL.txt` 與 `SOURCE.md`；CJK 用系統字（box 上是 Noto Sans CJK，截圖確認中文都有正常顯示）。
- **文字對比**（WCAG 公式計算；文字 ≥ 4.5:1、圖形 ≥ 3:1）：
