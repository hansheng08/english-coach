## 1. 產品一句話
每天打開就有排好的 80 分鐘英文練習（早上讀新聞跟讀、中午不出聲複習、晚上口說診斷），用「語塊」把工程師的英文從「講得出來」練到「講得像 Senior」。

## 2. 使用者（只照 PRD §2）
- 只有一位：Hansheng，軟體工程師，多益約 550～700，3 個月內要面試外商（半導體設備系統軟體、AI 開發與應用）。單人、需登入、不開放註冊（Q-01）。
- 痛點：聽不懂快的英文、開口卡、只會簡單字；練習散在很多工具、要自己備料、沒有累積感（PRD §1）。
- 熟悉科技產品、每天用電腦工作 → 可以接受資訊密度較高的畫面（**不確定**，PRD 沒寫，D1 驗證）。
- 視力、色弱、慣用手等：PRD 沒寫（**不確定**），一律照無障礙基準設計。

## 3. 前 3 個主要任務
1. **照今日課表一步一步做完**：打開首頁就知道現在是哪個時段、下一步是什麼，按一下就開始（AC-01、AC-26）。
2. **練口說並看懂自己哪裡不好**：錄音 → 左右對照診斷 → 勾選升級語塊 → 跟讀改寫版 → 無稿重答（AC-13～18）。
3. **快速複習與收錄語塊**：中午 25 張字卡不出聲作答、手動新增；新聞裡點一下就收錄（AC-03、AC-07～10）。
- 次要：看累積（streak、Mastered 數、成長曲線，AC-21～22）、管理履歷與設定（AC-11～12、AC-24～26）。

## 4. 使用情境
| 裝置 | 何時、在哪裡（PRD §2 S1～S4） | 對設計的意思 |
|---|---|---|
| **手機為主**（Android＋Chrome，PWA 加到主畫面，NFR-01、Q-02） | S1 早上 30 分可開口（在家或出門前，**地點不確定**）；S2 中午 20 分**不能出聲**（辦公室／餐廳，旁邊有人）；S3 晚上 30 分可開口（在家）；可能單手、戴耳機 | 單手、拇指操作；中午畫面完全不碰麥克風、不自動出聲；錄音狀態一眼看懂；每段 20～30 分鐘要能專心不被打斷 |
| **電腦為輔**（Chrome／Edge，≥ 1280 寬，Safari 不驗收） | PRD 只寫「電腦也可完整使用」、AC-23 跨裝置同步；**哪一段常在電腦做「不確定」**（推測：晚上看診斷長文、看紀錄與成長曲線、上傳履歷、改設定） | 用寬度做雙欄（診斷對照、清單＋細節）；鍵盤快捷鍵；滑鼠 hover；長時間閱讀的行寬控制 |

## 6. 手機與電腦的版面差異
- **共同**：360 寬無橫向捲動（也檢查 412、768、1280、1440）；手機可點元素 ≥ 48×48 CSS px；版面同時看寬度與 `pointer: coarse／fine`。

| 群組 | 手機（360～412） | 電腦（≥ 1280） |
|---|---|---|
| A 首頁 | 單欄；「目前時段＋下一步」放最上面，主按鈕在拇指範圍（下方）；底部導覽（**不確定**，D1 定） | 側欄導覽＋主區；三個時段可同時並排看；鍵盤直接開始下一步 |
| B 早上 | 文章單欄，語塊點一下用底部抽屜顯示中文；播放／計次／錄音固定在底部 | 文章限制行寬置中、右側欄放語塊清單與已收錄；跟讀結果與原句並排；空白鍵播放、R 錄音（候選） |
| C 中午 | 一張卡佔滿、三個評分鈕在底部等寬大按鈕；排句子用拖曳或點選（點選優先，單手） | 卡片置中加最大寬度，旁邊顯示今日進度與種子庫剩餘；1／2／3 鍵評分、數字鍵選選項 |
| D 晚上 | 錄音鍵大、在拇指範圍、計時明顯；診斷對照改成上下分段或「原文／Senior 版」切換（見 §10 第 1 題）；升級語塊勾選在底部 | 真正左右雙欄對照（ARCHITECTURE §9）；標記用 hover／focus 顯示說明；勾選區固定在下方或右側 |
| E 累積 | 數字與日曆單欄往下排，圖表可直式閱讀、不橫向捲動 | 儀表板多欄格線；紀錄用「清單＋細節」雙欄 |
| F 管理 | 單欄表單，錯誤標在該格 | 表單限制寬度、兩欄（分類＋內容）；hover 說明 |
| G 狀態 | 全寬提示、重送鈕在拇指範圍 | 行內提示，不擋住其他內容 |

## 7. 感覺關鍵字候選（還沒決定，D1 會變成 2～3 個方向）
- 安靜、專注（像好用的閱讀器或工程工具，20～30 分鐘看得久不累）
- 有進度感、有累積（但不是遊戲化，PRD §4 不做徽章、點數）
- 精準、專業（呼應「說得像 Senior 工程師」，診斷資訊清楚可信）
- 溫和不批判（被指出錯誤時不讓人想放棄）
- 俐落、快（零準備：打開就做）

## 8. 要避免的 AI 樣子（英文學習 App 版）
- 米白底＋陶土橘；近黑底＋螢光綠（「駭客終端機」風）；紫藍漸層、毛玻璃。
- 整頁同款圓角卡片＋陰影；置中大標題＋三張圖示卡的首頁。
- emoji 當圖示（🔥 streak、🎯、🚀、📚）；吉祥物、紙花、過度慶祝動畫。
- Duolingo 翻版：綠色貓頭鷹感、圓胖按鈕、闖關地圖、寶石／愛心／排行榜。
- 全大寫小標、`01／02／03` 假序號、`A · B · C` 分隔、按鈕後黏 `→`。
- Inter 一路到底、只靠字重區分層級；到處淡入上滑。
- 錯誤一律紅色大叉、對錯只靠紅綠（色弱看不出）；診斷 3 種標記只用顏色區分。
- 為了「看起來 AI」加的光暈、閃爍、打字機效果、Sparkle ✨ 圖示。
- 原則：只在一個地方大膽（候選：跟讀過關或 chunk 講出的回饋），其他保持安靜。

## 9. 限制
- **ADR-001**：React 19＋Vite＋CSS Modules，不用 UI 框架、元件庫、CSS-in-JS；token 用 CSS 變數＋CSS Modules（落地方式由 Architect 在 G2 增補決定）。
- **不新增依賴**：字型服務（例如網路字型）、圖示庫、圖表庫、動畫庫都要先寫進 `docs/OPEN_QUESTIONS.md` 給 Architect；D1 方向先以系統字型可行為前提，網路字型列為選項。
- 文字對比 ≥ 4.5:1（大字與圖形元件 ≥ 3:1）；尊重「減少動態」；鍵盤焦點清楚可見。
- 中英混排：介面中文（台灣）、內容英文；英文長句、逐字稿、標記要好讀。
- Android Chrome 優先，桌機 Chrome／Edge；不離線（斷線要有提示）；中午畫面不碰麥克風（AC-08）。
- 深色模式：D1 決定要不要做。
- 原型只用靜態 HTML／CSS＋假資料，放 `docs/design/prototype/`。

## 10. D1 研究方向（候選，不是最後方向）
1. **閱讀與標註工具**：電子書閱讀器、稍後閱讀、程式碼審查的 diff 介面 → 新聞閱讀的行寬與標註、診斷左右對照與 3 種標記怎麼做得清楚。
2. **專注計時與每日例行**：練習計時、運動或冥想課表類 App → 早中晚時段、步驟進度、「下一步」怎麼做到零思考。
3. **專業工具感的學習產品**：給成人用、非遊戲化的語言或發音練習工具、錄音與波形介面 → 錄音、跟讀結果、成長曲線怎麼可信又不嚇人。

## 11. 未決事項／需要 Hansheng 確認（最多 3 題）
