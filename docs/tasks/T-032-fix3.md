## 背景（開始前先讀）

- **原因**：`origin/main` 的 `supabase/migrations/20261128100000_t046_audio_bucket_purge_cron.sql`（T-046，commit `c189e24`）和 `task/T-032` 的 `supabase/migrations/20261128100000_t032_card_review_date_record_review.sql`（commit `f6c4968`）時間戳記都是 `20261128100000`。Supabase 用時間戳記當 migration 版本，兩個檔同版本，`supabase start` 套第二個時寫 `schema_migrations` 主鍵衝突。PR run 的 checkout 沒有指定 `ref`（`.github/workflows/ci.yml`），用的是 PR 與 main 的合併結果，所以兩個檔同時存在；push run 只檢出分支本身，分支從 `bb8c7b7` 開出，沒有 T-046 的檔，所以綠。程式沒有錯。
- **為什麼會撞**：T-032 與 T-046 兩張單都寫「時間戳記取寫檔時的台北時間，必須比最新的檔案晚」，但兩個分支各自看不到對方的檔，而且兩邊都填了整點 `100000`（T-032 commit 是 09:58、T-046 commit 是 13:52 台北時間，都不是 10:00:00）。規則只能擋「同一棵樹裡」的順序，擋不到「兩條分支」之間的撞號。
