## 目標
`bundle` job 建置後掃 `apps/web/dist/**` 的每一個檔：出現任一後端變數名稱，或任何不在白名單裡的 `VITE_` 名稱，就讓 job 失敗；附反向測試證明故意放入名稱時會失敗。

## 定義（本節凍結）

### 後端名稱（ARCH §3.2 第 8 點、§7.1；恰好 8 個，大小寫須完全相同）
`GEMINI_API_KEY`、`GEMINI_PAID_API_KEY`、`GROQ_API_KEY`、`AZURE_SPEECH_KEY`、`SUPABASE_SECRET_KEYS`、`SUPABASE_SECRET_KEY`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_DB_URL`
- 比對方式：子字串。前後接什麼字元都算命中（例如 `XGROQ_API_KEY_2` 也命中 `GROQ_API_KEY`）。
- 同一段文字同時命中 `SUPABASE_SECRET_KEYS` 與 `SUPABASE_SECRET_KEY` 時，兩個都列。

### `VITE_` 白名單（恰好 3 個）
`VITE_DATA_MODE`、`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`
- 取出方式：每一段「`VITE_` 加上其後連續的英數字與底線（大小寫都算）」視為一個名稱，取到最長；前面接什麼字元不影響。
- 取出的名稱**恰好等於**白名單之一才放行；其他一律命中，包括只有 `VITE_`、`VITE_DATA_MODE_X`、`VITE_DATA_MODEx`、`VITE_SUPABASE_ANON_KEY`。
- 白名單比對區分大小寫（`vite_data_mode` 不會被取出；`VITE_data_mode` 會被取出且不在白名單 → 命中）。

### 掃描範圍
- 指定資料夾底下遞迴的**每一個一般檔案**，含點開頭的檔、`.map`、`.html`、`.webmanifest`、`sw.js`、圖片等，不依副檔名略過。
- 檔案內容以位元組讀入、用 latin1 解碼後比對（二進位檔不會讓工具拋錯；上述名稱都是 ASCII）。
- 符號連結（檔或資料夾）一律算輸入錯誤，不跟隨。

### 輸出
- 每個命中印一行：相對於掃描資料夾的路徑、名稱、種類（`backend`／`vite`）。**不得**印出命中處前後的內容、整行文字或任何變數值。
- 依路徑再依名稱排序，同檔同名只印一次。

## 介面

### `tooling/bundle-name-scan.mjs`（Claude 新增；只用 Node 內建模組）
```text
export const BACKEND_NAMES          // 凍結陣列，恰好上表 8 個
export const ALLOWED_VITE_NAMES     // 凍結陣列，恰好上表 3 個
export function scanText(text)      // → [{ name, kind: 'backend' | 'vite' }]，去重、依 name 排序
export function scanDir(dir)        // → { ok: true, files } | { ok: false, findings: [{ file, name, kind }] }
                                    //   輸入錯誤 → { error: 'INPUT', reason }
CLI：node tooling/bundle-name-scan.mjs <dir>
  exit 0：沒有命中（stdout 印掃過的檔數）
  exit 1：有命中（每個命中一行，見「輸出」）
  exit 2：INPUT（沒給參數或多給、路徑不存在、不是資料夾、0 個檔、遇到符號連結、讀檔失敗）
```
- `scanText` 收到非字串 → 拋錯或回 INPUT，不得回空陣列。
- `scanDir` 的 `files` 是實際讀過的檔數，必須 ≥ 1；0 個檔是 INPUT，不是通過。

## 驗收標準
- AC-O29-1：`BACKEND_NAMES` 恰好等於上表 8 個、`ALLOWED_VITE_NAMES` 恰好等於上表 3 個（集合相等且長度相同）。
- AC-O29-2：任一後端名稱以子字串出現 → 命中且種類為 `backend`；前後接其他字元也命中。
- AC-O29-3：白名單 3 個名稱單獨出現 → 不命中；任何其他 `VITE_` 名稱（含前綴相同、多一段、大小寫不同、只有 `VITE_`）→ 命中且種類為 `vite`。
- AC-O29-4：`scanDir` 遞迴掃每一個一般檔案，不依副檔名或點開頭略過；名稱只放在深層子資料夾、`.map`、`.html`、點開頭的檔、含非 UTF-8 位元組的檔裡，都要命中。
- AC-O29-5：CLI exit code：乾淨 0；有命中 1；INPUT 2（沒參數、不存在、不是資料夾、空資料夾、符號連結）。以 `child_process.spawnSync(process.execPath, …)` 實際斷言。
- AC-O29-6：輸出不洩漏內容：命中行只有路徑、名稱、種類；測試在名稱旁放一段假值（例如 `=fake-value-o029`），斷言 stdout、stderr 都不含該假值。
- AC-O29-7：突變必須被抓到：拿掉任一後端名稱；白名單改成前綴比對（`startsWith`）；白名單不分大小寫；略過 `.map` 或 `.html`；不遞迴；空資料夾回 0；跟隨符號連結；有命中仍 exit 0；印出命中所在行。上述削弱若仍能通過測試，本 AC 失敗。
- AC-O29-8：本單新增或修改的檔案沒有未允許的 `|| true`、`continue-on-error`。
- AC-O29-9（SRE 接線）：`ci.yml` 的 `bundle` job 在 `Build` 之後有一步恰好執行 `node tooling/bundle-name-scan.mjs apps/web/dist`，沒有 `continue-on-error`、沒有 `|| true`；`ci-workflow-check` 凍結這一步，拿掉、移到 `Build` 之前、或加上 `continue-on-error` 都要失敗。
