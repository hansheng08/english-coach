## 背景（開始前先讀）
- run 45323782247：Step 7「Run Claude Code」success 並已推 `task/T-003`，push CI 45324530991 success；Step 10「Verify push triggered CI」在 `git fetch` 得到 `remote: Invalid username or token`（exit 128），Notify 送出 `outcome=failure`，routine 當成產品連續失敗。
- checkout 設 `persist-credentials: false`（RUNBOOK §1.1，必須保留）；`claude-code-action` 把 App token 放進 remote URL，並在 Step 7 結束前撤銷。
- 開始前讀 `verify-push.sh`、`run-task-outcome.sh` 及其測試、`claude-run-task.yml`、`notify-grok.yml`、`ci.yml`、`fail-open-lint.mjs`、`claude-permission-check.mjs`、PR 範本與 RUNBOOK。

## 目標（一句話）
讓「分支已推、push CI 已觸發」的 run-task 不再被 Verify 標成假紅燈，同時讓通知能分辨 Claude／產品失敗與 Verify 失敗，且全程維持預設失敗。

## 範圍：要做
1. `.github/scripts/verify-push.sh`：拿掉 `git fetch`；用 `GH_TOKEN` 跑 `gh api repos/$GITHUB_REPOSITORY/git/ref/heads/$BRANCH` 取 SHA（嚴格解析單一物件、`.ref` 相符、40 位小寫 hex），再用 `gh run list` 輪詢同 SHA 的 `push` run；輸入缺漏、404、401／403、其他錯誤、JSON 不對、找不到 run 一律 exit 1；寫 `verify_reason` 到 `GITHUB_OUTPUT`。
2. `.github/workflows/claude-run-task.yml`：Verify 步驟明確帶 `GH_TOKEN: ${{ github.token }}`、`GITHUB_REPOSITORY: ${{ github.repository }}`；Notify 改用 `run-task-outcome.sh --json` 並在 payload 加 `claude_outcome`／`verify_outcome`／`summary_outcome`／`verify_reason`；評估並（若低風險）把 `anthropics/claude-code-action@v1` 釘到完整 commit SHA。不放寬 `permissions:`。
3. `.github/scripts/run-task-outcome.sh`：新增 `verify_failed`、`summary_failed`，以及 `--json` 模式；只有三個 `success` 才得 `success`。
4. 測試：`verify-push-test.sh`、`run-task-outcome-test.sh`、`claude-permission-check.mjs`／`.test.mjs`（checkout `persist-credentials: false`、verify-push 無 `git fetch`、Verify 帶 `GH_TOKEN`、action 釘 SHA）。
5. `docs/RUNBOOK.md`（§1.2、新 §1.5、§3.1、§3.3）、`docs/tasks/O-007.md`、`docs/reports/O-007.md`。

## 範圍外：不要做

## 實作限制
- 驗證腳本預設失敗（憲章 v5 §5）；不得新增未附理由的 `|| true`、`|| :`、`|| exit 0`、`continue-on-error`。
- 測試零網路、不 sleep（`VERIFY_PUSH_SLEEP=0`）。
- 報告數字必須從 job log 或本機指令輸出複製。同一原因 CI 連續紅燈 2 次就停下回報。

3. box 上用 box 的 `gh` 權杖實跑 `verify-push.sh` 一個存在的分支與一個不存在的分支。
4. 開 PR 後看 `pull_request` 的 `ci` run（`gh run view --json`／`--log`；不要依賴 `gh pr checks`）。
