## 背景
- O-025 已合併（PR #73，main `ff8b0a5`）。現行 `ci.yml` 的 e2e 步驟是 `pnpm e2e -- --reporter=list --reporter=json`，並以 `PLAYWRIGHT_JSON_OUTPUT_NAME=playwright-results.json` 釘死輸出。缺檔時 artifact 上傳是 `if-no-files-found: error`，`taskcheck` 在 e2e 有跑時必傳 `--playwright`，缺檔則 `die`。
- TechLead 回報：這個 `--` 會讓 Playwright 忽略 reporter 參數，因而沒有 JSON，PR 的 e2e 上傳與 taskcheck 都會紅，擋住 T-018 的 G3（以及之後有畫面的前端單）。**不要**在 `playwright.config.ts` 加 json reporter 來繞過（該檔屬 T-018）。
- SRE 在 box 用與 T-018 相同的 script（`"e2e": "playwright test"`）重現（origin/main 尚無 e2e script／設定，故用最小等價：一支不開瀏覽器、不啓 Supabase、不拉 `public.ecr.aws` 的 trivial spec）。`pnpm` 12.21.0（`packageManager`）會把 `--` 原樣傳給 script，實際執行是 `playwright test -- --reporter=list --reporter=json`。Playwright CLI 是 `test [options] [test-filter...]`，`--` 之後的參數當檔案路徑正規表示式，不當選項；此次原文為 `Error: No tests found. Make sure that arguments are regular expressions matching test files.`，且沒有 `playwright-results.json`。拿掉 `--` 後變成 `playwright test --reporter=list --reporter=json`，JSON 寫出且可解析（有 `suites` 陣列）。`pnpm` 自己的 `--reporter` 只作用在 script 名稱**之前**；放在 `e2e` 之後會轉給 script。
- O-025 契約：e2e 被略過時不傳 `--playwright`。push 的 `e2e` 本來就略過（`is_pr`），因此只在 Playwright 裡出現的 AC／TC 在 push `taskcheck` 會是 `CV-MISSING`。本單要把這類 AC 改成「只在 PR CI 判定」，並讓結果在 push log 裡可見，而不是默默略過。

## 目標
修好 e2e 的 JSON reporter 接線（拿掉多餘的 `--`，不改 `playwright.config.ts`），並讓 push 上「只由 E2E 覆蓋」的 AC／TC 以明確代碼延到 PR 判定；PR 維持 fail-closed。

## 介面

### e2e CLI（SRE 改 `ci.yml`；本節凍結）
步驟必須是 `pnpm e2e --reporter=list --reporter=json`（`e2e` 與 `--reporter` 之間**沒有** `--`），並維持 `PLAYWRIGHT_JSON_OUTPUT_NAME=playwright-results.json`。不要改 `playwright.config.ts`。不要新增 job、不要改 `ci-budget.json`、不要調高逾時。

### 僅 E2E 的 AC／TC（Claude 改 `tooling/ac-coverage.mjs`）
任務單裡的一個 AC 或 TC 編號（與現有 ac-coverage 相同的 `(AC-…)`／`(TC-…)` 標籤）在同時成立時算「僅 E2E」：

1. 它沒有出現在此次 Vitest JSON 或 TAP 的任何測試名稱裡（不論 `passed`／`failed`／`skipped`／其他狀態）。
2. 它有出現在 e2e 規格檔原始碼裡的同一個標籤。預設掃描目錄是 `test/e2e/`（可用 `--e2e-dir` 覆寫，測試用），檔名符合 `**/*.{spec,test}.{ts,js,mjs,cjs}`。只認標籤本身，不當通過。

沒有出現在 Vitest／TAP、也沒有出現在 e2e 規格檔的編號，仍是 `CV-MISSING`，不得當成僅 E2E。出現在 Vitest／TAP 名稱裡但沒通過的，仍依 O-025 規則（`CV-FAILED` 或 `CV-MISSING`），不得延後。

### CLI
在既有 `--branch`／`--results`／`--tap`／`--playwright`／`--tasks-dir` 之外：

- `--event <name>`：事件名稱（例如 `push`、`pull_request`）。
- `--e2e-skipped`：宣告此次沒有跑 e2e。
- `--e2e-dir <dir>`：僅 E2E 掃描目錄，可重複；預設 `test/e2e`。

規則（fail-closed）：

- 有傳 `--e2e-skipped` 但沒有 `--event`，或 `--event` 不是 `push`（含 `pull_request`）：一律 `INPUT`／非 0。不得忽略該旗標而當成功。
- `--event push` 且 `--e2e-skipped`：僅 E2E 且沒有通過測試的編號改報 `CV-DEFERRED-PR`（必須印出，讓 log 看得見）。若這次沒有 `CV-MISSING`／`CV-FAILED`／`INPUT`，即使有 `CV-DEFERRED-PR`，CLI 為 0。不是僅 E2E 的缺漏仍是 `CV-MISSING`，CLI 非 0。
- 有傳 `--playwright` 時維持 O-025：缺檔、空檔、無效 JSON、缺欄位 → `INPUT`／非 0，不得因 `--e2e-skipped` 或事件而放行。e2e 有跑時接線不得傳 `--e2e-skipped`。
- 沒有傳 `--e2e-skipped` 時，行為與 O-025 相同（僅 E2E 的缺漏仍是 `CV-MISSING`）。

考慮過但不採用：push 完全不跑 ac-coverage（會丢掉 Vitest／TAP 的早期訊號）；或把僅 E2E 的編號從結果裡默默拿掉（log 看不見）。`CV-DEFERRED-PR` 較可見，PR 仍 fail-closed。

## 驗收標準
- AC-O27-1：e2e 步驟以 `pnpm e2e --reporter=list --reporter=json` 執行（中間沒有 `--`），在 `PLAYWRIGHT_JSON_OUTPUT_NAME` 指出的路徑產出可解析的 JSON；不得改 `playwright.config.ts` 來繞過。
- AC-O27-2：`--event push --e2e-skipped` 時，僅 E2E 且沒有通過測試的 AC／TC 報 `CV-DEFERRED-PR` 而非 `CV-MISSING`；若沒有其他失敗，CLI 為 0。
- AC-O27-3：在 `pull_request`（或任何非 `push` 的 `--event`）上傳 `--e2e-skipped`，必須 `INPUT`／非 0，不得當成功。
- AC-O27-4：有傳 `--playwright` 但檔案缺漏或無效時，仍是 `INPUT`／非 0（與 O-025 相同），包括同時傳了 `--e2e-skipped` 的情況。
- AC-O27-5：`--event push --e2e-skipped` 時，不是僅 E2E 的 AC／TC 若沒有通過測試，仍是 `CV-MISSING`（或相關測試失敗時 `CV-FAILED`），CLI 非 0。
- AC-O27-6：突變必須被抓到：把非 E2E 的缺漏當成 `CV-DEFERRED-PR`、在 PR 事件接受 `--e2e-skipped`、缺 Playwright JSON 當成成功。上述削弱若仍能通過測試，本 AC 失敗。
- AC-O27-7：本單新增或修改的檔案沒有未允許的 `|| true`、`continue-on-error`。
