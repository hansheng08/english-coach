## 背景
- 開始前先讀：`CLAUDE.md`；ARCHITECTURE v1.12 §4.12.4；ADR-018 決定 2；`.github/scripts/db-job-verify.sh` 的工作目錄選擇；`.github/workflows/ci.yml` 的 `has_supabase` 偵測；`docs/RUNBOOK.md` §2、§2.3、§2.4；`tooling/supabase-config.test.ts`。
- 事實（#100 合併後的 origin/main）：根目錄已有 `supabase/config.toml` 時，`db-job-verify.sh` 直接用根目錄，不會用 `.github/ci/supabase-probe/`。探針只剩「沒有產品設定」的備援。`has_supabase` 仍用第二個路徑把探針算進去。`tooling/supabase-config.test.ts` 仍有一個測試 import 並逐行比對探針（§4.12.4 把改測試交給 T-046 或先派工的那張；撰寫本單時該變更尚未進 main）。
- 決定：開本 O 單刪掉探針目錄、備援分支、以及 `ci.yml` 偵測裡的探針路徑，讓 CI 只認產品設定。本單不擋 T-046、T-025a。
- 埠 54322：產品與探針的設定都使用同一預設資料庫埠。現況備援不會走到，`db` job 一直用根目錄設定。拿掉備援不改變現況路徑，因此不影響 runner 上曾出現的 54322 埠衝突（O-025、PR #86）；該問題另案處理。

## 目標
刪除已不再被 CI 使用的 supabase probe，讓偵測與 `db` job 只認 repo 根目錄的產品設定；測試必須在探針被還原或備援被加回時失敗。

## 介面
本單不新增套件、CLI 或匯出函式。行為變更如下。
- `has_supabase` 只在根目錄存在 `supabase/config.toml` 時為 true。
- `db-job-verify.sh` 只以根目錄為工作目錄。根目錄沒有該檔時，在啟動 Supabase 之前以非 0 結束，且不得讀取或複製探針目錄。
- `tooling/supabase-config.test.ts` 不得再 import 探針。若實作時仍有「與探針逐行比對」的測試，Claude 依 §4.12.4 改成產品設定本身的檢查：每個 `[functions.<slug>]` 區塊都有 `verify_jwt = false` 與 `import_map = "./functions/deno.json"`，且 slug 等於 `supabase/functions/` 底下一個資料夾名稱；測試名稱保留原產品驗收標記，並註明 v1.12 不再比對 probe（ARCHITECTURE §4.12.4）。若該測試已被 T-046 或先派工的單改完，不得改其斷言，只確認沒有探針路徑。其餘既有產品設定測試維持不變。
- Claude 的測試必須在探針目錄尚未刪除時就能通過，不得斷言該目錄已經不存在（刪目錄是 SRE 接線）。

## 驗收標準
- AC-O30-1：`.github/ci/supabase-probe/` 整棵目錄不存在（含其中的 `config.toml`、`functions/api/index.ts`、`functions/deno.json`）。
- AC-O30-2：`ci.yml` 的 `has_supabase` 只檢查根目錄 `supabase/config.toml`；條件中不得再出現探針路徑，也不得再備援第二個設定檔。
- AC-O30-3：根目錄有產品設定時，`db-job-verify.sh` 仍以 repo 根目錄為工作目錄。根目錄沒有該檔時，腳本在啟動 Supabase 之前以非 0 結束，且不會讀取或複製探針路徑。
- AC-O30-4：`tooling/` 與 `.github/` 不再引用探針路徑（`docs/tasks/**`、`docs/reports/**` 的歷史紀錄除外）。`tooling/supabase-config.test.ts` 不再 import 探針；若實作時比對測試仍在，須已改成 §4.12.4 的產品設定本身檢查；其餘既有產品設定測試仍通過。
- AC-O30-5：靜態檢查（接在既有 `ci-workflow-check` 或同等檢查）在 `has_supabase` 偵測或 `db-job-verify.sh` 再出現探針路徑、或恢復「無產品設定就複製探針」時必須失敗。
- AC-O30-6：`docs/RUNBOOK.md` §2、§2.3、§2.4 的現行操作說明改為只認產品設定。歷史實測敘述可保留，但現行偵測條件不得再寫「探針會讓 `has_supabase` 為 true」。
- AC-O30-7：突變必須被抓到：還原探針目錄或重新 import；`has_supabase` 加回探針路徑；無產品設定時改走複製探針；拿掉靜態檢查仍能通過。上述削弱若仍能通過測試，本 AC 失敗。
- AC-O30-8：本單新增或修改的檔案沒有未允許的 `|| true`、`continue-on-error`。

## 限制
- 只用既有工具與 Node 內建模組；不新增套件、不連網。
- Claude 不得修改 `.github/workflows/**`、`.github/scripts/**`，也不得刪除探針目錄。
- 備援與偵測的負面測試必須在無 Docker、不啟動 Supabase 的情況下可跑。
- 不改分支保護或必過檢查清單。
- 讀檔、搜尋一律用內建 Read／Grep／Glob 工具；不要用 Bash 的 `cat`、`grep`、`head`、`ls`、`sed`。
- 每一個 git 指令都是一次獨立的 Bash 呼叫，依序為：`git fetch origin`、`git switch -c task/O-030 origin/main`、`git add <明確檔案路徑…>`、`git commit -m "[Claude] O-030 …"`、`git push -u origin task/O-030`；每一次都不得含 `&&`、`;`、`|`、`2>&1` 或其他指令。

## 驗證方式
`pnpm check` 跑到通過；任務單不另列指令。

## 結束時
1. 在指定的分支上 commit 並 push，不得動 main。
2. 把結果寫到 `docs/reports/O-030.md`：完成摘要、變更檔案、測試結果、未完成事項、需要人類決定的問題。
3. 測試結果、權限被拒以 workflow 自動產生的摘要與 PR 觸發的 CI run 為準，報告不重貼。
