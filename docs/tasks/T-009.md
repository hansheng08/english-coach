## 目標
依 ARCHITECTURE §4.3 新增 contracts 的字卡 schema（`card.ts`）與 domain 的字卡狀態機（`applyReview`／`markMastered`），轉換表每一列都有測試（PRD AC-09、AC-19、AC-20）。

## 介面
`packages/contracts/src/card.ts`：名稱與定義照 ARCHITECTURE §4.3 的 contracts 程式碼區塊（`CARD_STATES`／`CardStateSchema`／`CardState`、`REVIEW_RATINGS`／`ReviewRatingSchema`／`ReviewRating`、`REVIEW_MODES`／`ReviewModeSchema`／`ReviewMode`、`CARD_SOURCE_TYPES`／`CardSourceTypeSchema`／`CardSourceType`、`IntervalStepSchema`／`IntervalStep`、`CardScheduleSchema`／`CardSchedule`、`ReviewRequestSchema`／`ReviewRequest`），不另加欄位或型別；從 `packages/contracts/src/index.ts` 匯出。

`packages/domain/src/card-state.ts`（§4.3 已固定，從 `packages/domain/src/index.ts` 匯出）：
```ts
export type ReviewOutcome = { readonly before: CardState; readonly schedule: CardSchedule; readonly intervalDaysApplied: number };
export function applyReview(card: CardSchedule, rating: ReviewRating, today: PlanDate, srs: SrsSettings): Result<ReviewOutcome, ValidationError>;
export function markMastered(card: CardSchedule): { readonly schedule: CardSchedule; readonly changed: boolean };
```
行為一律照 §4.3 轉換表與其下的說明，本單不重述。v1.1 已寫明、本版沿用的實作細節：
- 到期日＝`addDays(today, d)`；`addDays` 回 `err` 時 `applyReview` 原樣回傳該 `err`。
- mastered 的 `err` 是 `kind: 'validation'`，`issues` 含 `path` 為 `state` 的一筆。
- domain 的 `SrsStep` 與 contracts 的 Reviewing 階段（1～4）是同一組值；需要轉換時用 `switch` 或型別縮小，不用 `as`。

## 驗收標準
- **AC-T9-1**（§4.3）`CardScheduleSchema`：4 種狀態的合法例子都通過；擋下 4 種不合法組合（collected 的 `correctCount` 不是 0、learning 的 `intervalStep` 不是 0、reviewing 的 `dueDate` 是 `null`、mastered 有 `dueDate`）；`ReviewRequestSchema` 擋下未知 `rating` 與未知 `mode`；`IntervalStepSchema` 擋下 `5`。
- **AC-T9-2**（AC-19、Q-17；§4.3 轉換表）`applyReview` 照轉換表每一列（fast 與 hesitant 合寫的列兩種評分各自成立），回傳的 `state`、`correctCount`、`intervalStep`、`dueDate`、`intervalDaysApplied`、`before` 都正確；`correctCount` 只增不減；Reviewing 忘記後回 Learning，之後再答對回到 Reviewing **第 1 階**；mastered → `err`（`path: 'state'`）。
- **AC-T9-3**（AC-09、Q-18）設定與日期：天數與到期日跟著傳入的 `srs` 走（同一張卡用兩份設定各算一次結果不同）；`addDays` 失敗時 `applyReview` 回 `err`，不丟例外。
- **AC-T9-4**（AC-20、ADR-011 決定 2、Q-24）`markMastered`：只有 reviewing → mastered（`intervalStep` 保留、`dueDate: null`、`correctCount` 不變、`changed: true`）；collected／learning／mastered 原樣回傳、`changed: false`；所有結果都通過 `CardScheduleSchema`。
- **AC-T9-5**（§4.3、CLAUDE.md §4）匯出：`@english-coach/contracts` 匯出 `card.ts` 的全部名稱，`@english-coach/domain` 匯出 `applyReview`、`markMastered` 與型別 `ReviewOutcome`；`applyReview` 的回傳結果都通過 `CardScheduleSchema`。
