## 背景（開始前先讀）
- T-003 驗收：`supabase start`；`supabase functions serve` 後 curl health（無 JWT 401、有使用者 JWT 200）；ADR-009 (1)(2)。模式 C 的 run-task 不能跑 Supabase CLI／curl（§5 第 27 點 (a)）。Hansheng 核准把這些檢查放進 `db` job。
- ADR-010：health 路徑為 `GET /functions/v1/api/health`；`verify_jwt = false`；用本機 Auth 建測試使用者取 token（**不是** `ANON_KEY`，因為 `requireUser` 要求 `role === 'authenticated'`）；並確認函式環境有 `SUPABASE_URL` 與 publishable／secret 金鑰（只檢查有無，不印值）。若只注入舊名稱，停下回報 Architect。
- CLI 3.2.0：`functions deploy` 為 Remote only，沒有 `--dry-run`。CI 不得對遠端部署。
- main 當時沒有 `supabase/config.toml`，原 `has_supabase` 會讓 `db` 被略過。
- `claude-run-task.yml`：通知幕僚長的 `outcome` 只用 `steps.claude.outcome`，verify-push 失敗仍回 success；`permissions` 的 write 範圍過寬。
