- **資料模式**（§9.1.1、O-023）：`apps/web/vite.data-mode.ts` 匯出 `dataModeOrThrow(env)`，回傳 `'mock' | 'supabase'`，不合法就丟 `Error`（訊息只寫鍵名與原因，不寫值）。規則與 O-023 的 `assertDataModeEnv` 相同，優先直接 import 它；型別接不上時可同等實作，報告寫明。`vite.config.ts` 用 Vite 讀到的全部 `VITE_` 變數（`.env*` 與程序環境）呼叫它。
- **`api/`**：`api/index.ts` 依 `import.meta.env.VITE_DATA_MODE` 動態 import `api/supabase/` 或 `api/mock/`；`@supabase/*` 只在 `api/supabase/`。supabase 版用 `signInWithPassword`，全程不呼叫任何註冊 API。錯誤對應：帳密錯 → `{ kind: 'unauthenticated' }`，其他 → `{ kind: 'internal' }`。
- **mock**（§9.1.1；TechLead 決定）：`getSession` 一律回固定示範身分（UUID 通過 `UserIdSchema`）；`signInWithPassword` 在 `error` 情境回 `unauthenticated`，其他情境成功；資料在記憶體，不發網路請求；假資料放 `api/mock/fixtures/`，自己寫、不放真新聞原文。`?scenario=` 用 `parseScenario`：沒有參數 → `default`；名稱不在 `MOCK_SCENARIOS` → 用 `default`，`unknown` 帶原字串，並在「預覽：假資料」旁邊顯示「未知情境「<名稱>」，改用 default」（純文字），不丟例外、不白畫面。本單只定義 `default`、`error` 的行為，其他已知名稱暫同 `default`。
- **登入閘門**（§7、AC-23 基礎）：supabase 模式 `getSession` 回 `null` → 導到 `/login`；登入成功 → `/`。mock 模式閘門直接放行，`/login` 仍可直接開（截圖與 E2E 用）。
- **首頁**：本單的 `/` 只有頁面外殼：右上頭像（主題切換入口，home.md「頂部」）與 mock 時的「預覽：假資料」。今日任務內容是 T-026，不在本單。
- **登入頁**（login.md、DESIGN §7 表單）：Email、密碼兩欄（標籤在上、輸入框 52px）、墨色「登入」按鈕；帳密錯時密碼框紅框＋圖示＋「Email 或密碼不對，再試一次。」（密碼欄 `aria-invalid="true"`，訊息以 `aria-describedby` 連到欄位）；下方「連線加密。履歷與錄音只供你自己練習。」。電腦版（≥900px）左右分割：左＝深藍焦點卡「每天 80 分鐘，把英文講得像 Senior。」＋今天的份量（1 篇科技新聞、5 句跟讀、25 張字卡、1 題面試題）；右＝同一張表單，最大寬 400px。不放註冊、社群登入、忘記密碼。畫面只做 login.md 列出的狀態。
- **主題切換**（theme.md、DESIGN §9）：頭像按鈕開「帳號與外觀」：<900px 底部 sheet、≥900px 右上 popover。第一個控制項是三段 `.seg`（radio），順序 淺色／深色／跟隨系統，預設跟隨系統。說明文字：跟隨系統時「跟隨系統，現在是淺色。只存在這台裝置。」或「跟隨系統，現在是深色。只存在這台裝置。」；手動時「現在是淺色。只存在這台裝置。」或「現在是深色。只存在這台裝置。」。切換立即套用、顏色無轉場；跟隨系統時作業系統改變，畫面與說明文字不重新載入就跟著變（AC-27）。
- **主題機制**（§9.1.4）：`index.html` 的 `<head>` 順序照 §9.1.4（本單放第 1～3、6、7 項；第 4、5 項 `theme-color` 由 T-019 加）。inline script 只在 `ec-theme` 是 `light`／`dark` 時設 `data-theme`。`theme.ts`：沒有值、不合法或 `getItem` 丟例外都回 `system`；`setThemePreference` 寫入 `ec-theme`（`system` 也寫入），`light`／`dark` 設 `<html data-theme>`，`system` 移除；`setItem` 丟例外時不往外丟、`data-theme` 照樣更新。`<html lang="zh-Hant-TW">`。
- **tokens 產生器**（§9.1.5、DESIGN §11）：只用 Node 內建模組；路徑相對於工作目錄；解析規則照 §9.1.5 的 1～7；另加（幕僚長決定）：物件含 `light` 或 `dark` 鍵、但不是剛好 `{light, dark}` 兩個字串值（例如只有 `light`）→ 失敗。檔頭「自動產生，不要手改」；三段輸出與 `color-scheme` 照 §9.1.4；值原樣輸出。失敗時 stdout 空、stderr 寫原因、exit 1。`apps/web/src/ui/tokens.css` 用合併後的 `tokens.json` 產生並 commit；`main.tsx` 第一個 import 它。
- **CSS 字面值檢查**（§9.1.5 使用規則；CI 接線是 SRE 的事）：`tooling/css-literals.mjs` 去掉註解後，在宣告值裡找 `#` 加 3、4、6、8 位十六進位色碼、`rgb(`、`rgba(`、`hsl(`；`tokens.css` 不掃；`0`、`1px`、`%`、`fr` 不算違規。違規印 `檔案:行` 到 stderr、exit 1；找不到 `apps/web/src` → exit 1。
- **依賴與設定**（ADR-001 修訂 1）：`apps/web` 的 dependencies 加 `react`、`react-dom`、`react-router`、`@supabase/supabase-js`、`@english-coach/contracts`、`@english-coach/domain`（後兩個 `workspace:*`，不用 alias）；devDependencies 加 `vite`、`@vitejs/plugin-react`、`@types/react`、`@types/react-dom`（`^19`）、`jsdom`、`@testing-library/react`（`^16`）、`@testing-library/dom`（`^10`）；根目錄加 `@playwright/test`。根 `engines.node` 改成 `^22.22.2 || ^24.15.0 || >=26.0.0`。`apps/**` 的測試跑 jsdom（`vitest.config.ts` 的 `projects` 或檔頭 `// @vitest-environment jsdom`，擇一寫進報告），其他維持 `node`。`apps/web/test/setup.ts` 放 `afterEach(cleanup)` 與可控制結果的 `matchMedia` stub。`.dependency-cruiser.cjs` 加規則：`apps/web/src/**` 的非測試檔不得 import `jsdom`、`@testing-library/*`（測試檔用 ADR-008 修訂 2 決定 3 的 regex `(^|/)test/|\.test\.tsx?$|\.test-d\.ts$`）。根 `package.json` 加 `build`、`e2e` 指令；`apps/web/.env.example` 列 `VITE_DATA_MODE`、`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`（值留空）。

## 驗收標準

## 限制
- 依賴只用「介面」列的套件；`vite-plugin-pwa` 留給 T-019；不加動畫、UI 元件、圖示、字型套件，字型只用 tokens 的系統字型（CLAUDE.md 第 19 條）；清單外的依賴停下寫報告。
