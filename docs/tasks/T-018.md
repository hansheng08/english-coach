## 目標
建立 `apps/web`（Vite＋React＋react-router），讓前端可以用 `VITE_DATA_MODE` 在記憶體假資料與 Supabase 之間切換，主題偏好在第一次繪製前套用，並提供把 `tokens.json` 轉成 CSS 變數、可在 CI 檢查一致的產生器。

## 介面
```ts
// apps/web/src/build-env.ts（vite.config.ts 呼叫；不 import 其他 apps/web 檔案）
export type DataMode = 'mock' | 'supabase';
export function validateBuildEnv(env: Readonly<Record<string, string | undefined>>):
  { readonly ok: true; readonly mode: DataMode } | { readonly ok: false; readonly reason: string };
// apps/web/src/api/mock/index.ts
export const MOCK_MARKER = '__EC_MOCK__';
// apps/web/src/ui/theme.ts
export type ThemePreference = 'system' | 'light' | 'dark';
export const THEME_STORAGE_KEY = 'ec-theme';
export function readThemePreference(storage?: Pick<Storage, 'getItem'>): ThemePreference;
export function setThemePreference(pref: ThemePreference, storage?: Pick<Storage, 'setItem'>, root?: HTMLElement): void;
```
```text
node tooling/tokens-css.mjs           讀 docs/design/tokens.json，寫 apps/web/src/ui/tokens.css
node tooling/tokens-css.mjs --check   只比對；不同、檔案不存在或解析失敗 → exit 1
```
- **資料模式**（§9.1.1）：`VITE_DATA_MODE` 只能是 `mock` 或 `supabase`，沒有預設值。`supabase` 要有非空的 `VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`；`mock` 時這兩個只要有定義（含空字串）就失敗。`vite.config.ts` 拿到 `ok: false` 就讓建置失敗並印出 `reason`。
- **`api/`**：`client.ts` 定義 `ApiClient`（回傳 `Result`）；`api/supabase/`、`api/mock/` 各一份；`api/index.ts` 依 `import.meta.env.VITE_DATA_MODE` 動態 import 其中一邊。`@supabase/*` 只在 `api/supabase/` 裡 import。
- **`mock` 模式**：登入閘門直接放行（固定示範身分）；資料在記憶體，重新整理回到初始狀態；不發出任何網路請求；假資料放 `api/mock/fixtures/`，自己寫、不放真新聞原文，每份都通過 contracts 對應的 schema。
- **主題**（§9.1.4）：`index.html` 的 `<head>` 順序照 §9.1.4（本單放第 1～3、6、7 項；第 4、5 項的 `theme-color` 由 T-019 加）。inline script 的行為照 §9.1.4：只在 `ec-theme` 是 `light`／`dark` 時設 `data-theme`，讀不到或其他值都不設。`theme.ts`：讀值時沒有、不合法或 `getItem` 丟例外都回 `system`；`setThemePreference` 寫入 `ec-theme`（`system` 也寫入），`light`／`dark` 設 `<html data-theme>`，`system` 移除；`setItem` 丟例外時不往外丟，`data-theme` 照樣更新；`storage`、`root` 預設用瀏覽器的全域物件，測試注入假的。`<html lang="zh-Hant-TW">`（§9.1.2）。
- **tokens 產生器**（§9.1.5）：只用 Node 內建模組；路徑相對於執行時的工作目錄。解析規則照 §9.1.5「解析規則」1～7；輸出檔頭寫「自動產生，不要手改」；三段輸出與 `color-scheme` 照 §9.1.4 的 CSS 規則；值原樣輸出；名稱 `--<群組>-<名稱>` 只能是小寫英數和 `-`。失敗時 stdout 空、stderr 寫原因、exit 1。
- **其他**：根 `package.json` 加 `build`、`e2e` 指令；`apps/web/.env.example` 列 `VITE_DATA_MODE`、`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`（值留空；`VITE_DATA_MODE` 依 ADR-014 加入，TASKS 列的「只有兩個」是 ADR-014 之前的寫法）；`apps/web/package.json` 以 `workspace:*` 依賴 `@english-coach/contracts`、`@english-coach/domain`，不用 alias（ADR-009 決定 1）。
- **TechLead 決定**：mock 標記字串用 `__EC_MOCK__`（§9.1.1 的例子）；`theme.ts` 用注入參數讓 Vitest 在 Node 環境測，不加 DOM 測試環境；`mock` 模式下 `VITE_SUPABASE_*` 有定義就算違規（fail-closed）。

## 驗收標準
- **AC-T18-1**（ADR-014 決定 1）`validateBuildEnv`：`VITE_DATA_MODE` 沒設或不是 `mock`／`supabase` → `ok: false`；`supabase` 缺網址或金鑰 → `ok: false`；`mock` 帶任一 `VITE_SUPABASE_*` → `ok: false`；合法組合 → `ok: true` 與對應 `mode`。
- **AC-T18-2**（§7）`apps/web` 原始碼、`vite.config.ts`、`.env.example` 用到的 `VITE_` 名稱都不含 `KEY`、`SECRET`、`TOKEN`，唯一例外是 `VITE_SUPABASE_PUBLISHABLE_KEY`。
- **AC-T18-3**（ADR-008 第 4 條、§9.1.1）`@supabase/*` 只出現在 `apps/web/src/api/supabase/`；`MOCK_MARKER` 只由 `api/mock/index.ts` 匯出。
- **AC-T18-4**（§9.1.1）每一份 `api/mock/fixtures/` 的假資料都通過 contracts 對應的 schema。
- **AC-T18-5**（ADR-014 決定 1）`mock` 模式的頁面：沒有登入也直接進首頁、顯示「預覽：假資料」、除了提供頁面的本機伺服器之外沒有任何網路請求。
- **AC-T18-6**（ADR-014 決定 4、AC-27、AC-28）`theme.ts` 的讀寫與 `data-theme` 照「介面」；key 字串和 `index.html` inline script 裡的一致。
- **AC-T18-7**（ADR-014 決定 4）`index.html` 的 `<head>` 順序照 §9.1.4（本單的項目），inline script 在任何樣式表之前；`<html lang="zh-Hant-TW">`。
- **AC-T18-8**（ADR-014 決定 4）瀏覽器中 inline script：`ec-theme` 為 `light`／`dark` 時第一次繪製前就有對應的 `data-theme`；`system`、其他值、沒有值、`localStorage` 丟例外時都沒有 `data-theme`，頁面照常顯示。
- **AC-T18-9**（ADR-014 決定 5、§9.1.5）產生器照解析規則輸出：`$` 鍵略過、6 個群組以外失敗、子類別攤平、`{light, dark}` 分段、鍵順序保留、名稱不合法或重複失敗、值型別不對失敗。
- **AC-T18-10**（§9.1.4、§9.1.5）輸出的三段結構、`color-scheme` 與檔頭照「介面」；同一份輸入兩次輸出完全相同。
- **AC-T18-11**（ADR-014 決定 5）`--check`：一致 → exit 0、不改檔；不一致或輸出檔不存在 → exit 1、不改檔；解析失敗 → exit 1、stdout 空。
- **AC-T18-12**（TASKS T-018、ADR-009 決定 1）`apps/web` 的程式不用 alias 就能 import `@english-coach/contracts`、`@english-coach/domain`；`pnpm build` 的實際建置由 PR 觸發的 CI `bundle` job 驗證（依「待確認」第 1 點接線後）。
