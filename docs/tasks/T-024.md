## 介面
```ts
// packages/contracts/src/card.ts（新增匯出；index.ts 已 export * from './card.ts'，不用改）
//   SEED_TAGS、SeedTagSchema、SEED_BATCH_SIZE（= 100）、SeedChunkSchema、SeedBatchSchema、型別 SeedChunk、SeedBatch
// packages/seed-data/src/seed-chunks.ts（新增）
export function checkSeedBatch(input: { readonly fileName: string; readonly data: unknown }, others: readonly SeedBatch[]): Result<SeedBatch, ValidationError>;
export function renderSeedMigration(batch: SeedBatch): string;
// packages/seed-data/src/index.ts（新增）：export * from './seed-chunks.ts';
```
- 簽名、`SEED_TAGS` 的 8 個值與順序（`meeting`、`presentation`、`negotiation`、`interview`、`email`、`project`、`technical`、`small-talk`）、R1～R8 的文字、migration 格式（含範本）照 ARCHITECTURE §4.10；SQL 範本只在 ARCHITECTURE，這張單不重寫。8 個值已由 #91 合併核准（ADR-016 決定 2 與修訂）。輸入形狀比照 B-004 的 `checkQuestionBatch`；錯誤型別照 §4.10 是 `ValidationError`。
- **分工**（§4.10「能放進 zod 的放進 schema」）：`SeedChunkSchema`／`SeedBatchSchema` 放 R1（含 2～6 個字）、R2、R3、R5、R7（`items` 剛好 `SEED_BATCH_SIZE` 筆）、R8 的 `batch` 1～6；`checkSeedBatch` 先過 schema（`data`），再做 R4、R6，以及 R8 的檔名與「`others` 已有同一個 `batch`」：`fileName` 先取 basename（去掉任何目錄），必須是 `batch-<n>.json` 且 `<n>` 等於 `batch`，不合 → R8、`path` 是 `fileName`。
- **issue 的形狀**：回傳 `ValidationError`（`kind: 'validation'`），每個 issue 的 `message` 以規則編號開頭（`R1`～`R8`，後接空白與說明），`path` 是字串：欄位用 `items.<i>.chunk`、`items.<i>.meaning_zh`、`items.<i>.example_en`、`items.<i>.tags`，整批用 `items`（R7）、`batch`（R8）。R6 的 issue 放在「後出現的那一項」的 `items.<j>.chunk`，說明對到哪一批哪一項。形狀根本不合（輸入不是物件、`items` 不是陣列、某一項不是物件）的 issue 以 `shape` 開頭。頂層 `message` 取第一個 issue 的 `message`。一次回傳全部 issue；測試只檢查規則編號與 `path`，說明文字不鎖死。
- **R1～R3 的算法**：R1 的 2～6 個字用空白切；`ChunkTextSchema` 已擋頭尾與連續空白。R2 另外要求 trim 後等於原值（頭尾不得有空白）、不含控制字元（U+0000–U+001F、U+007F，含換行與 TAB），比照 R3；字元數與 `newsWords` 同一種算法（以 code point 計，`Array.from`），漢字用 `\p{Script=Han}`。R3 的字數用 `newsWords`；「不含 `/`」是整個字串任何位置都不能有 `/`（不只是獨立的 `/`）；換行包含 `\n` 與 `\r`。
- **R4、R6 的執行條件**：只對 `chunk` 通過 R1 的項目執行（chunk 不合格時，R1 已回報，正規化沒有意義）；R4 另外要 `example_en` 是字串。其餘規則不互相跳過，所以一份資料可以同時回多條 issue。
- **R6 的正規化**：照 §4.7：連字號換成空白，再用 domain 匯出的 `normalizeWords`，最後用一個空白接回；不複製 `chunk-hit.ts` 裡沒有匯出的 `normalize`。同批內與 `others` 的每一批都比。
- **`renderSeedMigration`**：只做格式化，不驗證（不檢查筆數、不檢查規則）；`tags` 照 JSON 的順序，不排序；空陣列寫 ARCHITECTURE 範本裡的空陣列寫法。同樣的輸入永遠同樣的輸出，不修改傳入的物件。
- **drift 測試**（寫在 `seed-chunks.test.ts`）：比對函式收「檔名 → 內容」兩張對照表（批次 JSON、migration），不直接讀檔，讀檔只在把真實目錄讀進對照表的那一層；這樣「有 JSON 沒 migration」等失敗情境不必在 repo 放壞檔。規則：
  - `supabase/seed-chunks/` 裡檔名符合 `batch-*.json` 但不是 `batch-1.json`～`batch-6.json` 的檔案（例如 `batch-7.json`、`batch-01.json`）算失敗；其他檔名（含 `.sample.md`）本單不處理。
  - 每個 `batch-<n>.json`：經 `checkSeedBatch({ fileName: <basename>, data }, others)`（`others` 是其他所有批次）為 `ok`（檔名與 `batch` 是否相符由檢查器的 R8 判斷），且 `supabase/migrations/` 裡剛好一個檔名以 `_seed_chunk_batch_<n>.sql` 結尾，內容逐字等於 `renderSeedMigration` 的輸出。
  - 有 `_seed_chunk_batch_<n>.sql` 卻沒有對應 JSON、或同一個 `<n>` 有兩個 migration：失敗。目錄不存在或沒有任何批次：通過。
  - 路徑用 `import.meta.url` 和全域 `URL` 算出 repo 根目錄，不寫死絕對路徑；讀檔用 `node:fs`（需要時 `node:path`、`node:url` 的 `fileURLToPath`），型別用 `packages/seed-data/test/node-builtins.d.ts` 只宣告用到的函式（`readFileSync`、`readdirSync`、`join`、`fileURLToPath` 這類；§4.10.1 檔案表），不得宣告未使用的 API。
- **測試資料用工廠建**（ADR-018 決定 10 的做法）：`packages/seed-data/test/factories.ts` 提供 `makeSeedChunk(overrides)`、`makeSeedBatch(overrides)`：用索引產生 100 條互不相同、通過 R1～R8 的項目（內容不必是自然的英文），每個規則的測試只覆寫一處。本單不在 `RouteDeps`、`RouterDeps`、`UserDb`、`DbClient`、`ApiClient` 加任何欄位，所以不改各處的 `makeTest…` 工廠。沒有外部 API，不需要假回應。

## 驗收標準
- **AC-T24-1**（§4.10 契約）`SEED_TAGS` 剛好是上面 8 個值（順序固定）、`SEED_BATCH_SIZE` 是 100；`SeedTagSchema` 只收這 8 個（大小寫要一致）；`SeedChunkSchema`、`SeedBatchSchema` 與型別 `SeedChunk`、`SeedBatch` 由 `@english-coach/contracts` 匯出。
- **AC-T24-2**（R1）`chunk` 含括號、斜線、`…`、頭尾空白、連續空白，或少於 2、多於 6 個字：各回 R1；2 個字與 6 個字（含連字號、撇號、佔位詞 `sb`）通過。
- **AC-T24-3**（R2）`meaning_zh` 去空白後為空、超過 30 字元、沒有漢字、頭尾有空白、含控制字元（換行、TAB、U+0000、U+007F）：各回 R2；30 字元且含漢字通過（字元以 code point 計）。
- **AC-T24-4**（R3）`example_en` 前後有空白、少於 5 或多於 25 個字、含 `/`（任何位置）、含換行：各回 R3；剛好 5 與 25 個字通過。
- **AC-T24-5**（R4）`example_en` 沒有 `chunk` 回 R4；佔位詞（`get buy-in from sb` 對 `…get buy-in from the whole product team…`）與詞形變化（`take over` 對 `took over`）通過；`ship it` 對 `shipment` 回 R4。
- **AC-T24-6**（R5）`tags` 含不在 `SEED_TAGS` 的值、超過 3 個、重複：各回 R5；0 到 3 個合格的值通過。
- **AC-T24-7**（R6）同批內，或和 `others` 的任一批，`chunk` 正規化後相同回 R6，`path` 指向後出現的那一項；`let's go` 與 `lets go` 不算重複。
- **AC-T24-8**（R7、R8）`items` 少於或多於 100 筆回 R7；`batch` 是 0、7、小數、字串，或 `others` 已有同一個 `batch`：回 R8（`path` 是 `batch`）；`fileName` 不是 `batch-<n>.json` 或 `<n>` 不等於 `batch`：回 R8（`path` 是 `fileName`），帶目錄時只看 basename；1～6 的整數且檔名相符通過。
- **AC-T24-9**（§4.10 全部 issue 一次回傳）一份同時違反多條規則的資料，所有對應的 issue 都在；形狀不合回 `shape`；合格資料回 `ok`，值型別是 `SeedBatch`。
- **AC-T24-10**（§4.10 migration 格式）`renderSeedMigration` 照 ARCHITECTURE 範本：第一行註解帶批次號、順序照 `items`、兩個空白縮排、`'` 寫成 `''`、空 `tags` 與多個 `tags` 的寫法、最後一列 `;`、結尾一個換行、沒有 `on conflict`；同樣的輸入兩次輸出相同，且不修改傳入的物件。
- **AC-T24-11**（§4.10 drift 規則）比對函式：JSON 與 migration 一致時通過；migration 差一個字元、有 JSON 沒 migration、同一個 `<n>` 兩個 migration、有 migration 沒 JSON、檔名 `<n>` 與 `batch` 不同、`batch-7.json` 與 `batch-01.json`：各自失敗並指出是哪一批；沒有任何批次通過。
