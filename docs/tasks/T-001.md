> 名詞
> - **monorepo**：一個 repo 裡放好幾個套件（前端、共用型別、純邏輯），用 pnpm workspaces 一起管理。
> - **lockfile（`pnpm-lock.yaml`）**：記下每個套件實際安裝的版本，讓每台電腦和 CI 裝到一模一樣的東西。
> - **dependency-cruiser**：檢查「哪個資料夾可以 import 哪個資料夾」的工具；違規就讓 `pnpm arch` 失敗。
> - **typescript-eslint strict-type-checked**：最嚴格的一組 TypeScript 程式碼規則，會用型別資訊抓錯。
> - **測試用範例（fixture）**：故意寫錯（或寫對）的小檔案，只給測試用，證明規則真的會擋。

## 實作限制

### A. 可以安裝的套件（只有這 5 個，全部是 devDependencies；ADR-001 依賴清單已核准）
| 套件 | 版本規則 |
|---|---|
| `typescript` | **5.x 的最新版**（CLAUDE.md §2 寫 TypeScript 5；不要裝 6 或以上） |
| `eslint` | `typescript-eslint` 當下最新版支援的最新 ESLint 主版本 |
| `typescript-eslint` | 當下最新穩定版 |
| `dependency-cruiser` | 當下最新穩定版 |
| `vitest` | 當下最新穩定版 |
- pnpm 用當下最新穩定版，寫進 `packageManager`。
- `pnpm add -D …` 與不加參數的 `pnpm install` 在 `.claude/settings.json` 屬於「要問」：Claude Code 會跳確認視窗，**Hansheng 只核准上表 5 個套件**；其他套件一律拒絕。
- 如果發現還需要其他套件（例如 `@types/node`、`@eslint/js`、`globals`），**停下來寫進報告**，不要自己加（CLAUDE.md §5 第 5 條，新增依賴要 Architect Review）。
- 第三方套件的 `.d.ts` 若因缺少 Node 型別讓 `tsc` 失敗，可以在 `tsconfig.base.json` 加 `"skipLibCheck": true`（只略過 `node_modules` 裡的型別檔，不放鬆我們自己的程式），並在報告寫明。`tooling/` 的測試程式不要 import `node:*` 模組，這樣不需要 `@types/node`。
- 版本號、選擇理由寫進報告的「決定紀錄」。

### B. TypeScript
- `tsconfig.base.json`：AC-T1-4 的 5 個選項，加 `target`／`module`／`moduleResolution` 等基本設定（自行選擇，報告說明）。不得出現 `"strict": false` 或關掉任何 AC-T1-4 選項。
- 根 `tsconfig.json`：`"files": []`＋`references` 指向 `tooling`；之後的單（T-002 起）再把 `packages/*`、`apps/web` 加進來。
- `tooling/tsconfig.json`：extends `../tsconfig.base.json`，`include` 只含 `tooling/*.test.ts`，排除 `tooling/fixtures/**`；需要 `resolveJsonModule` 讀 `tsconfig.base.json` 時打開。`tsc -b` 產生的檔案（`*.tsbuildinfo`、輸出資料夾）不得 commit。

### C. dependency-cruiser（`.dependency-cruiser.cjs`）
- 7 條規則，對應 ADR-008：
  | ADR-008 | 規則內容（路徑相對 repo 根目錄） |
  |---|---|
  | 1 | `packages/domain/**` 只能 import `packages/contracts/**`（以及同資料夾內） |
  | 2 | `packages/contracts/**` 只能 import `zod`（以及同資料夾內） |
  | 3 | `apps/web/src/features/X/**` 不得 import `apps/web/src/features/Y/**`（X≠Y） |
  | 4 | 只有 `apps/web/src/api/**` 可以 import `@supabase/supabase-js` |
  | 5 | `supabase/functions/<endpoint>/**`（`_shared` 以外）不得直接 import `supabase/functions/_shared/providers/<adapter>`，只能經過 `_shared/providers/registry.ts` |
  | 6 | 只有 `supabase/functions/_shared/providers/registry.ts` 可以 import `supabase/functions/_shared/config/paid.ts` |
  | 10 | 禁止循環依賴 |
- `tooling/fixtures/arch/` 底下用**和真實專案相同的相對路徑**（例如 `tooling/fixtures/arch/packages/domain/src/bad-import.ts`）；測試用 dependency-cruiser 的 API 並把 base 目錄設在 `tooling/fixtures/arch`，讓同一份規則（用 `^packages/domain/` 這類路徑）同時適用真實專案與範例。若 dependency-cruiser 做不到這一點，停下來寫進報告，**不要**為了測試而放寬規則的路徑。
- 範例檔裡 import 不存在的套件（例如 `@supabase/supabase-js`）時，dependency-cruiser 要能判斷成「該套件」而不是報錯中止；做不到就在報告說明採用的替代寫法。
- `pnpm arch` 掃 `apps packages supabase`，排除 `tooling/fixtures`；資料夾還不存在時指令要成功（例如用 `--ignore-known` 以外的正當方式；做法寫進報告）。

### D. ESLint（`eslint.config.js`，flat config）
- typescript-eslint `strict-type-checked`（用 `projectService` 或等效設定取得型別資訊）。
- ADR-008 第 7～9 條用 `no-restricted-syntax`／`no-restricted-globals`／`no-restricted-properties`，以 `files` 限定路徑。訊息要寫明原因與 ADR-008 條號（例如 `ADR-008 #9: domain must not read the clock; pass now as a parameter`）。
- 忽略：`node_modules/**`、`dist/**`、`coverage/**`、`.claude/**`、`.github/**`、`tooling/fixtures/**`。
- `supabase/functions/**`（Deno）的型別檢查方式由 T-003 決定；本單只要確定規則的 `files` 路徑已經寫好。

### E. 單元測試（`tooling/*.test.ts`，Vitest）
- 不呼叫網路、不讀 `.env`、不依賴目前時間。
- 測試名稱寫明對應的 ADR-008 條號或 CLAUDE.md 條號。
- 不得 `it.skip`、`test.only`（CLAUDE.md §7）。

## 結束時
1. 在 `task/T-001` commit（`[ClaudeCode] T-001 monorepo 骨架與 pnpm check`）並 `git push -u origin task/T-001`。不得動 main、不得合併、不得開 PR、不得 force push。
2. 寫 `docs/reports/T-001.md`（同分支 commit 後再 push 一次）：
   - 完成摘要、變更檔案清單
