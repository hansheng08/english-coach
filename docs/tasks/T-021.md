## 目標
使用者（或之後的頁面）給一句英文，`POST /tts` 用設定裡的語音回一個可以播放的 signed URL；同一句同一個語音第二次以後直接用 `tts` bucket 裡的物件，不再呼叫 Azure。前端有一個同時只播一個來源、可重複與排隊播放的 `audio/player`。

## 介面
§4.19 已定的 `tts.ts`（`TTS_TEXT_MAX_CHARS`、`DEFAULT_TTS_VOICE`、`normalizeTtsText`、`TtsRequestSchema`、`TtsResponseSchema`）、`ttsObjectPath`、`audio/player` 的型別照 ARCHITECTURE；以下是 TechLead 補的決定：
```ts
// supabase/functions/_shared/db/tts-store.ts（新增；照 user-db.ts：對外只有回 Result 的函式）
export type TtsStore = {
  readonly readVoice: () => Promise<Result<VoiceId, AppError>>;            // profile.settings.tts.voice
  readonly find: (path: StoragePath) => Promise<Result<{ readonly bytes: number } | null, AppError>>;
  readonly upload: (path: StoragePath, audio: Uint8Array, mime: TtsResult['mime']) => Promise<Result<null, AppError>>;
  readonly signedUrl: (path: StoragePath) => Promise<Result<string, AppError>>;   // 3600 秒
  readonly recordCall: (r: ProviderCallRecord) => Promise<Result<null, AppError>>;   // 轉呼叫既有的 insertProviderCall（_shared/db/provider-call.ts，不改該檔）
};
export function ttsStoreFrom(client: TtsDbClient, userId: UserId): TtsStore;
// supabase/functions/api/tts.ts（新增）
export const postTts: Route;            // router.ts 的 RouteKey 加 'POST /tts'
export const TTS_TIMEOUT_MS = 8000;     // synthesize 的 timeoutMs（§6 第 6 點；/tts 目標 ≤ 3 s）
```
- **`readVoice`**：讀 `profile.settings`，取 `tts` 這一組。`SettingsSchema`（T-020）已在 main 就用 `SettingsSchema.parse(settings).tts.voice`；還沒有就由本單在 `settings.ts` 建 `TtsSettingsSchema`（只有 `provider`、`voice`，`voice` 的預設是 `DEFAULT_TTS_VOICE`，§4.19），用 `TtsSettingsSchema.parse(settings.tts ?? {})`。沒有 `profile` 列 → 預設語音；`tts` 不合法 → `internal`（不默默改用預設）。
- **`find`**：`storage.from('tts').list(<user_id>, { search: <檔名>, limit: 1 })`，名稱完全相同才算有，回 `metadata.size`；沒有 → `null`。`upload` 用 `upsert: false`；回「已存在」（另一個請求剛好先傳）也算成功。Storage 錯誤 → `storage_failed`（§5.0.4；`find` 的 `op` 是 `download`、`upload` 是 `upload`、`signedUrl` 是 `sign`；訊息不含路徑）；讀 `profile` 的錯誤 → `db_failed`。
- **`postTts` 順序**：
  1. body 照 §5.1.1 驗證，用 `TtsRequestSchema`（正規化後 1～1,000 字元；超過或空的 → 400 `validation`，`path` 是 `text`）。
  2. `voice = readVoice()`；`path = ttsObjectPath(ctx.userId, voice, text)`（`text` 已正規化）。
  3. `find(path)` 有 → `cached: true`，`durationMs = Math.round(bytes * 8 / 48)`（和 §5.6.3 同一個公式；抽成 `_shared/tts/cache.ts` 的 `mp3DurationMs(bytes)`，adapter 不改）。
  4. 沒有 → `deps.providers.resolve('tts', DEFAULT_SETTINGS, usedThisMonthNtd)`（第三個參數用 `sumPaidUsageThisMonthNtd`，T-020 建，ADR-019 決定 4；**過渡**（§4.19）：T-020 還沒合併、函式不在 main 時傳 `0`，在報告與 TASKS 備註，由 T-020 的用量接線改接）→ `synthesize(text, voice, { timeoutMs: TTS_TIMEOUT_MS })` → **寫 `provider_call`**（見下）→ `upload` → `cached: false`、`durationMs` 用 `TtsResult.durationMs`。
  - **`provider_call`**（§4.19、ADR-020 決定 3）：只有第 4 步真的呼叫了 `synthesize` 才寫，成功與失敗（`timeout`、`rate_limited` 等）各寫一筆；第 3 步快取命中不呼叫供應商，**不寫**；`resolve` 就失敗（`not_configured`、付費被拒）沒有送出請求，也不寫。`recordCall` 的內容：`capability: 'tts'`、`provider` 與 `tier` 取自 `resolve` 回的 provider（`id`、`tier`）、`model: null`（Azure TTS 沒有模型 ID）、`errorKind` 成功 null／失敗是 `ProviderError` 的 `kind`、`latencyMs` 用 `deps.now()` 在 `synthesize` 前後各讀一次的差；T-020 的 `providerCallRow` 合併後 `cost_ntd`、token 由 `estimateCostNtd` 填（Azure F0 為 0）；本單先合併時只送上面這些欄位，其餘用資料庫預設。`recordCall` 本身回錯：不改變回應（照 §4.19 這是記帳，不是請求的一部分），log 一行 `tts` 開頭、只含 `kind`，不含文字與路徑（TechLead 決定，請 Architect 順手確認，不擋派工）。
  5. `signedUrl(path)` → 200＋`TtsResponseSchema` 的值；`meta.ttsProvider` 是用到的 provider id（快取命中時是 `DEFAULT_SETTINGS.tts.provider`），`meta.voice` 是 `voice`。
  - 錯誤：供應商錯誤照 §5.0.4 轉成回應（`not_configured`、`timeout`、`rate_limited` 等原樣帶出，不改用 Web Speech）；Storage 錯誤 → 502 `storage_failed`、資料庫錯誤 → 500 `db_failed`（§5.0.4）。
- **`RouteDeps`** 加一個必填欄位 `ttsStore: (ctx: AuthContext) => TtsStore`；`makeTestRouteDeps` 在同一個 commit 補預設值，並新增 `makeTestTtsStore`（`_shared/db/test/fakes.ts`，沒覆寫的方法回 `not stubbed: <名稱>`）（§5.1.1 規則 2、3）。`index.ts` 用使用者 client 接上。
- **`wiring.ts`**：`loadAzureSpeechConfig` 成功時把 `createAzureSpeechProviders` 的 `tts`（與 `pronunciation`）放進清單；失敗就不放（`resolve` 自然回 `not_configured`）。Gemini 的部分不改。
- **migration**（`supabase/migrations/<時間戳記>_t021_tts_bucket.sql`；時間戳記必須比最新的檔案晚）：`tts` bucket（`public = false`、`file_size_limit = 2097152`）；`storage.objects` 兩個 policy `tts_select_own`、`tts_insert_own`（`authenticated`，條件照 §4.12.1 Storage RLS）；不建 `update`、`delete` policy。
- **前端**：
  - `apps/web/src/audio/player.ts`：§4.19 的 `createAudioPlayer` 全部行為（同時只播一個、新的 `play` 先停舊的、`repeat` 次數、多個來源依序播、`resolve` 或 `<audio>` 的 `error` → `error` 狀態、`subscribe` 回取消函式）。`audio/` 不 import `api/`。
  - `ApiClient` 加 `tts(text): Promise<Result<TtsResponse, AppError>>`、`ttsSignedUrl(path): Promise<Result<string, AppError>>`（和既有方法一樣回 `AppError`，伺服器的 `ApiErrorBody` 由 supabase 版轉成 `AppError`）；supabase 版呼叫 `POST /tts`、`createSignedUrl(path, 3600)`；mock 版不發網路請求，回 `public/mock/tts.wav`（新增的極短靜音檔）的網址。`apps/web/src/api/tts-resolve.ts` 的 `ttsResolver(client): PlayerDeps['resolve']` 把兩個方法接成 player 要的 `resolve`。
  - **`ApiClient` 工廠與組成根**（§9.1.7、ADR-020 決定 1、CLAUDE.md §5 第 21 條；Architect 已確認）：本單是第一張擴充 `ApiClient` 的單，所以建 `apps/web/src/api/test/fakes.ts` 的 `makeTestApiClient(overrides?)`、`makeTestApiRuntime(overrides?)`（沒覆寫的方法回 `err({ kind: 'internal', message: 'not stubbed: <名稱>' })`，回傳完整的 `ApiClient`，正式程式不 import）；已經有這個檔案（別張先建）就沿用。本單新加的 `tts`、`ttsSignedUrl` 在 `ApiClient` 介面上**暫時選填**、`fakes.ts` 補預設值（§9.1.7 過渡 1、ADR-021 決定 4）；改回必填、拿掉 `??`、QA 改兩個探針由 **T-020** 做（§9.1.7 過渡 2；T-020 若比本單先合併，改由本單之後第一張改 `ApiClient` 的單做），TASKS 已備註。組成根 `createSupabaseApiClient(auth, deps)` 的 `deps` 是 §9.1.7 的 `ApiClientDeps`：`fetch: typeof globalThis.fetch`、`getAccessToken: () => Promise<string | null>`（ADR-021 決定 5）；預設全域 `fetch` 與 session 的 access token，**未登入或沒有 token 回 `null`、不丟例外**，需要登入的方法看到 `null` 回 `err({ kind: 'unauthenticated', … })`、不發請求。supabase 版的 `tts` 只用注入的 `deps`，不在方法裡直接用全域 `fetch`。`makeTestApiRuntime(overrides?)` 回 `ApiRuntime` 加測試用 `deps`，預設 `client` 是 `makeTestApiClient()`、`preview` 是 `null`、`deps.fetch` 是未覆寫就失敗的假 fetch、`deps.getAccessToken` 是回 `null` 的 async 函式；可覆寫 `client`、`preview`、`fetch`、`getAccessToken`。`features/**` 一律經 `useApi()`。既有 QA 探針（`features/login/login-errors.qa.test.ts:39`、`src/app.qa.test.ts:29-35`）若仍寫完整的 `ApiClient`／`ApiRuntime`，由 QA 在驗收時改成工廠，本單不碰，不改也要通過。

## 驗收標準
- **AC-T21-1**（§4.19 schema）`tts.ts` 照 §4.19：`normalizeTtsText` 依序去「/」、NFC、空白壓成一個、trim；`TtsRequestSchema` 正規化後 1～1,000 字元、`.strict()`；`TtsResponseSchema` 五個欄位；`DEFAULT_TTS_VOICE` 是 `azure:en-US-AvaNeural`，全專案只寫這一次；`index.ts` 匯出。
- **AC-T21-2**（§4.19 快取鍵）`ttsObjectPath(userId, voice, text)`＝`<user_id>/<sha256(voice + "\n" + text) 小寫 hex>.mp3`，用 `crypto.subtle.digest`；`/tts` 只透過它算路徑。
- **AC-T21-3**（§5.1.1）`POST /tts`：未登入 401；body 不是 JSON、多出欄位、正規化後空的、超過 1,000 字元 → 400 `validation`（`path` 是 `body` 或 `text`），都不讀設定、不呼叫供應商。
- **AC-T21-4**（§4.19 預設語音）語音只從 `readVoice` 來：沒有 `profile` 列或沒有 `tts` → `DEFAULT_TTS_VOICE`；有自訂語音就用它；`tts` 不合法 → 500 `internal`。請求帶 `voice` 會被 `.strict()` 擋下。
- **AC-T21-5**（§4.12.1 快取）物件已在 → 不呼叫 `resolve`、`synthesize`、`upload`，`cached: true`，`durationMs` 用物件大小換算；不在 → `synthesize` 一次、`upload` 一次（`mime` 是 `audio/mpeg`）、`cached: false`；`upload` 回「已存在」也算成功。
- **AC-T21-6**（§5.0.4）供應商錯誤（`not_configured`、`timeout`、`rate_limited`、`invalid_response`）照 §5.0.4 回對應的狀態與 body，不 `upload`；Storage 錯誤一律 502 `storage_failed`（可重試，`op` 照「介面」），不用 `db_failed`，訊息不含路徑與文字。
- **AC-T21-7**（§5.6.3、§4.19、§4.15.6）成功回應通過 `TtsResponseSchema`；`meta.voice` 是用到的語音；`synthesize` 收到的 `timeoutMs` 是 `TTS_TIMEOUT_MS`；`resolve` 的第三個參數是 `sumPaidUsageThisMonthNtd` 的結果（T-020 建）；T-020 未合併時過渡傳 `0` 並在報告註明。
- **AC-T21-8**（§5.1.1 規則 2、3）`RouteDeps.ttsStore` 必填；`makeTestRouteDeps` 有預設值；`makeTestTtsStore` 沒覆寫的方法回 `not stubbed:`；QA 探針不改也通過 `tsc -b`。
- **AC-T21-9**（§5.4.1）`createProviders`：有 Azure 兩個變數時 `resolve('tts', DEFAULT_SETTINGS, usedThisMonthNtd)` 回 Azure TTS；缺任一個時回 `not_configured`；Gemini 的行為不變。
- **AC-T21-10**（§4.12.1，靜態＋pgTAP）migration 原文含 `tts` bucket、`false`、`2097152`、兩個 policy 名稱、`storage.foldername(name)` 條件，沒有 `for update`、`for delete`；pgTAP：bucket 存在且 `public = false`、兩個 policy 的指令是 `SELECT`、`INSERT`（由 PR CI 驗證）。
- **AC-T21-11**（§4.19 播放器）`createAudioPlayer`：狀態依序 `idle` → `loading` → `playing`（`repeat.index` 從 0 到 `total - 1`）→ `idle`，回 `ok('ended')`；播放中再 `play` → 舊的回 `ok('stopped')`、只有一個 `<audio>` 在播；多個來源依序播；`stop()` 回 `idle`；`resolve` 回錯或 `<audio>` 的 `error` 事件 → `error` 狀態帶錯誤、回 `err`；取消訂閱後不再收到狀態。

## 測試的寫法
- 後端全用假依賴：`makeTestRouterDeps`、`makeTestRouteDeps`、`makeTestTtsStore`（只傳要覆寫的部分）、假 `TtsProvider`、假 Storage client（記錄 `list`、`upload`、`createSignedUrl` 的參數）；不連網、不連資料庫、不讀系統時鐘。

- 不改用 Web Speech（§4.13.3）；不預先產生 TTS（T-025b）；不做任何畫面（播放鈕由各頁的單做）。`features/**` 不直接 `fetch`、不 import `supabase-js` 打產品 API（§9.1.7）；不建模組載入時就連上正式後端的全域 client。
