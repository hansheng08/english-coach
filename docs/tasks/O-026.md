## 背景（開始前先讀）
- 證據只以 T-018 第二次 run-task [45852999547](https://github.com/hansheng08/english-coach/actions/runs/45852999547)（2026-11-26 23:50–00:06 台北時間）與備份分支 `archive/T-018-run1`（head `28367c8c2e7dace35fda16b7c697cda11f27e7ee`，第一次 run 的 tip）為準。Hansheng 核准後，該 tip 已備份到 `archive/T-018-run1`，當時的 `task/T-018` 已刪除並從 main 重派。不要讀、不要推現在的 `task/T-018`。
- 根因有三層。第一，workflow 在 `claude-run-task.yml` 第 40～46 行用 `actions/checkout@v6` 檢出 dispatch 的預設分支（main），`fetch-depth: 0`、`persist-credentials: false`（必須維持 false，RUNBOOK §1.1）。第 76～80 行的 `run-task-pre-head.sh` 已記到既有分支 tip（log：`run-task-pre-head: task/T-018 exists at 28367c8c2e7dace35fda16b7c697cda11f27e7ee`），但沒有把工作區切到該 tip。第二，`.claude/skills/run-task/SKILL.md` 第 14 步示例是 `git switch -c task/<編號> origin/main`，既有遠端分支也會從 main 再長一條歷史。第三，Claude 想確認既有 commit 時執行 `git log --oneline origin/main..origin/task/T-018 | head`，被權限拒絕（該 run「Summarize permission denials」count: 4，其中一條原文即此指令）。`settings.json` 已允許 `Bash(git log*)`，拒絕的是管線與 `head`（deny 有 `Bash(head)`／`Bash(head *)`）；`--allowedTools` 已有 `Bash(git *)`。因此只放寬 allowedTools 不夠，也不要為了本單放寬 `|` 或 `head`。Claude 從 main 另建 commit `7fb74cce397e9b84de590497893677260662590c`（不是 `28367c8` 的子孫），push 未發生，當時遠端仍停在 `28367c8`（現由 `archive/T-018-run1` 保存）。
- 「Verify push triggered CI」（`verify-push.sh` 第 87～141 行，workflow 第 165～180 行）只讀遠端 tip，再找該 SHA 的 `ci.yml` event=push run，不比對這次的 local `HEAD`，也不比對 `PRE_HEAD`。該 run log：`remote task/T-018 = 28367c8c2e7dace35fda16b7c697cda11f27e7ee`，接著找第一次 push CI [45849856325](https://github.com/hansheng08/english-coach/actions/runs/45849856325)（log 裡 `conclusion` 為 `failure`），仍印 `Found push-triggered CI run for task/T-018 @ 28367c8c2e7dace35fda16b7c697cda11f27e7ee` 且 `VERIFY_OUTCOME: success`、`VERIFY_REASON: ok`。這是假綠燈：接受了更早一次 run 的 SHA（問題在 SHA 不屬於這次，不在於該舊 run 的 `conclusion` 為 failure）。對本次 SHA，verify 不要求 `conclusion=success`，見「已決定」。
- post-check 有抓到（`run-task-post-check.sh` 第 88～89 行）：`run-task-post-check: PRE_HEAD 28367c8c2e7dace35fda16b7c697cda11f27e7ee is not an ancestor of HEAD 7fb74cce397e9b84de590497893677260662590c`，以及 `run-task-post-check: FAILED: pre-head-invalid`。
- 留言步驟（`run-task-summary-step.sh` 第 49～59 行）用 `SHA="$(git rev-parse HEAD)"`（未推送的 `7fb74cc`）去留 commit comment。`post-run-task-comment.mjs` 不檢查該 SHA 是否在遠端。log：`post-run-task-comment: gh: No commit found for SHA: 7fb74cce397e9b84de590497893677260662590c (HTTP 422)`，以及 `{"message":"No commit found for SHA: 7fb74cce397e9b84de590497893677260662590c","documentation_url":"https://docs.github.com/rest/commits/comments#create-a-commit-comment","status":"422"}`。
- `run-task-outcome.sh` 第 149～172 行只在 claude／verify／summary 都已是 success 時，才把 `post_check=failure` 收成 `post_check_failed`。此次 `post_check=failure` 且 `summary=failure`，變成 `summary_failed`。log：`run-task-outcome: task_lint=success post_check=failure usage_limit=false claude=success verify=success summary=failure -> summary_failed`。既有 `run-task-outcome-test.sh` 第 181 行只覆蓋 post-check success 時的 summary_failed，沒有「post-check 與 summary 都 failure」的案例。

## 目標
修正／重跑既有 `task/*` 或 `fix/*` 分支時，run-task 必須接在該分支當下的 head 上。verify 必須確認遠端 head 等於這次 local HEAD、且不等於 `PRE_HEAD`，不得接受更早一次 run 的 SHA；只要求該 SHA 已觸發 push CI，不要求該 run 的 `conclusion=success`。post-check 失敗時 overall outcome 必須是 `post_check_failed`，留言失敗不得覆蓋。commit comment 只准留在實際已推送的 SHA。

## 介面
- 若遠端已有任務單指定的 `task/<id>` 或 `fix/Q-<nnn>`：在 Claude 開始前，把工作區切到該分支的 `PRE_HEAD`，並保留足夠歷史（`git merge-base --is-ancestor` 可跑）。`persist-credentials: false` 不得改成 true。分支尚不存在（第一次 run）時，維持在 dispatch 檢出的 main。切到既有分支後，工作區裡的 `docs/tasks/<TASK>.md` 必須仍是 Task lint 用的那一版（通常是 dispatch 的 main）；不要為了對齊任務單而去 merge main。
- `run-task/SKILL.md`：遠端或工作區已在指定分支時，繼續該 head（例如 `git switch <分支>`），不得在分支已存在時再執行 `git switch -c <分支> origin/main`。不要為了查歷史而放寬 `head` 或管線的 deny；workflow 切好分支是主做法。
- `verify-push.sh` 必須同時成立才可 `verify_reason=ok`（否則 fail-closed，exit 1）：（1）遠端 head 等於這次 local `HEAD`（40-hex）；（2）遠端 head 不等於 `PRE_HEAD`；（3）該 SHA 上已觸發 `ci.yml`、`event=push`、`headBranch` 相符的 run。幕僚長 00:19（台北時間）決定：（3）不要求該 run 的 `conclusion` 為 success；該 SHA 的 push run 仍在進行（in_progress）或 `conclusion` 為 failure，只要 run 已觸發，仍可 `ok`。理由：CI 結果由 G3 的 PR `ci-ok` 判定；verify 當下 CI 常常還在跑；不穩定的 CI 不應讓 Claude 這次輸出被判失敗。該 SHA 完全沒有 push CI run 則失敗。輸入可用環境變數 `PRE_HEAD`（由 workflow 傳 `steps.pre_head.outputs.pre_head`）。比對失敗請新增明確的 `verify_reason`（例如遠端≠local 為 `head_mismatch`，遠端＝`PRE_HEAD` 為 `stale_head`），並加入 `normalize_verify_reason`。不得只因更早一次 SHA 的遠端 tip 上「曾經有過」push CI 就判 `ok`。仍不要在 verify 步驟對已撤銷的 Claude token 做 `git fetch`（O-007）。
- `run-task-outcome.sh`：在 task-lint 已過、claude 為 success，且 `--post-check failure` 時，overall `outcome` 必須是 `post_check_failed`；`summary` 為 failure（含留言 422）不得改成 `summary_failed`。task-lint 失敗或 claude 未成功的既有優先順序維持。verify 也失敗時，維持既有「verify_failed 優先於 post-check」（`run-task-outcome-test.sh` 第 180 行），本單不改那條。
- 留言：commit comment 的 SHA 必須已在遠端（這次有推送：遠端 head＝local HEAD）。未推送的 local HEAD（如此次的 `7fb74cc`）不得拿去 POST `/commits/<sha>/comments`。沒有已推送 SHA 時，略過 commit comment，且不得因此把 post-check 失敗改寫成 `summary_failed`。若已有 PR，可對 PR 留言，但 fallback 的 commit comment 仍須遵守「只留已推送 SHA」。

## 驗收標準
- AC-O26-1：遠端已有指定 `task/*`／`fix/*` 時，Claude 開始前工作區已在該 `PRE_HEAD`，歷史足夠做祖先檢查；第一次尚無分支時仍從 main 起步。`persist-credentials: false` 維持不變。
- AC-O26-2：`run-task/SKILL.md` 要求已存在的分支接在既有 head，不得再從 `origin/main` 建同名分支。
- AC-O26-3：verify 在遠端 head ≠ 這次 local HEAD、或遠端 head ＝ `PRE_HEAD`、或只有更早一次 SHA 的 push CI、或該（這次）SHA 沒有任何 push CI run 時必須失敗（再現 45852999547：local `7fb74cc`、遠端 `28367c8` 不得 `ok`）。遠端＝local 且 ≠ `PRE_HEAD` 且該 SHA 已觸發 push CI 時可 `ok`；不要求該 run 的 `conclusion=success`（in_progress 或 conclusion 為 failure 亦通過）。
- AC-O26-4：`--post-check failure` 且 summary failure 時，outcome 為 `post_check_failed`，不得為 `summary_failed`。
- AC-O26-5：對未出現在遠端的 SHA 不得發 commit comment；對已推送 SHA 仍可留言（PR 或 commit comment）。
- AC-O26-6：本單新增或修改的檔沒有未允許的 `|| true`、`continue-on-error`。突變必須被抓到：verify 只認遠端 tip 上既有 push CI、outcome 在 post-check 失敗時改報 `summary_failed`、留言不檢查 SHA 是否已推送、既有分支仍從 `origin/main` 開新歷史。上述削弱若仍能通過測試，本 AC 失敗。
