## 背景（開始前先讀）
- **QA 第 1 次退件**（head `4d92eef`）。push CI 的 e2e 不跑，QA 在本機以真瀏覽器跑 `test/e2e/t019.spec.ts`，有 5 個必定失敗；TechLead 在 `4d92eef` 重跑，結果相同：
  - **D1（TC-5）**：precache 裡圖示的網址帶 `?__WB_REVISION__=<雜湊>`（例如 `/icons/icon-192.png?__WB_REVISION__=…`），測試用整個網址做 `endsWith('/icons/<檔名>')`，所以找不到。產品正確。
  - **D2（TC-12）**：卡片出現時有 `ec-up`（上移 16px＋淡入），測試在動畫還沒結束時就量位置：手機底距量到 71（應為 76）、電腦右距量到 16（應為 24）。動畫結束後量，值都正確。
  - **D3（TC-18 與「淺色→跟隨系統」）**：建置後的 CSS 把 `--color-theme-bar` 壓成小寫（`#0a1420`、`#f4f5f7`），`applyThemeColor` 收到的是小寫，測試比對大寫。幕僚長決定：測試改成不分大小寫比對，產品不改。
  - **D4**：開啟時離線 → 恢復連線（面板換回頁面）→ 再斷線，內容區又換成離線面板。原因是 `App.tsx` 的 `openedOffline` 一旦為真就不會重設。違反 pwa.md §3.2「已經開著的畫面內容不清掉」。
  - **D5**：兩個分頁都顯示「有新版本」時，先在一個分頁按「更新」，新 SW 接手後該分頁重新載入；另一個分頁的卡片還在，但按「更新」什麼都不會發生。原因是 `pwa/register.ts` 的 apply 在 `registration.waiting` 已經是 null（新版已由別的分頁啟用）時直接結束，沒有重新載入。
- **Claude 在 T-019 報告的未決事項**，幕僚長的決定：
  - (a) `watchForUpdate` 沒傳 `register` 時什麼都不做，與原單「介面」寫的「`register` 預設會註冊 SW」不符。產品要照原單與 ARCHITECTURE 的約定：不傳 `register` 也會註冊 SW 並在有新版時通知。原單「介面」不改。

## 目標
T-019 的 E2E 在 PR 觸發的 CI `e2e` job 穩定通過、斷言強度不變；再次斷線時已開著的頁面不被換掉；任一分頁按「更新」都會換成新版；`watchForUpdate` 預設就會註冊 SW；`?pwa=update` 在正式建置無效。

## 介面
```ts
// apps/web/src/pwa/register.ts：RegisterSW 型別移到這裡（update.ts 再匯出同名型別），避免 pwa/update.ts ↔ pwa/register.ts 循環相依
export type RegisterSW = (options: { onNeedRefresh?: () => void }) => (reloadPage?: boolean) => Promise<void>;
// apps/web/src/pwa/update.ts：register 沒傳時用 registerServiceWorker
export function watchForUpdate(onNeedUpdate: (apply: () => Promise<void>) => void, register?: RegisterSW): void;
// apps/web/src/pwa/update.ts（新增）：previewActive 為 true 且 search 的 pwa 參數是 update 才回 previewUpdateRegister，其餘一律 registerServiceWorker
export function chooseRegister(previewActive: boolean, search: string): RegisterSW;
```
- **E2E 修正（D1～D3）**：TC-5 比對前先去掉網址的查詢字串（只比對 pathname），origin 與 `/functions/` 的檢查照舊。TC-12 手機與電腦兩個量位置的測試，量之前先等卡片上所有動畫的 `finished` 都完成（決定性的等待），量到的值仍是原單的精確值。theme-color 的 E2E（TC-18 與「淺色→跟隨系統」）把 `content` 轉成同一種大小寫再比對，`media` 與 meta 個數照原本嚴格比對。不用 `waitForTimeout` 或任何固定等待，不設 `retries`、不加 `test.slow`／`test.fixme`；其他斷言一個都不改。
- **再次斷線（D4）**：「離線開啟」只在開啟時離線、而且還沒恢復過連線時成立；一旦恢復連線就不再成立，之後再斷線只多斷線條，內容區照舊顯示頁面。
- **多分頁更新（D5）**：apply 被呼叫時，若等待中的 SW 已經不在（別的分頁已讓新版接手），直接重新載入頁面一次並結束；仍在等待時照原本送 `SKIP_WAITING`、接手後重新載入一次。卡片文字「按更新會重新載入頁面。」不變。
- **預設註冊（a）**：`watchForUpdate` 不傳 `register` 時，用 `registerServiceWorker` 註冊並在有新版時呼叫 `onNeedUpdate`；有傳時用傳入的。不支援 SW 的環境照舊什麼都不做、不丟錯。
- **預覽專用參數（b）**：`main.tsx` 改用 `chooseRegister(runtime.preview !== null, window.location.search)` 決定傳給 `App` 的 register。正式建置的 `preview` 是 null，`?pwa=update` 無效。畫面元件不判斷資料模式。
