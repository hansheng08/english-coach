> 名詞
> - **`GITHUB_TOKEN`**：GitHub Actions 自動提供的短期權限憑證。用它 `git push` 時，GitHub 故意不觸發新的 workflow（避免無窮迴圈）；例外是 `workflow_dispatch` 與 `repository_dispatch`。
> - **`persist-credentials`**：`actions/checkout` 的選項。設為 `true`（預設）時，會把 `GITHUB_TOKEN` 寫進獨立的 credentials 檔，再以 `includeIf.gitdir` 掛進 git 設定；這個 HTTP `Authorization` header 會蓋過 remote URL 裡的其他 token。
> - **Claude GitHub App token**：`claude-code-action` 用 job 的 OIDC（`id-token: write`）向 Anthropic 換到的安裝 token。用它推送才會觸發 `push`／`pull_request` synchronize，CI 檢查才會出現在 PR 上。
> - **execution_file**：action 輸出的執行紀錄路徑（`$RUNNER_TEMP/claude-execution-output.json`），內含工具呼叫與 `permission_denials`。
> - **artifact**：GitHub Actions 上傳、可在該 run 頁下載的檔案；本 repo 為私有，有讀取權限的協作者都可以下載。

- 試跑證據（T-900，run https://github.com/hansheng08/english-coach/actions/runs/45179784919 ，2026-11-23 21:01–21:03 台北時間）：action 已成功換到 App token（日誌有 `App token successfully obtained`、`Using GITHUB_TOKEN from OIDC`、`Updated remote URL with authentication token`），但清 header 時寫 `No existing authentication headers to remove`。同 run 的 checkout 日誌則把 `AUTHORIZATION: basic ***` 寫進 `_temp/git-credentials-….config` 再 `includeIf` 掛上。結果 `task/T-900` 的 `ci.yml` 只有開 PR 時那次 `pull_request` run（`45180613771`），沒有 `event=push` 的 run。

### 1. `claude-run-task.yml` 必做變更

**（A）checkout** 加上 `persist-credentials: false`（其他 `with:` 維持現狀，例如 `fetch-depth: 0`）：

```yaml
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
          persist-credentials: false
```

**（B）保持不要傳 `github_token`。** `Run Claude Code` 步驟維持 `id: claude`，`with:` 不得新增 `github_token`。

**（C）在 `Run Claude Code` 之後、`Notify Grok chief of staff` 之前，依序加入以下三個步驟（文字需與下列等效；不要改 notify 步驟本身）。** artifact 必須用與 `ci.yml` 相同的 pin，不得改用未釘選的 `@v4` 或 `@v7`。

```yaml
      - name: Summarize permission denials
        if: always()
        env:
          LOG: ${{ steps.claude.outputs.execution_file }}
        run: |
          set -euo pipefail
          if [[ -z "${LOG:-}" || ! -f "$LOG" ]]; then
            echo "No execution_file; skip."
            exit 0
          fi
          DENIALS=$(jq '[.[] | select(.type=="result") | .permission_denials // []] | add // []' "$LOG")
          COUNT=$(jq 'length' <<<"$DENIALS")
          {
            echo "## Claude permission denials"
            echo "count: $COUNT"
            jq -r '.[]? | "- `\(.tool_name)`: \(.tool_input.command // "(no command field)")"' <<<"$DENIALS"
          } | tee -a "$GITHUB_STEP_SUMMARY"
          if [[ "$COUNT" -gt 0 ]]; then
            echo "::warning::Claude had $COUNT permission denial(s). See job summary and artifact."
          fi

      - name: Upload Claude execution output
        if: always()
        uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
        with:
          name: claude-execution-output-${{ github.event.client_payload.task }}-${{ github.run_id }}
          path: ${{ steps.claude.outputs.execution_file }}
          if-no-files-found: warn
          retention-days: 7

      - name: Verify push triggered CI
        if: success()
        env:
          GH_TOKEN: ${{ github.token }}
          TASK: ${{ github.event.client_payload.task }}
        run: |
          set -euo pipefail
          BRANCH=$(git branch --show-current)
          if [[ ! "$BRANCH" =~ ^(task|fix)/ ]]; then
            BRANCH="task/${TASK}"
          fi
          git fetch origin "refs/heads/${BRANCH}:refs/remotes/origin/${BRANCH}" || true
          if ! git rev-parse --verify "origin/${BRANCH}" >/dev/null 2>&1; then
            echo "No origin/${BRANCH}; skip CI verify (Claude may not have pushed)."
            exit 0
          fi
          SHA=$(git rev-parse "origin/${BRANCH}")
          echo "Looking for ci.yml run event=push branch=${BRANCH} sha=${SHA}"
          for i in $(seq 1 12); do
            RUN_JSON=$(gh run list --workflow ci.yml --branch "${BRANCH}" --event push --limit 20 --json databaseId,headSha,event,status,conclusion,url,createdAt)
            MATCH=$(jq -c --arg sha "$SHA" '[.[] | select(.headSha==$sha)]' <<<"$RUN_JSON")
            if [[ $(jq 'length' <<<"$MATCH") -gt 0 ]]; then
              echo "$MATCH" | jq .
              echo "Found push-triggered CI run for ${SHA}"
              exit 0
            fi
            echo "Attempt ${i}/12: no matching push CI run yet, waiting 15s..."
            sleep 15
          done
          echo "ERROR: no event=push ci.yml run found for ${BRANCH} @ ${SHA} after ~180s"
          gh run list --workflow ci.yml --branch "${BRANCH}" --limit 10
          exit 1
```

Job summary 只准印被拒絕的 `tool_name` 與 `tool_input.command`（沒有 `command` 欄就印 `(no command field)`）。不要把完整 `tool_input` JSON 或 execution 檔內容倒進 log／summary。

`permissions:` 維持現狀（含 `actions: read`、`id-token: write`）；本單不改權限。`gh run list` 用內建的 `GITHUB_TOKEN` 即可，不要另設密鑰。

### 2. 新增 `docs/RUNBOOK.md`

簡短、繁體中文（臺灣）、指令與檔名用 English。第一次出現的技術名詞用一句話解釋。至少包含「模式 C 疑難排解」一節，內容必須寫到：

1. **為什麼用 `GITHUB_TOKEN` 推送不會觸發 CI**：GitHub 為避免 workflow 無窮迴圈，用此 token 的 `push`（以及多數其他事件）不會開新的 run；所以 T-900 只有開 PR 時才跑到 `ci.yml`。
2. **`persist-credentials` 修正（方案 A'）**：checkout 設 `persist-credentials: false`，避免 `GITHUB_TOKEN` 的 `Authorization` header 蓋掉 Claude GitHub App token。`claude-code-action` **不要**傳 `github_token`。合併後，Claude 推 `task/*` 或 `fix/*` 應出現 `event=push` 的 `ci.yml` run，head SHA 與分支先端相同；若當時已有 PR，也應出現 `pull_request` synchronize。
3. **在哪裡看權限拒絕與 artifact**：run 頁的 job summary 看 `tool_name` + command；同一 run 下載 artifact `claude-execution-output-<任務編號>-<run_id>`（保留 7 天）。檔內可能有倉庫內容或被回顯的敏感字串；有 repo 讀取權限的人都能下載。
4. **方案 A（另建 GitHub App 或 fine-grained PAT 並設 repo secret）必須先問幕僚長**，任何人不得自行新增密鑰。這是 A' 若經驗證仍無法觸發 push CI 時的備案，不是本單要做的事。
5. 也寫明：`workflow_dispatch` 或把 CI 接在同一個 `repository_dispatch` run 裡，官方文件說其檢查**不會**出現在 PR 上，故不採用。

開頭加版本與日期（v0.1，2026-11-23），註明擁有者是 SRE。不要寫密碼、Token、API Key 的值。
