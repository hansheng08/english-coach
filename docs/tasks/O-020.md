## 操作步驟（約 8 大步、25～35 分鐘；不含等信、不含付款畫面停下後的等待、不含等第一條 `design/*` 分支）
選單名稱以官方文件為準；若畫面不同，對照該步來源連結。找不到就停下回報。不要建自訂網域（custom domain）。

### 步驟 1：開免費帳號（已有就跳過，約 5 分）
到 [Cloudflare 註冊頁](https://dash.cloudflare.com/sign-up) 用自己的 email 註冊並完成驗證。官方建議開啟兩步驟驗證（2FA）。來源：[Zero Trust Get started](https://developers.cloudflare.com/cloudflare-one/setup/)、計畫 §4 A。

### 步驟 2：用 Git 連這個倉庫（約 8 分）
1. Dashboard → Workers & Pages → Create application → Pages → Connect to Git，選 GitHub 並登入。來源：[Git integration guide](https://developers.cloudflare.com/pages/get-started/git-integration/)。
2. 安裝「Cloudflare Workers & Pages」GitHub App 時，儲存庫權限選 **Only select repositories**，只勾 `hansheng08/english-coach`，再 Install & Authorize。不可選 All repositories。之後可在 [GitHub Installed GitHub Apps](https://github.com/settings/installations) 再確認。來源：[GitHub integration（Manage access）](https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/)。
3. 選 `hansheng08/english-coach` → Begin setup。

### 步驟 3：填建置設定並第一次部署（約 3 分）
在 Set up builds and deployments 填「介面」表的值，選 Save and Deploy。來源：[Git integration guide（Configure your build settings）](https://developers.cloudflare.com/pages/get-started/git-integration/)、[Build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/)（無框架時 Build command 留白）。若第一次部署因缺少 `docs/design/prototype` 失敗，繼續下一步，不要新增檔案。若因其他原因失敗，停下回報（見「不確定」關於 `exit 0`）。

### 步驟 4：預覽只限 `design/*`（約 3 分）
專案 → Settings → Builds & deployments（有的文件寫 Settings → Builds）→ Branch control。正式分支保持 `main`，自動正式部署保持開啟。Preview branch 選 Custom branches：Include 填 `design/*`，Exclude 留空，存檔。來源：[Branch deployment controls](https://developers.cloudflare.com/pages/configuration/branch-build-controls/)、[GitHub integration（Custom branches）](https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/)。

### 步驟 5：為預覽網址開 Access，並處理 Zero Trust 方案（約 5 分，可能在此停下）
專案 → Settings → General → Enable access policy。來源：[Preview deployments（Customize preview deployments access）](https://developers.cloudflare.com/pages/configuration/preview-deployments/)。官方註明：這一步**只保護預覽網址**（例如 `373f31e2.english-coach-proto.pages.dev`），還不保護正式的 `english-coach-proto.pages.dev`。

若此時要建立 Zero Trust 組織：填 team name（內部識別名稱），方案選 **Free**。官方寫：「Complete your onboarding by selecting a subscription plan and entering your payment details. If you chose the Zero Trust Free plan, this step is still needed but you will not be charged。」來源：[Get started §2](https://developers.cloudflare.com/cloudflare-one/setup/)。**本單仍要求：若出現付款或信用卡畫面，立即停下告訴幕僚長，不要填。** 我們沒有實際點過這個畫面；是否現在就要填卡，由 Hansheng 決定。

### 步驟 6：把正式網址一併保護，並把政策改成只允許本人＋一次性 PIN（約 10 分）
依 [Known issues：Enable Access on your `*.pages.dev` domain](https://developers.cloudflare.com/pages/platform/known-issues/)：
1. 在步驟 5 產生的 Access 政策旁點 Manage。
2. Access → Applications 選這個專案 → Configure。
3. Public hostname 的 Subdomain 欄刪掉 `*`，Save（若報錯，先改 Application name 再存）。此時正式網址已在門禁後。
4. 回到專案 Settings → General，再點一次 Enable access policy，讓預覽網址重新受保護。
5. 確認有兩條：一條給 `english-coach-proto.pages.dev`，一條給 `*.english-coach-proto.pages.dev`。本單不設自訂網域，故不必做該節步驟 10～13。

接著收緊「誰能進來」並啟用一次性 PIN（新組織預設是 Cloudflare 帳號登入，**不會自動**加上 PIN）：
1. Zero Trust → Integrations → Identity providers → Add new identity provider → 選 One-time PIN。來源：[One-time PIN login](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/one-time-pin/)。
2. 打開上述兩個 Access application，確認都啟用 One-time PIN。把政策改成（兩個都要改）：Action = Allow；Include 的 Selector = **Emails**、值 = 只有 `<Hansheng 的 email>`；可再加 Require、Selector = Login Methods、值 = One-time PIN（強迫用驗證碼，而不是只靠 Cloudflare 帳號）。來源：[Access policies（selector Emails）](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/)、[Common policies](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/common-policies/)。
3. 刪掉或改掉會放行太多人的規則。官方警告不可出現：Include + Everyone；或 Include + Login Methods = One-time PIN（沒有限制 email 的話，任何能收到碼的人都可能符合）。也不要用 Emails ending in 放行整個網域，不要留 Cloudflare Account Member 給整個帳號。不要新增 Bypass。
4. 信件若沒送到，寄件者是 `noreply@notify.cloudflare.com`（網域 `notify.cloudflare.com`）。被拒絕的 email **不會**寄碼，但登入頁仍可能顯示「A code has been emailed to you」。

### 步驟 7：無痕分頁驗收（約 5～10 分）
在 Android Chrome 與電腦 Chrome 各開無痕分頁，分別打開正式網址 `https://english-coach-proto.pages.dev` 與一條預覽網址（Pages 專案裡任一 `design/*` 部署；分支別名會把 `/` 換成 `-`，例如 `design/brief` → `design-brief.english-coach-proto.pages.dev`）。來源：[Preview deployments（Preview aliases）](https://developers.cloudflare.com/pages/configuration/preview-deployments/)。

預期：先出現 Access 登入頁，不能直接看到內容。用 `<Hansheng 的 email>` 選一次性 PIN、到信箱取碼（10 分鐘內、用過即失效）後才能進入。用另一個自己的 email：不應進入；通常不會收到碼。若正式部署因目錄不存在而還沒有網址，先驗預覽；若連預覽都還沒有（尚無 `design/*` 成功部署），完成步驟 1～6 後回報「等第一條 design/*」，不要自己加檔案。

### 步驟 8：核對 g3-comment-guard（等第一個相關 PR；不改 workflow）
Cloudflare 連上 Git 後，可能在 PR 留下預覽連結，或在 commit 旁顯示 check run（GitHub 的檢查結果）。來源：[Git integration](https://developers.cloudflare.com/pages/configuration/git-integration/)（「Preview URLs in pull requests」「status checks」）、[GitHub integration（Check runs、Preview URLs）](https://developers.cloudflare.com/pages/configuration/git-integration/github-integration/)。分支控制略過的建置，官方說 check run **不會**出現；是否仍留留言則未寫明。

`g3-comment-guard` 是只檢查標題以 `[G3]` 開頭的 PR 的留言自動檢查（commit status，不屬 `ci-ok`）。它會讀 issue 留言、review 內文與 review 行內留言，交給 `tooling/comment-lint.mjs`。只會在兩種開頭判紅：開頭為 `TechLead Review`（規則 `CM-TECHLEAD`）；或開頭為 `QA`，且同一則留言有一行同時提到本機重跑用語（本機／重跑／box／worktree／locally／rerun／re-run）與指令（`pnpm check`、`pnpm db:test`、`pg_prove`、`supabase test db`）（規則 `CM-QA-RERUN`）。**不讀 check run。** 標題不是 `[G3]`（例如 `[D2]`）時腳本直接結束、不寫 status。一般「預覽好了」留言預期不會命中，但本倉庫還沒實測過 Cloudflare 的作者名稱與正文開頭，故仍有誤判風險。

實測方法（誰開 PR 都可以，但不要改 `.github/**`）：
1. 第一個 `design/*` 的 PR（通常標題 `[D2]`）：記下是否有 Cloudflare 留言（作者、正文前兩行）或 check run。此類標題不會被 `g3-comment-guard` 檢查。
2. 下一個 `[G3]` PR（即使分支是 `task/*`、本專案因步驟 4 不會出預覽）：看 head 的 `g3-comment-guard` status 與 run 紀錄，以及有沒有 Cloudflare 留言。
3. 若 status 變紅：不要改 workflow。把 PR 編號、留言作者與連結、正文開頭、run 連結與規則代碼（若 log 有）回報幕僚長，另開 O 單再處理。
