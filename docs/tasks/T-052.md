## 目標
登入頁照 `screens/login.md` 補齊 7 種錯誤狀態的判定、位置、文案、焦點與清除規則；「預覽：假資料」條在淺色、深色與手機、電腦都照 pwa.md §3.4。

## 介面
```ts
// apps/web/src/features/login/validate.ts（新增）：前端檢查，只在按「登入」時呼叫；回傳各欄的訊息，沒問題是 null
export function validateLogin(email: string, password: string): { readonly email: string | null; readonly password: string | null };
```
- **前端檢查**（login.md #1～3）：Email 先去頭尾空白。空的 → 「請輸入 Email。」；不空但格式不對 → 「Email 格式不對，例如 name@example.com。」；密碼是空字串 → 「請輸入密碼。」（密碼不去空白）。兩欄都錯時兩則都出現。
- **Email 格式**（TechLead 決定）：去頭尾空白後，整串沒有空白字元；剛好一個 `@`；`@` 前面不是空的；`@` 後面至少有一個 `.`，而且 `@` 後面那段的開頭與結尾都不是 `.`。只做這個檢查，不查網域是否存在。
- **檢查順序**（login.md 規則）：欄位（#1～3）→ 離線（#5）→ 送出 → #4、#6。有欄位錯時不送出、不顯示表單訊息。
- **離線**（#5）：欄位都對、按「登入」時 `navigator.onLine` 為 false → 不送出，顯示表單訊息；送出後回來的錯不是 `unauthenticated`、而且此時 `navigator.onLine` 為 false → 也顯示 #5（不是 #6）。表單訊息：粗體「需要連網才能登入」＋「目前沒有網路。連上網路後再按一次「登入」。」；頁面頂端的「需要連網」條由外殼負責。
- **表單訊息**（#5、#6）：表單最上面、Email 欄之上；`bad-soft` 底＋1px `bad` 框＋圖示＋粗體標題＋一句說明；`role="alert"`；同時最多一則。#6 文案照現有（「現在登不進去」＋「登入服務沒有回應或暫時出錯。輸入的內容已保留，稍後再按一次「登入」。」）。
- **焦點**：前端檢查有欄位錯 → 焦點移到第一個錯的欄位（Email 在密碼之前）；顯示表單訊息（#5、#6）時焦點在「登入」按鈕（請求結束、按鈕恢復可按之後）。
- **清除與保留**：改了某一欄就清掉那一欄的訊息；再按「登入」時先清掉表單訊息；輸入的內容一律保留（密碼也不清空）。
- **預覽條**（pwa.md §3.4）：只在 mock 建置、每一頁最頂端（含登入頁）、在斷線條上面；`sunken` 底、下緣 1px 虛線 `ink-3`；燒杯圖示＋粗體「預覽：假資料」（`ink`、13px）＋「資料只在這個分頁，重新整理就回到初始狀態。」（`ink-2`、12px）；360 寬時說明換到第二行，電腦（≥900px）同一行；未知情境時說明換成「未知情境「<名稱>」，改用 default」（`bad` 色、純文字，長名稱自動換行）；不能關閉、沒有按鈕、`role="note"`。

## 驗收標準
- **AC-T52-1**（login.md #1～3、規則）`validateLogin` 照「介面」的前端檢查與 Email 格式；既有的空白檢查行為不變。
- **AC-T52-2**（login.md 欄位訊息、#3）Email 格式不對時：Email 欄下方 `bad` 字＋警告圖示、輸入框 2px `bad` 框、`aria-invalid="true"`、`aria-describedby` 連到訊息；不送出、沒有表單訊息；焦點在 Email 欄。
- **AC-T52-3**（login.md #5、NFR-06）按「登入」時離線：不送出；表單訊息文案與位置照「介面」；同時看得到頁面頂端的「需要連網」條；輸入保留；焦點在「登入」。恢復連線後再按一次就照常登入。
- **AC-T52-4**（login.md #5、#6）送出後失敗：`unauthenticated` → #4（不論是否離線）；其他錯且此時離線 → #5；其他錯且在線 → #6；表單訊息同時最多一則；顯示表單訊息後焦點在「登入」。
- **AC-T52-5**（login.md 規則、DESIGN §4）表單訊息與欄位訊息的顏色：淺色、深色都等於 `tokens.json` 的 `bad`／`bad-soft`；改欄位清掉該欄訊息、再按「登入」先清掉表單訊息。
- **AC-T52-6**（憲章 §15.8、NFR-01）360、412、768、1280、1440 下，Email 格式錯與離線兩種狀態都沒有橫向捲動；表單訊息在 Email 欄之上、左右不超出表單；360 下輸入框高 52、「登入」≥48×48。（由 PR e2e 驗證）
- **AC-T52-7**（pwa.md §3.4、DESIGN §4）預覽條在淺色、深色下的底色、虛線下緣、標題與說明的字級與顏色照「介面」；`role="note"`、裡面沒有按鈕；在 `/login` 也在斷線條上面。（由 PR e2e 驗證）
- **AC-T52-8**（pwa.md §3.4、NFR-01）預覽條在 360 時說明在標題下一行，1280 時同一行；未知情境的長名稱在 360 不造成橫向捲動，文字是 `bad` 色。（由 PR e2e 驗證）

## 測試的寫法
- 顏色比對一律不分大小寫：把實際值與期望值換成同一種寫法（例如都換成 `rgb(…)` 或都轉成小寫）再比。
- 量位置、大小前，先等該元素與其祖先上所有動畫的 `finished` 都完成，或用 `reducedMotion: 'reduce'`；不在動畫中途量。
- 不用 `waitForTimeout` 或任何固定等待；只用 Playwright 的 web-first 斷言或等到可觀察的條件成立；不設 `retries`、不加 `test.slow`／`test.fixme`。
- 元件測試的離線用 `navigator.onLine` 的 spy，結束後還原；E2E 用 `context.setOffline`。
- 每個 E2E 檔裡的測試名稱都帶本單的 AC／TC 編號（強制規則 11）。
