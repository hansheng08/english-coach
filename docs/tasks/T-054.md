## 目標
原始碼的 `VITE_` 檢查從「擋含 KEY／SECRET／TOKEN 的名稱」改成「只允許三個名稱」，並多掃三個會帶入建置變數的檔案。

## 介面
```ts
// apps/web/src/project-rules.test.ts 內（不匯出）
const ALLOWED_VITE_NAMES = ['VITE_DATA_MODE', 'VITE_SUPABASE_URL', 'VITE_SUPABASE_PUBLISHABLE_KEY'] as const;
/** text 裡每一個 VITE_ 名稱中不在 ALLOWED_VITE_NAMES 的，依出現順序、不去重。 */
function viteNamesOutsideAllowList(text: string): string[];
```
- **名稱的定義**：前面不是英數字或底線的 `VITE_`，後面接大寫英文、數字、底線，而且最後一個字元是大寫英文或數字。所以 `VITE_SUPABASE_`、`VITE_SUPABASE_*`、單獨的 `VITE_` 都是前綴說明、不算名稱；`%VITE_FOO%`（HTML 裡的寫法）算名稱 `VITE_FOO`。
- **掃描範圍**：原本的四類照舊，加上 `apps/web/index.html`、`apps/web/vite.pwa.ts`、根目錄的 `playwright.config.ts`。新加的三個檔一律用 `node:fs` 的 `readFileSync(new URL(…, import.meta.url), 'utf8')` 讀（和 `.env.example` 同一個寫法；HTML 不經過 Vite 的 `?raw`），每個讀到的內容都要非空。
- **白名單只寫在一個地方（TechLead 決定）**：`ALLOWED_VITE_NAMES` 只定義在 `project-rules.test.ts`，另外兩個列出名稱的檔案用測試綁住，不另寫第二份清單：
  - `src/vite-env.d.ts` 裡出現的 `VITE_` 名稱集合，必須剛好等於白名單；
  - `.env.example` 中以 `VITE_…=` 開頭的行，名稱集合必須剛好等於白名單。
  - 理由：沒有正式程式需要這份清單，匯出成正式程式只會多一個沒人用的常數；唯一共用的規則檔 `tooling/data-mode-guard.mjs` 屬 `tooling/`，要它匯出清單就得把 `tooling/` 拉進範圍（不做）；`vite-env.d.ts` 是型別宣告，不能從常數產生。用測試綁住後，任一處多一個或少一個名稱都會失敗。
- **既有測試**：`(AC-T18-2) (TC-5)` 那一個 `it` 是本單唯一可以改的既有測試：名稱保留 `(AC-T18-2) (TC-5)`，再加本單的 AC／TC 編號；`badViteNames` 換成 `viteNamesOutsideAllowList`，舊的三個反例斷言改成 TC-2 的斷言。同檔其他 `it` 不改。
