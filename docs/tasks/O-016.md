## 背景（開始前先讀）
- `CLAUDE.md` §2、§3；`docs/RUNBOOK.md` §6.3（O-015 的 `ci-guard`、三種模式）。
- 用量只能從 Actions 的 runs／jobs API 推算：box 的權杖讀 check-runs、billing API 都回 403。GitHub 對每個 job 各自進位到整分鐘計費，所以估計值＝每個 job ⌈(completed_at − started_at) ÷ 60 秒⌉ 加總（Linux runner 倍率 1）。O-015 的分析也用這個算法。
- API 形狀（只放規則用到的欄位）：
  - `GET repos/<owner>/<repo>/actions/runs?created=<YYYY-MM-DD>&per_page=100&page=<n>` → `{ total_count, workflow_runs: [{ id, name, run_attempt, status, created_at }] }`。`created` 篩選最多只回 1,000 筆。
  - `GET repos/<owner>/<repo>/actions/runs/<id>/jobs?filter=all&per_page=100&page=<n>` → `{ total_count, jobs: [{ id, run_id, run_attempt, name, status, started_at, completed_at, labels }] }`。`filter=all` 含重跑的每一次（重跑也計費）。
- `.github/pull_request_template.md` 會新增一節 `## Actions 分鐘數影響`，預設內容是一行佔位文字（SRE 加）：`（改到 .github/workflows/** 時必填：預估每月增減的分鐘數與算法，或「無影響：理由」）`。

## 目標
1. `tooling/actions-usage.mjs`：以既有權杖從 runs／jobs API 推算某一天與本計費週期的計費分鐘，依門檻給出 `ok`／`warn`／`stop`，輸出單一 JSON；任何 API 或資料問題一律失敗、不輸出部分 JSON。routine 由幕僚長建立。

## 介面
```ts
// tooling/actions-usage.mjs（只用 node: 內建模組；以子行程呼叫 gh，執行檔可由環境變數 GH_BIN 覆寫）
export function billedMinutes(job: unknown): { minutes: number; rawSeconds: number } | { error: string };
export function summarize(input: unknown): object | { error: string };  // input：runs、jobs、date、tzOffset、cycleStart、thresholds、included
export function run(argv: string[]): { code: number; stdout: string; stderr: string };
// tooling/pr-body-lint.mjs（只用 node: 內建模組）
export function workflowsChanged(files: unknown): boolean;
export function lintPrBody(body: unknown, files: unknown): { ok: boolean; rule: string | null; message: string };
export function run(argv: string[]): { code: number; stdout: string; stderr: string };
```
CLI：
- `node tooling/actions-usage.mjs --repo <owner/name> --date <YYYY-MM-DD> --included <分鐘> [--cycle-start <YYYY-MM-DD>] [--tz-offset <±HH:MM>] [--daily-warn <分>] [--daily-stop <分>] [--month-warn-pct <%>] [--month-stop-pct <%>]`。預設：`--cycle-start` ＝ `--date` 所在月份 1 日、`--tz-offset +08:00`、`--daily-warn 100`、`--daily-stop 200`、`--month-warn-pct 75`、`--month-stop-pct 90`。`--included` 必填（免費 2000、Pro 3000，不猜）。
- `node tooling/pr-body-lint.mjs --body <檔案> --changed <檔案>`（`--changed` 一行一個路徑）。成功 stdout `pr-body-lint: OK …`，exit 0；失敗 stderr `pr-body-lint: FAIL <RULE> …`，exit 1。

### actions-usage 規則
- 「某一天」＝`--tz-offset` 時區的 00:00～24:00；job 以 `started_at` 歸日。週期＝`--cycle-start` 00:00 到 `--date` 24:00（同一時區）。
- 取資料：週期內每一天各查一次 runs（`created=<該日>`，UTC 日期；頭尾各多查一天以涵蓋時區差），逐頁到收齊為止；任何一天 `total_count` > 1000 或收到的筆數 ≠ `total_count` → 失敗。每個 run 再逐頁查 jobs，收到的筆數 ≠ `total_count` → 失敗。
- `billedMinutes`：`status === "completed"` 且 `started_at`、`completed_at` 都是合法 ISO 時間且後者 ≥ 前者 → `minutes = ceil(秒數 ÷ 60)`（0 秒算 0 分，被略過的 job 是 0）。`labels` 必須含 `ubuntu-` 開頭的標籤；其他（windows、macos、self-hosted、缺漏）→ `error`（倍率未知，不猜）。`status` 不是 completed → 不計入，另計 `in_progress_jobs`。
- 輸出（單行 JSON，`schema: "actions-usage/v1"`）：
  - `repo`、`date`、`tz_offset`、`cycle_start`、`method: "sum of ceil(job seconds / 60) from actions runs/jobs API (estimate)"`
  - `day`：`{ billed_minutes, raw_minutes, runs, jobs, in_progress_jobs, by_workflow: [{ workflow, runs, jobs, billed_minutes, raw_minutes }] }`，`by_workflow` 依 `billed_minutes` 由大到小、同分依名稱排序；`raw_minutes` 四捨五入到小數 1 位。
  - `cycle`：`{ billed_minutes, days_elapsed, daily_average, by_workflow: [...同上] }`；`daily_average` ＝ `billed_minutes ÷ days_elapsed`，小數 1 位。
  - `allowance`：`{ included_minutes, used_minutes, remaining_minutes, used_pct, days_of_allowance_left, projected_cycle_minutes }`；`remaining_minutes` 可為負；`days_of_allowance_left` ＝ `remaining ÷ daily_average`（平均為 0 時為 null；remaining ≤ 0 時為 0），小數 1 位；`projected_cycle_minutes` ＝ `daily_average × 該月天數`，取整數。
  - `thresholds`：實際用到的 4 個門檻。
  - `status`：`stop`（`day.billed_minutes ≥ daily_stop` 或 `used_pct ≥ month_stop_pct` 或 `remaining_minutes ≤ 0`）＞`warn`（`≥ daily_warn` 或 `used_pct ≥ month_warn_pct` 或 `projected_cycle_minutes > included_minutes`）＞`ok`；`reasons`：觸發的條件代碼陣列（`daily-stop`、`month-stop`、`exhausted`、`daily-warn`、`month-warn`、`projected-over`），`ok` 時為空陣列。
- 失敗（exit 1，stdout 必須是空的）：`gh` 非 0、輸出不是 JSON、欄位缺漏或型別不對、筆數對不上、`billedMinutes` 有 error、`--date` 早於 `--cycle-start`、日期或時區格式錯 → `usage: <RULE> …` 寫到 stderr；規則代碼 `API`、`DATA`、`COUNT`、`RUNNER`、`USAGE`。

### pr-body-lint 規則
- `workflowsChanged`：任一路徑以 `.github/workflows/` 開頭 → true；`files` 不是字串陣列 → 拋不出例外，由 `lintPrBody` 回 `INPUT`。
- `lintPrBody`：沒有改到 workflow → `ok: true`（`rule: null`）。改到時，找標題恰為 `## Actions 分鐘數影響` 的一節（到下一個 `## ` 或結尾）：
  - 找不到這一節 → `PB-MISSING`。
  - 本節內容去掉 HTML 註解、去掉與佔位文字完全相同的行、去掉空行與只有 `-`、`*`、`無`、`N/A`、`TBD`、`待補` 的行後，什麼都不剩 → 原本有佔位行時為 `PB-PLACEHOLDER`，否則 `PB-EMPTY`（佔位行旁邊另有填寫的內容時，只看填寫的內容）。
  - 剩下的內容必須至少有一行含「數字＋分鐘」（例如 `-120 分鐘／月`、`約 600 分鐘`），或以 `無影響：` 開頭且冒號後有文字 → 否則 `PB-VAGUE`。
  - `body` 不是字串（例如 PR 說明為 null）而改到 workflow → `PB-MISSING`。`files` 型別不對 → `INPUT`。
- CLI：檔案讀不到 → `INPUT` exit 1；選項缺漏或重複 → `USAGE` exit 1。

## 驗收標準
- **AC-O16-1** 計費進位：61 秒 → 2 分、60 秒 → 1 分、1 秒 → 1 分、0 秒 → 0 分；completed_at 早於 started_at、時間不合法、非 ubuntu label → error；未完成的 job 不計入而算進 `in_progress_jobs`。
- **AC-O16-2** 歸日與彙總：`+08:00` 下 UTC 15:59:59 開始的 job 歸前一天、16:00:00 歸當天；重跑（同 run 不同 `run_attempt`）的 job 都計入；`by_workflow` 排序、`raw_minutes`、`cycle`、`allowance` 各欄依規則算出（以 fixture 寫死預期 JSON）。
- **AC-O16-3** 門檻：6 種 reason 各至少一例；`stop` 優先於 `warn`；預設門檻與自訂門檻都生效。
- **AC-O16-4** fail-closed：以假 `gh`（`GH_BIN`）實際跑 CLI 子行程：`gh` exit 1、壞 JSON、少一頁（筆數 ≠ total_count）、`total_count` 1001、job 缺 `labels`、windows label、`--date` 早於 `--cycle-start`、缺 `--included` → 各 exit 1 且 stdout 為空；正常 fixture → exit 0 且 stdout 恰為一行可解析的 JSON。
- **AC-O16-5** PR 說明檢查：改到 `.github/workflows/ci.yml` 時，缺節 → `PB-MISSING`；佔位文字原樣 → `PB-PLACEHOLDER`；只有 `-` 或 `無` → `PB-EMPTY`；「會變少」（沒有數字）→ `PB-VAGUE`；`-120 分鐘／月：算法…` 或 `無影響：只改註解` → ok；body 為 null → `PB-MISSING`；沒改 workflow（只改 `.github/scripts/x.sh` 或 `docs/a.md`）時任何 body 都 ok。
- **AC-O16-6** CLI 與依賴：兩支 CLI 以子行程斷言 exit code、stdout、stderr 規則代碼；新增原始碼只 import `node:` 與 `./`；不含 `|| true`、`continue-on-error`、吞掉錯誤後 exit 0 的 `catch`；不新增套件、不改 `pnpm-lock.yaml`；不新增 QA 擁有檔樣式的檔案。
