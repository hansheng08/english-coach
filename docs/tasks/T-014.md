## 目標
新增後端的供應商 registry：依使用者設定**只回傳被選中的那一個**供應商，付費供應商只能帶著 `PaidConsent` 取得，沒有備援清單也沒有「下一個」；新增唯一讀付費金鑰的 `config/paid.ts`；提供全部是免費供應商的 `DEFAULT_SETTINGS`；並寫出 ADR-003「測試」節前 5 項的測試（PRD AC-24、AC-25、NFR-03）。

## 介面
`supabase/functions/_shared/providers/registry.ts`（型別從 `@english-coach/contracts` import；`EnvGetter` 從 `../config/env.ts`）：
```ts
export type AnyProvider = LlmProvider | SttProvider | PronunciationProvider | TtsProvider;
export type ProviderFor<C extends Capability> = Extract<AnyProvider, { readonly capability: C }>;
export type ProviderSettings = {
  readonly llm: { readonly provider: ProviderId; readonly model: LlmModelId };
  readonly stt: { readonly provider: ProviderId; readonly model: SttModelId };
  readonly pronunciation: { readonly provider: ProviderId };
  readonly tts: { readonly provider: ProviderId };
  readonly paid_consent_at: string | null;
  readonly monthly_paid_cap_ntd: Ntd | null;
};
export type PaidRefusal = { readonly reason: 'no_consent' | 'monthly_cap_reached' };
export const PROVIDER_TIERS: Readonly<Record<ProviderId, Tier>>;
export const DEFAULT_SETTINGS: ProviderSettings;
```
```ts
export interface Registry {
  resolve<C extends Capability>(capability: C, settings: ProviderSettings, usedThisMonthNtd: Ntd): Result<ProviderFor<C>, ProviderError>;
  resolvePaid<C extends Capability>(capability: C, settings: ProviderSettings, consent: PaidConsent): Result<ProviderFor<C>, ProviderError>;
}
export function createRegistry(deps: { readonly providers: readonly AnyProvider[]; readonly env: EnvGetter }): Registry;
export function grantPaidConsent(settings: ProviderSettings, usedThisMonthNtd: Ntd): Result<PaidConsent, PaidRefusal>;
```
`supabase/functions/_shared/config/paid.ts`：
```ts
export function loadGeminiPaidKey(get: EnvGetter): Result<string, ProviderError>;
```

行為（依 ADR-003 與 ARCHITECTURE；標「TechLead 決定」的是 ARCHITECTURE 沒有寫死、本單決定的細節）：
- `resolve`：取 `settings[capability].provider`，在 `deps.providers` 找 `id` 與 `capability` 都相同的那一個。找不到 → `not_configured`（`provider`＝選中的 id、`capability`＝參數）。**不**找其他供應商、**不**呼叫 adapter 的任何方法。
- 付費判定（TechLead 決定，偏向安全）：`PROVIDER_TIERS[id] === 'paid'` **或** 找到的 adapter `tier === 'paid'`，就算付費。付費時 `resolve` 先 `grantPaidConsent`：拒絕 → `paid_not_allowed`（`reason` 照拒絕原因）；同意 → 交給 `resolvePaid`。付費供應商只能經 `resolvePaid` 取得（ADR-003 第 2 層）。
- `PROVIDER_TIERS`（TechLead 決定）：`ids.ts` 的 `PROVIDER_IDS` 中以 `-paid` 結尾的是 `paid`，其餘是 `free`（`ids.ts` 註解：付費版是不同的 id）。
- `grantPaidConsent`：`paid_consent_at` 為 `null` 或空字串、或 `monthly_paid_cap_ntd` 為 `null` → `no_consent`；`usedThisMonthNtd >= monthly_paid_cap_ntd` → `monthly_cap_reached`；否則回 `PaidConsent`（`grantedAt`、`monthlyCapNtd`、`usedThisMonthNtd`）。本月用量怎麼算不在本單，由呼叫端傳入（TechLead 決定）。
- `resolvePaid`：選中的是 `gemini-paid` 時，經 `loadGeminiPaidKey(deps.env)` 確認金鑰存在，缺少 → `not_configured`；`azure-speech-paid` 在 ARCHITECTURE §7.1 沒有金鑰名稱，一律 `not_configured`（MVP 不提供；TechLead 決定）；之後與 `resolve` 相同方式找 adapter。
- 重試（TechLead 決定，對齊 ADR-003「次數 ≤ 2」與 ARCHITECTURE §15「只呼叫一次」）：registry **不重試**；`invalid_response` 的同模型重試 1 次由各 adapter 自己做（ARCHITECTURE §5.2，T-015～T-017）。
- `DEFAULT_SETTINGS`（ARCHITECTURE §5.3 預設欄）：LLM `gemini`／`gemini-3.5-flash-lite`；STT `groq`／`whisper-large-v3-turbo`；發音 `azure-speech`；TTS `azure-speech`（備料時預產生；瀏覽器即時 Web Speech 不經後端）；`paid_consent_at`、`monthly_paid_cap_ntd` 都是 `null`。放在 `registry.ts`（TechLead 決定；`SettingsSchema` 與 jsonb 驗證是 T-020）。
- `loadGeminiPaidKey`：只讀 `GEMINI_PAID_API_KEY`；未設定或空字串 → `not_configured`（`provider: 'gemini-paid'`、`capability: 'llm'`），`message` 只含變數名稱、不含任何值；有值 → `ok`。只用注入的 `EnvGetter`，不直接碰 `Deno.env`。

## 驗收標準
- **AC-T14-1**（AC-24、NFR-03）`resolve` 只回傳設定中被選中的那一個供應商，回傳型別依 `capability` 縮小；改了設定後下一次呼叫就回新的供應商（registry 不快取）；選中的供應商沒有註冊、或註冊的能力不同 → `not_configured`，不回其他供應商。
- **AC-T14-2**（AC-25）沒有備援：對 `ProviderErrorKind` 的每一種，選中的假 adapter 回該錯誤後，再次 `resolve` 仍回同一個供應商；選中的 adapter 呼叫次數為 1（≤ 2，ADR-003），其他 adapter 呼叫次數為 0；`resolve` 本身不呼叫 adapter。
- **AC-T14-3**（AC-25）`DEFAULT_SETTINGS` 每一項的供應商在 `PROVIDER_TIERS` 都是 `free`，值與 ARCHITECTURE §5.3 預設欄相同，付費同意兩欄為 `null`；`PROVIDER_TIERS` 對每個 `PROVIDER_IDS` 都有值。
- **AC-T14-4**（AC-25）付費同意：沒有 `paid_consent_at`、沒有月上限、或本月用量 ≥ 上限時，選付費供應商回 `paid_not_allowed`（`reason` 分別為 `no_consent`／`no_consent`／`monthly_cap_reached`），付費 adapter 呼叫次數為 0；id 不是 `-paid` 但 adapter 宣告 `tier: 'paid'` 也一樣被擋。
- **AC-T14-5**（AC-25）有同意且用量 < 上限、`GEMINI_PAID_API_KEY` 有值時，選 `gemini-paid` 會回該付費 adapter；金鑰缺少 → `not_configured`；選 `azure-speech-paid` → `not_configured`。
- **AC-T14-6**（AC-25）型別：不帶 `PaidConsent`（省略或傳一般物件）呼叫 `resolvePaid` 編譯失敗（`// @ts-expect-error`）；`grantPaidConsent` 成功值的型別是 `PaidConsent`；`resolve('stt', …)` 成功值的型別是 `SttProvider`（`expectTypeOf`）。
- **AC-T14-7**（NFR-05、ADR-003 第 1 層）`loadGeminiPaidKey` 只讀 `GEMINI_PAID_API_KEY`：未設定、空字串 → `not_configured` 且訊息含變數名稱、不含值；有值 → `ok`；不讀其他名稱。
- **AC-T14-8**（AC-25、ADR-008 #6）在真實程式樹中，只有 `supabase/functions/_shared/providers/registry.ts` import `supabase/functions/_shared/config/paid.ts`（registry 確實 import 它）；`pnpm arch` 0 違規。
