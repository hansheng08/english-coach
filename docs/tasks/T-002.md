## 實作限制

### A. dependency-cruiser（`.dependency-cruiser.cjs`）
測試檔 regex：`TEST = '(^|/)test/|\\.test(-d)?\\.ts$'`（在設定檔裡定義一次，各規則共用）。
| 規則 | 內容 |
|---|---|
| `adr008-01-domain-imports-contracts-only` | `from`：`^packages/domain/` 且**不是**測試檔；`to`：不是 `^packages/(domain\|contracts)/` → 違規 |
| `adr008-01t-domain-tests-imports` | `from`：`^packages/domain/` 的測試檔；`to`：不是 `^packages/(domain\|contracts)/`、也不是 `vitest`（含 `@vitest/*`；解析後在 `node_modules/` 裡或無法解析時的裸名稱都要涵蓋）→ 違規 |
| `adr008-02-contracts-imports-zod-only` | `from`：`^packages/contracts/` 且不是測試檔；`to`：不是 `^packages/contracts/`、也不是 `zod` → 違規 |
| `adr008-02t-contracts-tests-imports` | `from`：`^packages/contracts/` 的測試檔；`to`：不是 `^packages/contracts/`、也不是 `vitest`／`@vitest/*` → 違規 |
| `adr008-03-features-isolated` | 不變 |
| `adr008-04-supabase-only-in-api-and-db` | `from`：不是 `^(apps/web/src/api\|supabase/functions/_shared/db)/`；`to`：`^(npm:\|jsr:)?@supabase/` 或 `node_modules/@supabase/` → 違規（取代舊的 `adr008-04-supabase-js-only-in-api`） |
| `adr008-05-endpoints-via-registry` | 不變 |
| `adr008-06-paid-config-only-registry` | 不變 |
| `adr008-10-no-circular` | 不變 |
| `adr008-11-no-test-code-in-production` | `from`：不是測試檔；`to`：是測試檔 → 違規 |
- 規則路徑不得為了讓測試通過而放寬；做不到就停下寫報告。
- `npm:`／`jsr:`／網址寫法在 Node 端無法解析，dependency-cruiser 會以原字串出現；請在報告貼出範例實際被記成什麼 `to` 值。

### B. ESLint（`eslint.config.js`）
- 所有 `files: ['**/*.ts']` 改成 `['**/*.{ts,tsx}']`（或等效寫法）；`packages/domain/**`、`_shared/**` 的路徑規則同樣涵蓋 `.tsx`。
- 新增（全 repo 的 `.ts`／`.tsx`）`no-restricted-imports`：禁止 `http:`、`https:`、`npm:`、`jsr:` 開頭的 import（ADR-008 修訂 1 決定 1）。訊息寫明 `ADR-008 #4`。
- `ThrowStatement` 禁令（訊息寫 `ADR-008 #9`）套用在：`packages/domain/**` 與 `supabase/functions/_shared/{providers,db,news}/**` 的**正式程式**。測試程式（`**/*.test.ts`、`**/*.test-d.ts`、`**/test/**`）不套用。

- `no-restricted-syntax` 在重疊路徑會互相覆蓋：請維持「每個路徑只落在一個區塊」的寫法，並用測試證明每個區塊的每個選擇器都還有效（驗證方式第 2 節）。

### C. `packages/contracts`

### D. 測試與範例
