## 目標
晚上任何一步（上傳、轉逐字稿、診斷、chunk 命中）失敗時，畫面顯示原因、供應商與什麼時候可以重送，錄音留在這台裝置；使用者可以稍後重送給同一個供應商，或手動到設定頁改用其他供應商後再送。不會自動改用其他或付費供應商。

## 介面
§4.16.3 的條件、步驟表、失敗時的寫法照 ARCHITECTURE；以下是 TechLead 補的決定：
```ts
// supabase/functions/api/retry.ts（新增）；RouteKey 加 'POST /retry/:answerId'
export const postRetry: Route;
// supabase/functions/_shared/evening/steps.ts（新增或擴充）：四步的實作，原端點與 /retry 共用
//   runSttStep、runDiagnoseStep、runChunksStep：(deps, ctx, answer) => Promise<Result<…, AppError>>
// apps/web/src/ui/retry-time.ts（新增；純函式，errors.md §3 的表）
export function retryTimeText(error: ApiErrorBody['error'], now: Date): string;
```
- **共用步驟**：T-037、T-038、T-041 的端點內如果把步驟寫在 route 檔裡，本單把它們搬到 `_shared/evening/steps.ts`、原端點改呼叫，行為不變（原測試照樣通過）；`/retry` 呼叫同一個函式，**不另寫一份**。`stt` 用**現在的** `settings.stt`、`diagnose` 用現在的 `settings.llm`。
- **`postRetry` 順序**：`answerId` 不是 uuid → 400 `validation`；讀 `evening_answer`（RLS 只讀得到本人的）→ 沒有 → 404 `not_found`（`entity: 'answer'`）；`status` 不是 `failed` 或 `retryable` 是 `false` → 409 `conflict`（`entity: 'answer'`）；`retryAfterSec` 還沒到 → 429，body 是原本的 `failure.error`、`retryAfterSec` 改成剩下的秒數（無條件進位）；都通過才依 `failure.step` 重做。重做失敗 → 整個 `failure` 換成新的（`step` 不變、`attempt + 1`）再回錯誤。
- **前端**：
  - 錯誤卡照 `errors.md` §1、§2（`ErrorCard` 已有就重用，沒有就照 §1 建）；原因文字讀 `ui/error-messages.ts`；右欄（電腦）「這次使用」用 `ProviderMeta` 與 `retryTimeText`；固定說明「不會自動改用其他供應商，也不會改用付費方案。」。
  - `rate_limited` 的「重送」按鈕倒數結束前 `disabled`、按鈕上顯示秒數；`quota_exhausted` 主按鈕「稍後重送」回今天。
  - `upload` 失敗：重送時先把 IndexedDB 的錄音重新上傳到同一個 `audio_path` 再呼叫 `/retry`；`stt` 成功後才刪 IndexedDB 的錄音（§6 第 3 點）。
  - 「到設定」：`quota_exhausted`、`auth`、`region_blocked`、`not_configured` → `/settings#providers`；`paid_not_allowed` → `/settings#paid`。
  - 首頁那一步的「待重送」`.tag`（見上）。
- `ApiClient` 加 `retryAnswer(answerId)`；照 T-021 的 `ApiClient` 工廠規則。

## 驗收標準
- **AC-T43-1**（§4.16.3 條件 1、2）不是本人的、`status` 不是 `failed`、`retryable` 是 `false`：404 或 409 `conflict`（`entity: 'answer'`）；都不呼叫任何供應商。
- **AC-T43-2**（§4.16.3 條件 3）`retryAfterSec` 還沒到：429，body 是原本的錯誤、`retryAfterSec` 是剩下的秒數（無條件進位）；不呼叫供應商。
- **AC-T43-3**（§4.16.3 步驟表）`stt`、`upload` 用現在的 `settings.stt` 重轉，成功後 `status = 'transcribed'`、`failure = null`、回 `{step:'stt', result}`；`diagnose` 用現在的 `settings.llm` 重做、`status = 'diagnosed'`；`chunks` 重算、`status = 'diagnosed'`；回應形狀照表。
- **AC-T43-4**（§4.16.3「失敗時」、「次數」）重做失敗時 `failure` 換成新的、`step` 不變、`attempt` 加 1；伺服器不設次數上限。
- **AC-T43-5**（ADR-003、§6 第 4 點）任何情況都不自動改用其他供應商或付費供應商：假 429 時付費 adapter 呼叫 0 次、其他供應商呼叫 0 次。
- **AC-T43-6**（§4.16.3、四步共用）原端點與 `/retry` 呼叫同一個步驟函式；T-037、T-038、T-041 的既有測試照樣通過。
- **AC-T43-7**（`errors.md` §1、§2、AC-25）錯誤卡：警告圖示＋標題（依步驟換字）＋原因（`role="alert"`）＋「保留」列（錄音已保存在這台裝置＋長度）＋按鈕列；主按鈕與次按鈕照 §2 的表；不顯示錯誤代碼、HTTP 狀態或英文訊息。
- **AC-T43-8**（`errors.md` §3、§5.9.3）重送時間照 §3 的表：有 `retryAfterSec` →「約 N 分鐘後可重送」（不到 1 分鐘寫秒）；Gemini 沒有 → 台北時間 16:00 或 15:00（太平洋時間下一個 0 點）；Groq →「明天再試」；Azure →「下個月再試」。
- **AC-T43-9**（AC-25、§6 第 3 點）重送流程：`rate_limited` 倒數結束前按鈕停用；`upload` 先重傳錄音到同一路徑；`stt` 成功後才刪 IndexedDB 的錄音；失敗時錄音仍在 IndexedDB。
- **AC-T43-10**（`errors.md` §2、`settings.md` §1）「到設定」依 kind 連 `/settings#providers` 或 `/settings#paid`；首頁那一步顯示「待重送」，點了回到同一張錯誤卡。
- **AC-T43-11**（DESIGN §2、`errors.md` §1；響應式）手機（< 900px）錯誤卡取代那一步的內容、按鈕上下排；電腦（≥ 900px）按鈕橫排、右欄 340px 放「這次使用」；360、412、768、1280、1440 都沒有橫向捲動；按鈕 ≥ 48×48。
- **AC-T43-12**（DESIGN §4、§10）淺深色只用 tokens；錯誤狀態用圖示＋文字，不只靠顏色；倒數按鈕的剩餘秒數對讀屏可讀；動態只在 `prefers-reduced-motion: no-preference` 下出現。
