## 目標
使用者隨時可以輸入單字、短句或中文意思產生字卡：3 秒內先看到 chunk 與中文並可播放發音，8 秒內補齊例句與同義替換，按「加入字卡」才成為 Collected 字卡；只收到一部分也可以先加入，缺的由 enrich 補。

## 介面
§5.8.4 的 prompt 要點、`parseCardStream` 的 4 條規則、contracts 兩處變更照 ARCHITECTURE；以下是 TechLead 補的決定：
```ts
// supabase/functions/_shared/ai/generate-card.ts（新增）
export const GENERATE_CARD_TIMEOUT_MS = 8000;   // §5.8.1 表；maxOutputTokens 512
export function parseCardStream(src: AsyncIterable<Result<StreamChunk, ProviderError>>): AsyncIterable<CardStreamEvent>;
// supabase/functions/api/cards-generate.ts（新增）；RouteKey 加 'POST /cards/generate'
export const postCardsGenerate: Route;   // 回 200、Content-Type: application/x-ndjson，一行一個 CardStreamEvent
// apps/web/src/api/client.ts：ApiClient 加
//   generateCard(input: string, signal: AbortSignal): AsyncIterable<CardStreamEvent>;   // 讀 NDJSON；網路錯誤轉成 error 事件
//   createCard(req: CreateCardRequest): Promise<Result<Card, AppError>>;  enrichCard(id: CardId): Promise<Result<Card, AppError>>;
//   listRecentManualCards(limit: 5): Promise<Result<readonly Card[], AppError>>;   // source_type = 'manual'，新的在前
```
- **伺服器**：body 照 §5.1.1 驗證（`{input}`，trim 後 1～200 字元，不合格回 400 `validation`、不開串流）→ `resolve('llm', …)`（`err` → 照 §5.0.4 回 JSON 錯誤、不開串流）→ `llm.stream({…, maxOutputTokens: 512, timeoutMs: 8000})` → `parseCardStream` 逐行送出。逾時以「從開始呼叫算 8 秒」為準，到時送 `error`（`timeout`）後結束。串流不重試、不寫資料庫；結束後寫一筆 `provider_call`。
- **contracts**：`CardStreamEvent` 的 `done` 改成 `{ type: 'done', meta: { llmModel } }`；`POST /cards` 的 `exampleEn?`、`synonyms?`（T-027 已加就不重做）。
- **前端**：
  - 路由 `/cards/new`（`RequireSession`）；入口：中午 rail 的「新增字卡」次要按鈕（T-033 的 rail）；首頁三個時段下方的「隨時可用」面板（main 上沒有就由本單建，只放「新增字卡」一項；「預覽今晚題目」由 T-039 加）。
  - 5 個狀態照 `noon.md` §3（輸入、產生中、補齊、沒有補齊、已加入）；連 chunk 都沒有 → 錯誤卡（`errors.md` §1、§2，文字讀 `ui/error-messages.ts`），輸入保留。`ui/ErrorCard.tsx` 在 main 上沒有就由本單照 `errors.md` §1 建，T-043 重用。
  - 「加入字卡」＝`createCard({chunk, meaningZh, exampleEn?, synonyms?, sourceType: 'manual'})`（`sourceSentence` 照 T-027 的 schema 對手動生卡的規定；schema 不允許空值時停下回報），成功後呼叫 `enrichCard` 但不等它（§4.17）；「重新產生」重新開串流。
  - **預取**（ADR-005）：`settings.cards.prefetch` 是 `true` 時，輸入停 600 ms 先呼叫；按「產生字卡」時輸入沒變就用預取的結果；同一個輸入只預取一次；輸入改變就 `abort` 上一個。
  - **發音鈕**：瀏覽器 `speechSynthesis`（ADR-005：Web Speech 只用在手動生卡），`lang` 為 `en-US`；瀏覽器沒有 `speechSynthesis` 時不顯示發音鈕。
- **測試工廠**：`RouteDeps` 不加欄位（用既有的 `providers`、`userDb`）；前端照 §9.1.7 的 `ApiClient` 工廠規則（組成根注入 `fetch` 與 token、畫面經 `useApi()`、測試用 `makeTestApiClient`）。

## 驗收標準
- **AC-T34-1**（§5.8.4 第 1、2 條）`parseCardStream` 把跨 chunk 的文字照換行切行；空行與不是 `{` 開頭的行略過；每行照 `CardStreamEventSchema` 與 K1、C3、E1（和第 1 行的 chunk 比）、S1 檢查，合格就馬上產生事件。
- **AC-T34-2**（§5.8.4 第 3、4 條）順序不對、重複、不合格 → `error`（`invalid_response`）後結束；3 行都到 → `done`（`meta.llmModel`）；來源結束但不到 3 行 → `error`（`invalid_response`）；來源回 `err` → `error`（那個 kind）。
- **AC-T34-3**（§5.1、§5.8.1）`POST /cards/generate`：`input` 不合格 400 `validation`；`resolve` 失敗照 §5.0.4 回 JSON；成功時 `Content-Type: application/x-ndjson`、`maxOutputTokens` 512；從開始算 8 秒到時送 `timeout` 並結束；不寫 `card`；寫一筆 `provider_call`。
- **AC-T34-4**（§5.8.4 contracts）`done` 沒有 `cardId`、有 `meta.llmModel`；`POST /cards` 收 `exampleEn`、`synonyms` 時照 E1、S1 檢查。
- **AC-T34-5**（AC-10、`noon.md` §3）產生中：chunk 一到就顯示 chunk、中文與發音鈕，例句與同義替換顯示骨架與「正在補例句和同義替換（8 秒內）」；主按鈕停用「補齊後才能加入」；補齊後顯示例句（chunk 底線）、例句中文（只顯示）、同義替換與「加入後是 Collected」。
- **AC-T34-6**（§5.8.4、`noon.md` §3「沒有補齊」）只收到 chunk 就逾時或出錯：例句、同義替換寫「8 秒內沒有產生。」、主按鈕「先加入字卡」；連 chunk 都沒有：錯誤卡（原因＋不會自動改用其他或付費供應商、主按鈕「到設定改用其他供應商」連 `/settings#providers`），輸入保留。
- **AC-T34-7**（AC-10、§4.17）按「加入字卡」或「先加入字卡」才呼叫 `createCard`；成功後呼叫 `enrichCard` 不等它；顯示綠色橫幅、輸入清空、焦點回輸入框、「最近新增」最上面多一列（最多 5 筆、不能點）；按「重新產生」或離開頁面不建卡。
- **AC-T34-8**（ADR-005、`noon.md` §3）預取開啟時停 600 ms 先送、輸入沒變就重用、同一輸入只送一次、改輸入就中止上一個；預取關閉時只有按鈕會送。
- **AC-T34-9**（ADR-005）發音鈕用 `speechSynthesis.speak`，`lang` 是 `en-US`、文字是 chunk；沒有 `speechSynthesis` 時不顯示。
- **AC-T34-10**（`noon.md` §3 入口、「已決定」）入口：中午 rail（只有電腦）與首頁「隨時可用」面板；素材沒備好或額度用完時入口不停用；面板標題右側寫「不算步驟，不影響打勾與連續」。
- **AC-T34-11**（DESIGN §2、`noon.md` §3；響應式）手機（< 900px）單欄、說明與「最近新增」在輸入區下方；電腦（≥ 900px）主欄＋340px rail 放說明與「最近新增」；360、412、768、1280、1440 都沒有橫向捲動；按鈕與範例 chip ≥ 48×48。
- **AC-T34-12**（DESIGN §4、§6、§10）淺深色只用 tokens；chunk 與橫幅用 `ec-in`，骨架與呼吸點在 `prefers-reduced-motion: reduce` 時不動；錯誤原因 `role="alert"`；主按鈕停用時原因文字可被讀屏讀到。
- **AC-T34-13**（§9.1.7、ADR-020 決定 1、CLAUDE.md §5 第 21 條）本單新增的 `ApiClient` 方法：supabase 版只用組成根（`apps/web/src/api/index.ts`）注入的 `deps.fetch`、`deps.getAccessToken`（測試注入假的，全域 `fetch` 被監看 0 次）；`features/add-card/**`、`features/home/**`、`features/noon/**` 沒有直接 `fetch`、沒有 import `supabase-js`、沒有模組載入時建好的全域 client，畫面經 `useApi()` 取用；新寫的前端測試用 `makeTestApiClient`／`makeTestApiRuntime`、沒有完整 `ApiClient` 字面值；新方法在 `api/test/fakes.ts` 有預設值（沒覆寫回 `internal`＋`not stubbed:`）。

- **QA 擁有的檔案不碰**：不得新增、修改、刪除或改名任何 `**/*.qa.test.ts` 與 `docs/qa/` 下的檔案。`docs/qa/**` 不列進「範圍外」：scope-check 先比對範圍外，列進去會讓 QA 自己的 commit 被判違規。既有的 QA 探針（例如 `shell.qa.test.ts` 的「今日任務會顯示在這裡。」）要照樣通過。

## 不在本單
