## 目標
`preparePlan` 在「完成」寫入之前多做四件事：選卡時傳入未用過的種子並轉成卡、對缺例句或中文意思的卡批次 enrich 並寫回、一次呼叫中午素材 LLM 並逐張檢查、預先產生跟讀 TTS；再算 `seedRemaining`。任何一件失敗都不讓計畫失敗。契約、migration 欄位、API 都不改。

## 介面
§4.14.3 的 `generateNoonMaterial`、`NoonMaterialInput`、`NoonMaterialResponseSchema`，§4.14.4 的 `shuffleBlocks`，§4.10 的 `prng.ts`，§5.8.3 的 `enrichBatch` 照 ARCHITECTURE；以下是 TechLead 補的決定：
```ts
// PlanStore（_shared/db/plan-store.ts）多四個函式，每個查詢都帶 user_id（§4.12.5）
//   listUnusedSeeds(limit)          → 還沒轉成卡的種子，batch 小的優先 → id
//   convertSeedsToCards(seedIds)    → 一次 insert，source_type 'seed'、state 'collected'；回新卡
//   countUnusedSeeds()              → §4.13.1 的 count，回非負整數
//   enrichCards(results)            → 逐張呼叫 applyCardEnrichment（T-027），回成功張數
// PlanDeps 多兩個欄位（makeTestPlanDeps 同一個 commit 補預設值）
//   readonly tts: Result<TtsProvider, ProviderError>;  readonly ttsStore: TtsStore;
export const NOON_MATERIAL_TIMEOUT_MS = 30_000;
export const NOON_MATERIAL_MAX_OUTPUT_TOKENS = 8192;   // v1.13：一次呼叫、不分批
```
- **種子**：`listUnusedSeeds` 的筆數上限是 25（一天最多用到的新卡數）；`selectDailyCards` 收到種子後，選中的種子用 `convertSeedsToCards` 一次轉卡（`card_ids` 寫新卡的 id），補位時新選中的種子同樣轉卡（§4.14.5 第 5 步）。轉卡失敗 → 照 T-025a 的「失敗原因」寫 `failure`（`step: 'cards'`），這是資料庫錯誤，不是降級。
- **批次 enrich**：選出的卡裡缺 `example_en` 或 `meaning_zh` 的（種子卡除外，§4.17 第 3 點），一次 `enrichBatch`；逐張 `checkEnrichItem`，合格的用 `enrichCards` 寫回，之後用寫回後的卡做中午素材；`enrichBatch` 回錯 → 不寫回、照 §4.14.5 繼續（§4.17 第 4 點）。
- **中午素材**：`sel1` 裡有例句的卡（最多 25 張）一次 `generateNoonMaterial`，`maxOutputTokens` 8,192、`timeoutMs` 30 秒；`i` 對回 `card_id`，沒回到、重複（第二個以後）、沒送出的都當成沒有素材；每張用 `buildNoonItem(card, llmItem, planDate)`（本單把參數放寬成 `NoonMaterialItem | undefined`），內容規則照 §4.14.2 逐欄檢查、不合格的欄位設 null；`blocks` 合格時 `shuffleBlocks` 的結果寫進 `shuffled_order`；回 null 時 `blocks`、`shuffled_order` 都設 null（那張卡改出 A）。補位卡不呼叫（§4.14.5 第 5 步）。任何 `err` → 全部 `llmItem` 是 `undefined`，計畫照樣 `ready`。
- **LLM 與 TTS 的取得**：`daily-prep` 與 `POST /plan/today` 都用 `providers.resolve('llm' | 'tts', DEFAULT_SETTINGS, usedThisMonthNtd)` 組 `PlanDeps`（第三個參數傳 `sumPaidUsageThisMonthNtd`，T-020 建；ADR-019 決定 4、§4.15.6：不要自己算。本單若比 T-020 先合併、函式還不在 main：暫傳字面 `0`（過渡，§4.19 對 T-021 的同一做法），在程式註解與報告記下呼叫點，由 T-020 的用量接線換掉；T-020 已在 main 就直接用函式）。
- **預先產生 TTS**：`shadow_items` 每一句依序 `ttsObjectPath(userId, voice, normalizeTtsText(text))`（`voice` 照 T-021 的讀法，預設 `DEFAULT_TTS_VOICE`）；物件已在就直接寫 `tts_path`；不在就 `synthesize`（`timeoutMs` 用 T-021 的 `TTS_TIMEOUT_MS`）＋`upload`（`daily-prep` 用 secret client 的 `TtsStore`，`POST /plan/today` 用使用者 client）；任一句失敗只讓那句 `tts_path` 是 null，不重試、不讓計畫失敗。
- **`seedRemaining`**：轉卡之後、「完成」之前呼叫 `countUnusedSeeds()`，和「完成」一起寫進 `seed_remaining`；回錯 → 寫 null（不讓計畫失敗）。
- **`prng.ts`**：main 上沒有就由本單照 §4.10 建（`mulberry32`、`sampleWithSeed`、`seedFromString`，測試固定前 5 個輸出）；已有就重用、不改。
- **時間**：在 `prepare.ts` 的 log 記一行各步驟毫秒數（不含內容與 id），讓 G4 部署時量 150 秒上限（§4.14.3「時間」）；本單不實測。

## 驗收標準
- **AC-T25-20**（§4.4、§4.14.5 第 1、5 步）新卡不足時從 `listUnusedSeeds` 補（`batch` 小的優先 → `id`）；選中的種子一次轉成 `source_type = 'seed'`、`state = 'collected'` 的卡，`card_ids` 是新卡的 id；補位時新選中的種子同樣轉卡；種子卡不順延、不送 enrich；轉卡回錯 → `failed`、`failure.step` 是 `cards`。
- **AC-T25-21**（§4.17「daily-prep 順手補」）缺例句或中文意思的非種子卡一次 `enrichBatch`；合格的逐張寫回、只補空欄位；不合格或沒回到的維持原樣；`enrichBatch` 回錯不讓計畫失敗；中午素材用寫回後的卡。
- **AC-T25-22**（§4.14.3、ADR-019 決定 2）有例句的 `sel1` 卡一次 `generateNoonMaterial`：`maxOutputTokens` 8,192、`timeoutMs` 30,000、不分批；送出的 `i` 是 0 起的序號；補位卡不送；任何 `err` → 全部沒有素材、計畫 `ready`。
- **AC-T25-23**（§4.14.2、§4.14.3）回應逐張對回：沒回到、重複（第二個以後）、沒送出的 `i` 都當沒有素材；每欄照 §4.14.2 檢查，不合格只把那欄設 null，不影響其他欄與其他卡。
- **AC-T25-24**（§4.14.4）`shuffleBlocks`：固定輸入固定輸出；排出的文字序列永遠不等於原句；全部重複時回 null；`buildNoonItem` 把結果寫進 `shuffled_order`，null 時 `blocks`、`shuffled_order` 都是 null。
- **AC-T25-25**（§4.14.5 第 3～6 步）enrich 與素材之後仍沒有例句和中文意思的卡順延並補位；補進來的卡只有 `cloze_en`；`noon_items` 與 `card_ids` 一一對應；順延卡的 `state`、`due_date` 不變。
- **AC-T25-26**（§4.12.1、§4.19、§4.13.3）每句跟讀先算 `ttsObjectPath`：物件已在 → 不呼叫 `synthesize`，直接寫 `tts_path`；不在 → `synthesize`＋`upload` 後寫 `tts_path`；任一句失敗只讓那句 null；計畫照樣 `ready`；語音照 T-021 的讀法。
- **AC-T25-27**（§4.13.1 v1.12）`seed_remaining`＝轉卡之後的 `countUnusedSeeds()`，和「完成」同一個 update 寫入；`countUnusedSeeds` 回錯 → null、計畫 `ready`。
- **AC-T25-28**（§4.10）`prng.ts` 的 `mulberry32` 前 5 個輸出固定、`sampleWithSeed` 決定性且不重複、`seedFromString` 同字串同結果（本單建時才測；已有就不改）。
- **AC-T25-29**（§4.12.5、§5.1.1、§4.15.6）新的 `PlanStore` 函式每個查詢都帶 `user_id`（`seed_chunk` 是共用表，不在此限，但 `not exists` 子查詢的 `card` 一定帶）；`PlanDeps` 的新欄位必填、`makeTestPlanDeps` 有預設值；`resolve` 的第三個參數是 `sumPaidUsageThisMonthNtd` 的結果（T-020 建；本單若先合併，由 T-020 用量接線完成）。

## 限制
- 不加依賴；根目錄 `package.json` 與 `.dependency-cruiser.cjs` 不動，所以 `tooling/o010.test.mjs`（TC-15）、`tooling/arch-rules.test.ts`（TC-24）不在範圍內。
- `_shared/plan/**` 只 import contracts、domain、`_shared/news`、`_shared/db`、`_shared/ai`、`_shared/tts` 的匯出；不 import registry、`wiring.ts`、adapter、`config/**`、`Deno`（§4.13.2）。不用 `Math.random`（§3）。
- 降級規則：enrich、中午素材、TTS、`countUnusedSeeds` 失敗都不讓計畫失敗、不重試；只有資料庫寫入（轉卡、「完成」）失敗才寫 `failure`。
- 正式程式不 `throw`、一律回 `Result`；不用 `any`、`as unknown as`、非空斷言、`eslint-disable`、`@ts-ignore`；`it.skip`／`it.only`／`describe.only`／`test.only` 不得提交。不刪除任何檔案；log 不含文章內容、卡片內容與使用者 id。
- **QA 擁有的檔案不碰**：不得新增、修改、刪除或改名任何 `**/*.qa.test.ts` 與 `docs/qa/` 下的檔案。`docs/qa/**` 不列進「範圍外」：scope-check 先比對範圍外，列進去會讓 QA 自己的 commit 被判違規。既有的 QA 探針要照樣通過。

## 不在本單
- 150 秒上限的實測（G4 部署時；本單只加步驟毫秒數的 log）；超過時改成只預產生前幾句 TTS（§4.14.3，不改契約，另開單）。
- 中午頁怎麼用素材（T-033）；`sumPaidUsageThisMonthNtd`（T-020）。

## 驗證方式
`pnpm check` 跑到通過；任務單不另列指令。

## 結束時
1. 在指定的分支上 commit 並 push，不得動 main。
2. 把結果寫到 docs/reports/T-025b.md：完成摘要、變更檔案、測試結果、未完成事項、需要人類決定的問題。
3. 測試結果、突變結果、權限被拒以 workflow 自動產生的摘要與 PR 觸發的 CI run 為準，報告不重貼。
