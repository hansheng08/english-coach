## 介面
```ts
type TapTest = { n: number; ok: boolean; description: string; directive: 'SKIP' | 'TODO' | null };
type TapResult = { file: string; plan: number | null; tests: TapTest[]; errors: Finding[] };
export function parseTap(text: string, file: string): TapResult;                        // tooling/tap.mjs
export function tapToTests(r: TapResult): Array<{ name: string; status: 'passed' | 'failed' | 'skipped' }>; // tooling/tap.mjs
export function checkCoverage(o: { branch: string; tasks: TaskFile[]; results?: unknown; taps?: TapResult[] }): Finding[]; // ac-coverage.mjs（擴充）
export function runDbTest(o: { testsDir: string; tapDir: string; dbUrl: string; psql: string; reset: boolean; spawn?: SpawnLike }): { findings: Finding[]; files: number; tests: number }; // db-test.mjs
```
CLI：
```text
node tooling/ac-coverage.mjs --branch <name> [--results <vitest.json>] [--tap <file.tap> ...] [--tasks-dir <dir>]
node tooling/db-test.mjs [--tests-dir supabase/tests] [--tap-dir .tmp/pgtap] [--db-url <url>] [--psql psql] [--reset]
pnpm db:test   # package.json scripts："db:test": "node tooling/db-test.mjs"
```
輸出格式同 O-008：通過 stdout `<tool>: OK <目標>`、exit 0；失敗 stderr 每個 Finding 一行 `<tool>: FAIL <file>:<line>: <rule>: <message>`，最後一行 `<tool>: <N> error(s)`，exit 1；`USAGE`／`INPUT` 同前。

### TAP 解析規則（`parseTap`；box 上以 PostgreSQL 17＋pgTAP 實測過的輸出格式）
- 計畫行 `1..N`（行首）必須恰好一行，在第一個測試行之前或最後一個測試行之後；沒有、重複、或 N 不等於測試行數 → `TAP-PLAN`。
- 測試行：`ok <n>` 或 `not ok <n>`，之後可接 ` - <描述>`，再可接 ` # SKIP …` 或 ` # TODO …`（不分大小寫）。pgTAP 的 skip 長這樣：`ok 3 # SKIP (AC-T9-3) skipped one`，此時描述取 `SKIP`／`TODO` 之後的文字。
- 編號必須從 1 起連續遞增，否則 `TAP-ORDER`；出現 `Bail out!` 開頭的行 → `TAP-BAIL`；整個輸入沒有任何測試行 → `TAP-EMPTY`。
- 其他行一律忽略：`#` 開頭的診斷、空行、`pg_prove` 的 `<路徑> .. ` 標頭與 `Files=…`／`Result: …` 摘要。
- `tapToTests`：`name` 為 `<file 的檔名>: <描述>`；`ok` 且無 directive → `passed`；`not ok` 且非 TODO → `failed`；SKIP 或 TODO → `skipped`。

### ac-coverage 擴充規則
- `--results` 與 `--tap` 至少要有一個，否則 `USAGE`；`--tap` 可重複，每個檔案都必須能讀、`parseTap` 沒有錯誤，否則 `INPUT`（訊息含 TAP rule id）。
- Vitest 與 TAP 的測試合併後套用 O-008 的 `CV-MISSING`／`CV-FAILED` 規則（含括號比對、TC 要同時含該列 AC、`skipped` 不算覆蓋）。只給 `--results` 時行為與 O-008 完全相同。

### db-test 規則
- 預設 `--db-url` 為 Supabase 本機預設連線字串 `postgresql://postgres:postgres@127.0.0.1:54322/postgres`（公開的本機預設值，不是祕密）；`--psql` 預設 `psql`。所有子行程以 `child_process.spawnSync` 的 argv 陣列執行，不經 shell，單次逾時 300 秒。
- 順序：`--reset` 時先執行 `supabase db reset`（失敗 → `DB-RESET`）；以 psql 執行 `create extension if not exists pgtap with schema extensions`（失敗 → `DB-PSQL`）；依檔名排序列出 `--tests-dir` 下的 `*.sql`、`*.pg`（沒有任何檔 → `DB-NOTESTS`）。
- 每個檔案以 psql 參數 `--no-psqlrc --no-align --quiet --pset pager=off --pset tuples_only=true --set ON_ERROR_STOP=1 --file <檔案> <db-url>` 執行；stdout 原樣寫到 `<tap-dir>/<檔名去掉副檔名>.tap` 並印到 stdout。psql exit 非 0 → `DB-PSQL`；`parseTap` 有錯誤 → `DB-TAP`；有 `failed` 的測試 → `DB-FAIL`（psql 在測試失敗時仍 exit 0，所以一定要解析 TAP）。
- 全部通過時最後一行 `db-test: OK <檔案數> file(s), <測試數> test(s)`、exit 0。任何一個檔案失敗時其餘檔案仍要執行並寫出 TAP，最後 exit 1。

## 驗收標準
- **AC-O10-1** `parseTap`：計畫行、測試行、directive、描述、忽略行依規則解析；`TAP-PLAN`、`TAP-ORDER`、`TAP-BAIL`、`TAP-EMPTY` 各自在壞輸入上出現；`tapToTests` 的狀態對應正確。
- **AC-O10-2** ac-coverage 讀 TAP：只有 pgTAP 測試覆蓋的 AC 在給 `--tap` 時 exit 0、不給時 `CV-MISSING`；TAP 內 `not ok` → `CV-FAILED`；SKIP／TODO 不算覆蓋；Vitest＋TAP 合併覆蓋；壞 TAP → `INPUT` exit 1；只給 `--results` 時 O-008 既有測試全部仍通過。
- **AC-O10-3** db-test：依規則的順序與 psql 參數呼叫子行程（以注入的假 `spawn` 斷言 argv）；寫出每個 `.tap` 檔；`DB-RESET`、`DB-PSQL`、`DB-NOTESTS`、`DB-TAP`、`DB-FAIL` 各自 exit 1；一個檔失敗時其餘檔仍執行。`package.json` 只新增 `scripts.db:test`，其他欄位不變。
- **AC-O10-4** scope-check 分支編號：任務單檔名與分支編號不同（例如任務 `T-930`、分支 `fix/Q-930`）時，`docs/qa/mutants/Q-930.json` 仍允許（只靠 `branchId` 規則）、`docs/qa/mutants/T-930.json` 也允許（任務編號規則）、`docs/qa/mutants/Q-931.json` → `SC-OUT`。拿掉 `branchId` 那條允許規則時，這個測試必須失敗。
- **AC-O10-6** 以 TAP 判定成敗（psql 在 pgTAP 測試失敗時仍 exit 0，box 上 PostgreSQL 17＋pgTAP 實測）：db-test 不得以 psql 的 exit code 當成通過的依據。psql exit 0 且 TAP 有 `not ok`（非 TODO）→ `DB-FAIL` exit 1；psql exit 0 且 TAP 缺計畫行、計畫數不符或含 `Bail out!` → `DB-TAP` exit 1；psql exit 0、全部 `ok` 且計畫數相符 → exit 0。
- **AC-O10-5** fail-closed 與依賴：`db-test`、擴充後的 `ac-coverage` 在缺參數、未知選項、檔案不存在時 exit 1（`USAGE`／`INPUT`）且不印 OK；以子行程（`process.execPath`）實際斷言 exit code；只 import `node:` 與 `./`；不含 `|| true`、`continue-on-error`、吞掉錯誤後 exit 0 的 `catch`；不新增套件、不改 `pnpm-lock.yaml`。
