> 名詞
> - **CI（持續整合）**：每次 push 或開 PR 時，GitHub 自動跑檢查的流程（GitHub Actions）。
> - **彙總 job `ci-ok`**：等其他 job 都跑完，再判斷「整體算不算過」的最後一個 job；GitHub 分支保護只要把它設成必過（required check）。
> - **PreToolUse hook**：Claude Code 執行每個指令**之前**會呼叫的外部程式，可以回覆 allow（放行）、deny（拒絕）或不表示意見。
> - **refspec**：`git push` 的「本地:遠端」寫法，例如 `task/x:main` 會把本地分支推到遠端 main；`:task/x` 是刪除；前面加 `+` 是強制覆寫。
> - **秘密掃描**：自動找出程式碼或建置結果裡像金鑰的字串，找到就讓 CI 失敗。
> - **被略過（skipped）的 job**：因為前置檔案還不存在（例如還沒有 `package.json`）而沒有跑的 job。它**不算驗證過**，G3 時要逐一列名。

## 實作限制

### A. pushguard 行為規格（`.claude/hooks/pushguard/`；**決定：用 Node.js 標準庫的 `.mjs`，不用 Go**）
> 理由（TASKS §5 第 3 點交給本單決定）：本專案是 TypeScript／Node 專案，Hansheng 的電腦本來就要裝 Node；Go 會多一套工具鏈，又違反 CLAUDE.md「不新增依賴」。`.mjs` 不需要編譯，`node --test` 是內建的測試工具。
- 輸入：stdin 的 JSON（`tool_name`、`tool_input.command`、`cwd`）。`tool_name` 不是 `Bash` 或 `PowerShell` → exit 0、無輸出。
- 斷詞與分段：簡易 shell 斷詞（單引號、雙引號、反斜線），在 `&&`、`||`、`;`、`|`、`&`、換行處切段；每段去掉開頭的環境變數指派（`X=y`）與包裝指令（`env`、`command`、`builtin`、`time`、`timeout <n>`、`nice`、`nohup`、`xargs`）；第一個字取檔名（去掉路徑與 `.exe`）。斷詞失敗（例如引號不成對）時，原始文字含 `git` 且含 `push`、`merge` 或 `pull` 任一，或含 `gh` → 一律 `deny`。
- **git**：略過 git 全域選項（任何以 `-` 開頭的字與其值，例如 `-C <x>`、`-c <x>`），第一個非選項字是子指令。
  - `push`：只有完全符合 `git push origin <B>`、`git push -u origin <B>`、`git push --set-upstream origin <B>` 才 `allow`。條件全部成立：原始指令只有**一段**，且不含 `` ` ``、`$(`、`${`、`<`、`>`、`*`、`?`、`[`、`~`、`\`、引號；`git` 前沒有環境變數或包裝指令；`git` 與 `push` 之間沒有任何選項；`<B>` 不含 `:`、不以 `+` 開頭、不是 `HEAD`／`main`／`master`，符合 `^(task|fix|poc)/[A-Za-z0-9][A-Za-z0-9._-]*(/[A-Za-z0-9][A-Za-z0-9._-]*)*$`、不含 `..`、不以 `.lock` 結尾，而且**等於目前分支**。其餘 push 一律 `deny`。
  - `merge`：一律 `deny`（強制工作規則 4）。
  - `pull`：含 `--ff-only` → 不表示意見；其他寫法 → `deny`（避免產生合併 commit）。
  - `commit`：目前分支是 `main` 或 `master`、或取不到目前分支 → `deny`；其他 → 不表示意見。
  - 其他 git 子指令 → 不表示意見（交給權限規則）。
- **gh**：只有 `gh run list`、`gh run view`、`gh run watch`、`gh pr view`、`gh pr list`、`gh pr checks`、`gh auth status` 不表示意見；其他所有 `gh` 指令（含 `gh pr create`、`gh pr merge`、`gh pr review`、`gh api`、`gh repo`、`gh release`、`gh secret`、`gh workflow run`）一律 `deny`。
- **包裝 shell**：第一個字是 `sh`、`bash`、`zsh`、`dash`、`pwsh`、`powershell`、`cmd`、`eval`、`Invoke-Expression`、`iex`，且整段文字含 `push`、`merge` 或 `gh ` → `deny`（無法安全解析）。
- 取目前分支：`execFileSync('git', ['-C', cwd, 'symbolic-ref', '--quiet', '--short', 'HEAD'], { timeout: 5000 })`；失敗（detached HEAD、不在 git repo）視為取不到 → 所有 push 與 commit 都 `deny`。把這個函式做成可注入，測試不碰真的 repo。
- 輸出：只在 stdout 印**一個** JSON 物件並 exit 0：`{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"pushguard: …"}}`。原因要寫明並提示正確寫法，例如 `pushguard: only "git push [-u] origin <current task/, fix/ or poc/ branch>" is allowed; got refspec with ":"`。不表示意見時不印任何東西、exit 0。程式內部例外 → 印原因到 stderr 並 exit 2（阻擋）。不要用 0、2 以外的 exit code。
- 相容性：程式要能在 Node.js ≥ 22 執行；Windows（PowerShell）是否完全正確：不確定，報告註明「未在 Windows 實測」即可。

### B. `.claude/settings.json`

- `hooks`：
  ```json
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|PowerShell",
        "hooks": [
          {
            "type": "command",
            "command": "node",
  ```

### C. CI workflow（`.github/workflows/ci.yml`；**決定 TASKS §5 第 4 點：Docker 版 Supabase、RLS 測試、E2E、秘密掃描的 CI 範圍**）
- `name: ci`；觸發：`pull_request`（目標 `main`）、`push`（分支 `main`、`task/**`、`fix/**`；**不含** `poc/**`，PoC 不跑 CI）、`workflow_dispatch`。`pull_request` **不得**加 `paths`／`paths-ignore`（否則必過檢查可能不出現，PR 永遠無法合併）。
- `permissions: contents: read`（全域，不給寫入權限）；`concurrency`：同一個 ref 新的 run 取消舊的（`main` 除外）。
- 所有第三方 action 用**完整 commit SHA** 釘版，後面加版本註解（例如 `actions/checkout@<40 碼 SHA> # v5.x.x`）；SHA 用 `git ls-remote https://github.com/<owner>/<repo> refs/tags/<tag>` 查。可用的 action 只有：`actions/checkout`、`actions/setup-node`、`pnpm/action-setup`、`supabase/setup-cli`、`actions/upload-artifact`。工具二進位檔（gitleaks、actionlint）從官方 GitHub release 下載**固定版本**，並用 release 附的 checksum 檔驗證 SHA-256；版本號寫在 workflow 的 `env`。
- Node 版本：用當下的 Node.js LTS 主版本（以 https://nodejs.org/en/about/previous-releases 為準），寫在 workflow `env.NODE_VERSION`，報告寫明選了哪一版。
- 每個 job 都設 `timeout-minutes`（一般 10；`db` 15；`e2e` 20）。
- **job 清單**：
  | job | 何時跑 | 做什麼 | 必跑／條件 |
  |---|---|---|---|
  | `detect` | 永遠 | checkout 後輸出旗標：`has_node`（根目錄有 `package.json` 且有 `pnpm-lock.yaml`）、`has_web`（有 `apps/web/package.json`）、`has_supabase`（有 `supabase/config.toml`）、`has_e2e`（有 `playwright.config.ts` 或 `playwright.config.js`）、`is_pr` | 必跑 |
  | `actionlint` | 永遠 | 下載固定版本 actionlint（驗 checksum）檢查 `.github/workflows/*.yml` | 必跑 |
  | `pushguard` | 永遠 | setup-node；`node --test .claude/hooks/pushguard/guard.test.mjs .claude/hooks/pushguard/settings.test.mjs .github/scripts/ci-ok.test.mjs` | 必跑 |
  | `secrets` | 永遠 | `fetch-depth: 0`；下載固定版本 gitleaks（驗 checksum）；`gitleaks git --config .gitleaks.toml --redact --no-banner`；`node .github/scripts/secret-selftest.mjs` | 必跑 |
  | `check` | `has_node` | `pnpm/action-setup`（版本從 `package.json` 的 `packageManager` 讀）、setup-node（pnpm 快取）、`pnpm install --frozen-lockfile`，再分成 4 個步驟：`pnpm typecheck`、`pnpm lint`、`pnpm arch`、`pnpm test` | 條件 |
  | `bundle` | `has_web` | 安裝依賴後 `pnpm build`；`gitleaks dir apps/web/dist --config .gitleaks.toml --redact --no-banner`（ARCHITECTURE §7「建置後掃 `dist/`」） | 條件 |
  | `db` | `has_supabase` 且是 PR | `supabase/setup-cli`（固定版本）；`supabase start`（用 `-x` 排除這個 job 用不到的服務，例如 studio、imgproxy、logflare、vector；名稱以 `supabase start --help` 為準）；`supabase db reset`；有 `supabase/tests/` 時跑 `supabase test db`（RLS 測試）；最後 `supabase stop` | 條件 |
  | `e2e` | `has_e2e` 且是 PR | 安裝依賴；`supabase start`；`pnpm exec playwright install --with-deps chromium`；`pnpm e2e`（假供應商，不打真 API）；失敗時用 `actions/upload-artifact` 上傳 Playwright 報告（保留 7 天） | 條件 |

  - Docker：GitHub 的 `ubuntu-latest` runner 內建 Docker，可以直接 `supabase start`，不另外裝。
  - `db`、`e2e` 只在 PR 跑：這兩個要拉 Supabase 容器、最花時間；repo 是私有的，Actions 分鐘數有限（GitHub Free 私有 repo 每月 2,000 分鐘，以 GitHub 帳單頁為準）。push 到 `task/**` 只跑便宜的 job，讓 Claude Code 早點看到錯誤；合併條件以 **PR 觸發的那次 run** 為準（憲章 §5）。
  - 秘密掃描：用 **gitleaks**（二進位檔，不是 npm 依賴，也不用要授權的 gitleaks-action），repo 歷史用 `gitleaks git`、建置結果用 `gitleaks dir`。`VITE_` 變數名稱白名單測試屬於 T-048（要有前端才測得到）。

### D. 秘密掃描規則（`.gitleaks.toml`、`secret-selftest.mjs`）
- `.gitleaks.toml`：`[extend] useDefault = true`，再加 3 條自訂規則：Gemini／Google API key（`AIza[0-9A-Za-z_\-]{35}`）、Groq（`gsk_[A-Za-z0-9]{20,}`）、Azure Speech（`AZURE_SPEECH_KEY` 等變數名後面接 32 碼十六進位）。不得用 allowlist 排除整個資料夾；需要排除時只能排除 `.github/scripts/secret-selftest.mjs` 這一個檔案，並在報告說明。
