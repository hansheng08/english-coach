## 目標
`claude-run-task.yml` 在換到 task 分支之前，先把派工當下的 `.github/scripts/` 與 `tooling/` 複製到 `$RUNNER_TEMP/trusted/`；切換之後的所有步驟只從這份副本執行守門腳本與工具。並以靜態檢查凍結，使後人無法再讓切換後的步驟引用工作樹的腳本。

## 定義（本節凍結）
- 可信根：`${{ runner.temp }}/trusted`（shell 內寫 `${RUNNER_TEMP}/trusted` 或 `$RUNNER_TEMP/trusted`）。底下鏡像 repo 結構：`trusted/.github/scripts/`、`trusted/tooling/`。
- 步驟與註解：步驟是 `steps:` 底下縮排 6 格的 `- ` 項目；分析前先去掉第一個非空白字元是 `#` 的行；步驟名稱取 `name:`，沒有就取 `uses:`。
- Snapshot 步驟：名稱固定 `Snapshot trusted scripts`；必須是第 2 個步驟（緊接第一步 checkout）；沒有 `if`、沒有 `continue-on-error`；`run:` 要有兩條遞迴 `cp`（`-R`、`-r` 或 `-a`），來源分別是 `.github/scripts` 與 `tooling`，目的在可信根底下；不使用任務編號（不含 `client_payload`）。第一步 checkout 不得有 `ref:` 或 `repository:`。
- 切換邊界：第 2 步之後，第一個含 `actions/checkout`，或含 `git switch`、`git checkout`、`git reset`、`git merge`、`git rebase`、`git pull`、`git restore`、`git clean` 之一的步驟。以內容判斷、不看名稱；找不到邊界一律算問題（fail-closed）。
- 引用規則：邊界步驟（含）之後的每個步驟，扣掉「可信根開頭的路徑」（`${RUNNER_TEMP}/trusted/`、`$RUNNER_TEMP/trusted/`、`${{ runner.temp }}/trusted/` 後接 `.github/scripts` 或 `tooling`）之後，不得再出現 `.github/scripts` 或 `tooling`（單字比對）；`uses:` 不得是本地 action（`./` 開頭）。Snapshot 必須在邊界之前。
- TOOLING_DIR：邊界之後含 `run-task-post-check.sh` 或 `run-task-usage-limit.sh detect` 的步驟，`env:` 必須有 `TOOLING_DIR: ${{ runner.temp }}/trusted/tooling`（兩支腳本預設的相對 `tooling` 不可用）。
- 唯讀：只有 Snapshot 步驟可以對可信根做 `cp`、`mv`、`rm`、`ln`、`chmod`、`rsync`（同一行出現 `/trusted` 與這些指令之一即算違規）。
- 順序：第 1 步 checkout、第 2 步 Snapshot、第 3 步 Validate（O-032 的鎖由「Validate 是第 2 步」改為第 3 步；Snapshot 不用任務編號，所以「Validate 之前沒有步驟用編號」仍成立）。Snapshot 放在 Validate 之前，是為了 Validate 失敗時 `always()` 的 Notify 仍找得到可信腳本。
- 比對規則：只看 workflow 文字，不連網、不執行；只用 Node 內建模組。

## 介面
```ts
// tooling/trusted-scripts.mjs
export function stepsOf(yml: string): { index: number; name: string; text: string }[] | null;
export function trustedScriptProblems(yml: string): string[]; // [] = 合格；每個問題一行，不含檔案路徑
```
`stepsOf` 在找不到 `steps:` 或零個步驟時回 null；`trustedScriptProblems` 對 null、非字串、空字串都回非空陣列。

## 驗收標準
- AC-O33-1：`trustedScriptProblems` 對「合格範本」回 `[]`。範本是測試內自備的 workflow 文字：checkout、Snapshot、Validate、Task lint（用工作樹的 `tooling/task-lint.mjs`，切換前允許）、`Check out existing task branch`、五個切換後步驟全部走可信根並設好 TOOLING_DIR。
- AC-O33-2：Snapshot 規則：缺少、不是第 2 步、在邊界之後、有 `if` 或 `continue-on-error`、少複製其中一個目錄、目的不在可信根、使用任務編號、第一步 checkout 帶 `ref:` 或 `repository:`，每一種都回對應的問題。
- AC-O33-3：引用規則：邊界之後任何一個步驟引用 `.github/scripts/…` 或 `tooling/…` 的相對路徑（`run-task-usage-limit.sh`、`verify-push.sh`、`run-task-post-check.sh`、`run-task-summary-step.sh`、`run-task-outcome.sh` 各一例，另加 `node tooling/…`、`bash -c` 內的引用、本地 `uses: ./…`）都回問題；邊界之前的步驟用相對路徑不報問題；只在註解行出現的路徑不報問題。
- AC-O33-4：TOOLING_DIR 規則：缺少、值是相對的 `tooling`、指向可信根以外、`TOOLING_DIR` 寫在別的步驟，都回問題；`run-task-usage-limit.sh fields` 與 Notify 不要求。
- AC-O33-5：fail-closed：找不到邊界（把切換步驟的指令全拿掉）、步驟改名但指令還在（仍判為邊界）、沒有 `steps:`、空字串、非字串輸入，都回非空陣列；非 Snapshot 步驟對可信根做 `cp`／`rm` 回問題。
- AC-O33-6（SRE）：真實 `claude-run-task.yml` 照「定義」接線：第 2 步是 Snapshot、第 3 步是 Validate；五個切換後守門步驟只走可信根；`trustedScriptProblems` 對真實檔回 `[]`；`claude-permission-check.mjs` 呼叫它並把 O-032 的順序鎖改為 Validate 第 3 步；新測試接進 `ci.yml` 既有測試步驟（不新增 job），並由 `tooling/o033.test.mjs` 包進 ac-coverage。
- AC-O33-7（SRE）：把真實 Snapshot 步驟的 `run:` 原文抽出，在暫存目錄（含真實腳本）執行：可信副本與來源逐檔相同；之後把工作樹的腳本改成舊式或壞檔，可信副本不變；用可信的 `run-task-validate-id.sh` 驗 `T-035b` 通過，而被改成舊式的工作樹版本拒絕（重現本單的失敗）；來源目錄不存在時結束碼非 0。
