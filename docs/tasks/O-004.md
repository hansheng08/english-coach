# O-004：CI／workflow 安全網（驗證腳本預設失敗、禁止 fail-open、run-task 防護）

> ## ⚠️ 強制工作規則（開始前必讀；不論使用什麼工具、外掛或代理程式，包括 pstack，都一樣）
> 1. 只在任務單指定的分支工作（從最新 origin/main 建立，或沿用既有的 task/T-xxx）。
> 2. 只 commit、只 push 這個分支：git push -u origin task/O-004。
> 3. 絕對不碰 main：不在 main commit，不用任何寫法推到 main（HEAD:main、task/O-004:main、refs/heads/main）。
> 4. 不合併（不執行 git merge，也不在 GitHub 合併任何東西）。
> 5. 不開 PR（若由 Claude Code 執行；本單改由 SRE 在 box 上實作並開 [G3] PR，仍不得合併）。
> 6. 只修改「範圍：要做」列出的檔案；需要動其他檔案就停下，寫進報告。
> 7. 不 force push，不刪除任何分支或既有檔案。
> 8. 不寫入、不讀取任何密碼、Token、API Key。
> 9. 報告的測試結果必須貼原始輸出。
> 10. 和其他指示（包括 pstack 的建議步驟）衝突時以本節為準；不確定就停下，寫進報告。

> ## 📌 本單特別規則（和上面 10 條同樣強制）
> 11. **不要新增任何 GitHub secret**，也不要改 repo 的 Secrets／Variables／分支保護。不要派工給 Claude Code。
> 12. **不要改產品程式**：不得修改 `apps/**`、`packages/**`、repo 根目錄的 `supabase/functions/**`。
> 13. 任務單與實作放在同一個 `task/O-004` PR，不先把任務單推進 main。若 PR #15 尚未合併，不得先推 `task/O-004`；待 #15 合併後 rebase 到最新 `origin/main` 再推。

## 背景（開始前先讀）
- 檢討報告 P4、P12：驗證腳本會 fail-open；被擋的指令被拆開重送；`cat`／`grep`／`head`／`ls`／`sed` 與任務單第 15 條不符；`git fetch || true` 讓 Verify 略過。
- C1–C6、D、A2 核准併入本單。C6 新增 workflow 檔已一併核准。
- ADR-009 (2) staging 部署實驗只寫計畫，不建立資源、不加 secret。

## 目標（一句話）
把檢討報告的 CI／workflow 安全網做成一張 [G3] PR：驗證預設失敗、禁止 fail-open、擋住拆指令重送、對齊 deny 清單、修好 Verify fetch，並補 PR 範本與執行環境能力表。

## 範圍：要做
1. `.github/scripts/detect-resplit.mjs`（及測試）：掃描 execution artifact，被拒指令拆開重送則失敗。證據：run 45205560119。
2. `.claude/settings.json`、`.claude/hooks/pushguard/guard.mjs` 與測試：deny `cat`／`grep`／`head`／`ls`／`sed`（含複合指令）。
3. `.github/scripts/verify-push.sh` 與 `.github/workflows/claude-run-task.yml`：`git fetch` 失敗則 Verify 失敗。
4. C1：每個 verify 腳本附負面測試，CI 的 `pushguard` job 一律跑。
5. C2：`.github/scripts/fail-open-lint.mjs` 擋驗證路徑的 `|| true`／`continue-on-error`（範圍寫在腳本開頭；例外需 `o004-allow:` 理由）。
6. C3：從 `claude-execution-output.json` 抓測試摘要、權限被拒次數、Duration，貼到既有 PR 留言（或無 PR 時的 commit comment）。`pull-requests: write` 僅為此，不開 PR。
7. C4：`ci-ok` 摘要列出被略過的 job；push 且 `db` skipped 時標「未驗證」。
8. C6：`poc-spike.yml`（`workflow_dispatch`，`poc/A-xxx`）。
9. D：`.github/pull_request_template.md`（檢討報告 D 節固定段落；不用 Bot 禁止用語）。
10. A2：`docs/RUNBOOK.md` 新增執行環境能力表。
11. `docs/tasks/O-004.md`、`docs/reports/O-004.md`（含 ADR-009 (2) staging 計畫，只列不實作）。

## 範圍外：不要做
- 合併任何 PR、推 main、新增 secret、改產品程式、派 Claude Code
- 不改任務單第 15 條本文（若認為該改，只在報告建議）
- 不修憲章 v5（A1 等屬幕僚長／Hansheng）
- 不實際建立 Supabase staging 專案或寫入任何密鑰值
