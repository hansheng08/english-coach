```text

git log --format=%x1e%H%x1f%ae%x1f%ce%x1f%s --name-status -M --diff-merges=dense-combined <BASE>..<HEAD>
```

### 「是誰改的」辨識方法（SRE 依 main 上實際 commit 決定）
- 實際資料：Claude 的 commit 作者與提交者都是 `claude[bot]`（noreply 信箱）；QA、SRE、Architect、PM、部分 TechLead 的 commit 作者全是同一個 `GrokBot`（box 上共用的 hansheng08 身分），其餘 TechLead commit 是 `hansheng08`。所以作者只能分辨「Claude 與否」，不能分辨 box 上的角色；角色只能靠訊息前綴（憲章 §5：`[角色] <編號> 摘要`）。
- 規則：QA commit ＝ 主旨以 `[QA] ` 開頭，且作者與提交者信箱都不在 `BOT_EMAILS`。其他一律視為非 QA commit（含 `[Claude]`、`[ClaudeCode]`、`[TechLead]`、`[SRE]`、無前綴）。
- 已知限制：前綴是自己宣告的，box 上的 Bot 都能寫 `[QA]`；Claude 有 `Bash(git *)`，理論上也能改作者與前綴。補強：run-task 內 Claude 產生的 commit 一律以 `--all-non-qa` 檢查（見「SRE 接線」），不看前綴與作者。
- 「放寬」的機械定義：非 QA commit 對 QA 擁有檔做任何新增、修改、刪除、改名（來源或目的）都算違規，不另判斷斷言數是否變少。理由：QA 獨佔這些檔案，任何變動都已越權；計算斷言數可被繞過且無法 fail-closed。

### scope-check 擴充規則
- 允許範圍：QA 擁有檔在 `SC-DENY`、`SC-OUT` 判斷之前就視為允許（即使任務單「範圍外」含 `supabase/**`、`packages/**`）；改由擁有者檢查把關。非 QA 擁有檔的行為與 O-008、O-010 完全相同。
- `parseCommitLog`：每筆以 `\x1e` 開頭，標頭四欄以 `\x1f` 分隔；之後每行 `<狀態>\t<路徑>[\t<路徑>]`；改名 `R<分數>` 有兩個路徑；合併 commit 的狀態可為多個字母（例如 `MM`）。標頭欄數不對、sha 不是 40 位十六進位、檔案行沒有路徑 → `SC-LOG`（CLI 視為 `INPUT`）。
- `checkQaOwnership`：每個非 QA commit 碰到的每個 QA 擁有檔 → `SC-QA-OWNER`（訊息含短 sha、主旨開頭的前綴、路徑）；`allNonQa` 為 true 時所有 commit 視為非 QA。
- 無法查證就失敗：變更清單含 QA 擁有檔但沒給 `--commits` → `SC-QA-NOLOG`；變更清單中的 QA 擁有檔沒有出現在任何 commit 的檔案行 → `SC-QA-NOLOG`。

## 驗收標準
- **AC-O12-1** `isQaOwned`：`x.qa.test.ts`（根目錄）、`packages/a/b.qa.test.ts`、`supabase/tests/qa_x.sql` 為 true；`a.qa.test.tsx`、`a.qa.test.ts.txt`、`a.test.ts`、`supabase/tests/sub/qa_x.sql`、`supabase/tests/t004_rls_test.sql`、`tooling/qa_x.sql` 為 false。
- **AC-O12-2** 允許範圍：`task/**`、`fix/Q-*` 分支上，QA 擁有檔即使不在「要做」或符合「範圍外」也不產生 `SC-OUT`／`SC-DENY`；非 QA 擁有檔的結果與擴充前相同，O-008、O-010 的 scope-check 既有測試全部仍通過。
- **AC-O12-3** `parseCommitLog`：依規則解析一般、改名、刪除、合併 commit；壞輸入產生 `SC-LOG`，CLI 對壞檔與不存在的檔 exit 1（`INPUT`）。
- **AC-O12-4** 擁有者檢查：`[QA] ` 前綴且非 bot 信箱的 commit 可新增、修改、刪除 QA 擁有檔；`[Claude]`、`[TechLead]`、`[SRE]`、無前綴、或 `[QA] ` 前綴但作者或提交者為 `BOT_EMAILS` 的 commit，對 QA 擁有檔的新增、修改、刪除、改名（來源或目的）、合併中的變動都 → `SC-QA-OWNER` exit 1；`--all-non-qa` 時 `[QA]` commit 也 → `SC-QA-OWNER`。拿掉 bot 信箱判斷或前綴判斷任一條時，至少一個測試必須失敗。
- **AC-O12-5** fail-closed：`SC-QA-NOLOG` 兩種情況各自 exit 1；變更清單不含 QA 擁有檔且未給 `--commits` 時行為與擴充前相同；以子行程（`process.execPath`）實際斷言 exit code，失敗時 stdout 不印 OK。
- **AC-O12-6** Vitest 真的執行 QA 擁有檔：`vitest.config.ts` 的 `test.include` 新增 `**/*.qa.test.ts`，其他欄位不變。測試以子行程執行 repo 的 vitest（`--config <repo 的 vitest.config.ts 絕對路徑> --root <暫存目錄> --globals --reporter=json`），暫存目錄內放根目錄層的故意失敗樣本與 `packages/` 下的通過樣本：exit 1，JSON 報告中失敗樣本為 failed、通過樣本為 passed。從 include 拿掉 `**/*.qa.test.ts` 時此測試必須失敗（SRE 已在 box 實測：拿掉時失敗樣本不會被收集、exit 0）。
- **AC-O12-7** db-test 真的執行 QA 擁有檔：預設 `--tests-dir` 為 `supabase/tests`；暫存目錄含 `qa_probe.sql` 與一般 `.sql` 時，以注入的假 `spawn` 斷言兩個檔都依檔名排序以 `--file` 執行；`qa_probe.sql` 的 TAP 有 `not ok` 而 psql exit 0 → `DB-FAIL` exit 1，其餘檔仍執行。
- **AC-O12-8** 依賴與自我約束：新增程式只 import `node:` 與 `./`；不含 `|| true`、`continue-on-error`、吞掉錯誤後 exit 0 的 `catch`；不新增套件、不改 `pnpm-lock.yaml`。本分支不新增任何符合 `QA_GLOBS` 的檔案（樣本一律存成 `.txt`，測試時才複製成正式檔名到 `os.tmpdir()`）。
