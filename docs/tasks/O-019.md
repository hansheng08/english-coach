## 目標
每筆突變只跑與該目標檔相關的測試，驗證強度不變，且不調高 40 分上限。相關測試沒抓到的突變仍判 SURVIVED；解析失敗或 0 個相關測試時 fail-closed 或改跑完整套件，絕不可因此判 KILLED。

## 介面
```js
// tooling/run-mutants.mjs；CLI 參數與報告 JSON 形狀不變
// resolveRelated(sourceFile, ctx) → { tests: string[] } | { rule: 'MU-RELATED', error }
// tests 為 repo 相對路徑；空陣列代表 0 個相關測試
export function execute({ file, root, runner, timeoutMs, spawn, resolveRelated })
```

### 相關測試規則
- 解析：以 Vitest import graph 找出會載入該突變檔的測試檔（可用 `vitest related <file>` 或等價、可注入的 `resolveRelated`）。每個不重複的 `file` 在乾淨樹上解析一次並快取；解析本身不是 KILLED／SURVIVED。
- 非空清單：該筆突變的執行器只跑這些測試檔（把路徑交給既有 runner，或等價的 `vitest run <tests…>`），不得再跑完整套件。
- 0 個相關測試：該筆改跑完整套件（與 baseline 相同的 `DEFAULT_RUNNER`／傳入的 `runner`）。不得把「0 個測試 + exit 0」（含 `passWithNoTests`）當最終結果。
- 解析失敗（無法啟動、逾時、輸出無法得到清單、回 `{ rule: 'MU-RELATED', error }`）：該筆 `unexpected`、finding 規則 `MU-RELATED`，不得判 KILLED；目標檔仍須還原。
- 判定不變：執行器 exit 0 → SURVIVED（相關測試沒抓到也是 SURVIVED）；失敗測試名稱命中 `expectFail` → KILLED；否則 `MU-UNEXPECTED`／`MU-RUNNER` 照舊。
- baseline 仍先跑一次完整套件；不通過則 `MU-BASELINE`、不套用任何突變（與 O-009 相同）。
- 不得調高 `DEFAULT_TIMEOUT_MS`，也不得改任何 workflow 的 `timeout-minutes`。
