## 目標
新增 Azure Speech 的 `PronunciationProvider`（短音訊 REST 發音評估）與 `TtsProvider`（TTS REST，mp3），由一個工廠回傳；新增 `loadAzureSpeechConfig`。只做 F0 的 `azure-speech`，不做付費版；不建立 `wiring.ts`。

## 介面
TechLead 決定（檔名與型別名稱照此；`azure-speech/` 對外只有 `index.ts` 的三個名稱）：
```ts
// supabase/functions/_shared/config/provider-keys.ts（新增）
export type AzureSpeechConfig = { readonly key: string; readonly region: string };
export function loadAzureSpeechConfig(get: EnvGetter): Result<AzureSpeechConfig, ProviderError>;
// supabase/functions/_shared/providers/azure-speech/index.ts（新增）
export type AzureSpeechDeps = { readonly key: string; readonly region: string; readonly fetch: typeof fetch };
export type AzureSpeechProviders = { readonly pronunciation: PronunciationProvider; readonly tts: TtsProvider };
export function createAzureSpeechProviders(deps: AzureSpeechDeps): AzureSpeechProviders;
// azure-speech/errors.ts、azure-speech/ssml.ts（新增；純函式，供 index.ts 與測試用）
export type AzureHttpFailure = { readonly status: number; readonly headers: Headers; readonly bodyText: string };
export function classifyAzureError(f: AzureHttpFailure, capability: 'pronunciation' | 'tts'): ProviderError;
export function parseRetryAfter(value: string | null): number | null;
export function escapeSsmlText(text: string): string;
export function buildSsml(voiceName: string, text: string): string;
```
- 請求、回應對應、SSML、錯誤表全部照 §5.6.2～§5.6.4；`retryAfterSec` 與時間換算照 §5.5 第 6、7 點。
- `ProviderError` 一律 `provider: 'azure-speech'`，`capability` 是發出請求的那個能力；`message` 回傳前把金鑰字串換成 `[redacted]`。每次 `assess`／`synthesize` 最多呼叫 `fetch` 一次，不重試。

## 驗收標準
- **AC-T17-1**（§5.5 `loadAzureSpeechConfig`）讀 `AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`；任一個沒有、空字串或只有空白 → `not_configured`（`provider: 'azure-speech'`、`capability: 'pronunciation'`，訊息只寫缺少的變數名稱）；`region` trim、轉小寫後必須符合 `^[a-z0-9]+$`，否則 `not_configured`、訊息 `invalid env AZURE_SPEECH_REGION`（不含值）。
- **AC-T17-2**（§5.6.1）工廠回傳兩個物件：`id: 'azure-speech'`、`tier: 'free'`、`displayName: 'Azure Speech'`，`capability` 分別是 `pronunciation`、`tts`；建立時不呼叫 `fetch`；不產生 `azure-speech-paid`。
- **AC-T17-3**（§5.6.2 請求）`POST https://{region}.stt.speech.microsoft.com/speech/recognition/conversation/cognitiveservices/v1?language=en-US&format=detailed`；標頭 `Ocp-Apim-Subscription-Key`、`Content-Type: audio/wav; codecs=audio/pcm; samplerate=16000`、`Accept: application/json`、`Pronunciation-Assessment`（§5.6.2 的 JSON 以 UTF-8 位元組做 base64，五個鍵與值照 §5.6.2，布林是 JSON 布林）；body 是 `Wav16kMono.bytes`；不送 `Transfer-Encoding: chunked`、`EnableProsodyAssessment`；`referenceText` 原樣放進 JSON；金鑰不在網址裡。
- **AC-T17-4**（§5.6.2 回應）`RecognitionStatus: Success` → 取 `NBest[0]`：`score0to100 = PronScore`（夾在 0～100）、`recognizedText = Display`、每個字 `Word`（空的跳過）、`startMs = round(Offset/10000)`、`endMs = round((Offset+Duration)/10000)` 再照 §5.5 第 7 點、`confidence: null`；`Offset`／`Duration` 是數字或純數字字串都接受；`provider: 'azure-speech'`；結果通過 `PronunciationResultSchema`。`NBest` 沒有或空陣列、沒有 `PronScore` → `invalid_response`。
- **AC-T17-5**（§5.6.2、ADR-015 決定 4）`NoMatch`、`InitialSilenceTimeout`、`BabbleTimeout` → `ok({ score0to100: 0, recognizedText: '', words: [], provider: 'azure-speech' })`；`Error` → `unavailable`；其他值或欄位缺少、2xx 不是 JSON → `invalid_response`。
- **AC-T17-6**（§5.6.3 請求）`POST https://{region}.tts.speech.microsoft.com/cognitiveservices/v1`；標頭 `Ocp-Apim-Subscription-Key`、`Content-Type: application/ssml+xml`、`X-Microsoft-OutputFormat: audio-24khz-48kbitrate-mono-mp3`、`User-Agent: english-coach`；body 等於 `buildSsml(去掉 azure: 前綴的語音名稱, text)`。`voice` 不是 `azure:` 開頭 → 不呼叫 `fetch`，回 `not_configured`（訊息 `voice not supported by azure-speech: <VoiceId>`）。
- **AC-T17-7**（§5.6.3 SSML）`buildSsml` 輸出等於 §5.6.3 的單行範本；`escapeSsmlText` 依序 `&`（最先）、`<`、`>`、`"`、`'` 換成實體，刪掉 U+0000～U+001F（保留 `\t`、`\n`、`\r`）；語音名稱也經同一個函式。
- **AC-T17-8**（§5.6.3 回應）200 的內容就是 `TtsResult.audio`，`mime: 'audio/mpeg'`、`durationMs = Math.round(bytes.length * 8 / 48)`；內容是空的 → `invalid_response`。
- **AC-T17-9**（§5.6.4）`classifyAzureError` 照表由上往下、用第一列符合的：408／504 → `timeout`；403＋內容含 `quota`（不分大小寫）→ `quota_exhausted`、`retryAfterSec: null`；429 → `rate_limited`（`retryAfterSec` 照 §5.5 第 6 點）；401、其他 403 → `auth`；400、415、其他 4xx、3xx、5xx → `unavailable`（訊息含 HTTP 狀態）。不產生 `region_blocked`。
- **AC-T17-10**（§5.5 第 2、3、4 點）兩個能力都：在 `opts.timeoutMs` 用 `AbortController` 中止並回 `timeout`（`fetch` 不理會 signal、內容讀不完時也一樣）；`fetch` 丟網路錯誤 → `unavailable`；任何 `message` 都不含金鑰字串；每次呼叫 `fetch` 剛好一次。
- **AC-T17-11**（§5.5「沒有實測樣本」）依文件做的樣本放在 `azure-speech/test/`，內容沒有金鑰樣子的字串（32 位十六進位、`AIza`、`gsk_`）；用到這些樣本的測試名稱含「未驗證」。

## 測試的寫法
- 只用注入的假 `fetch`（寫在 `azure-speech/test/`，記錄網址、標頭、body）；不連網、不讀環境變數、不 import 其他 adapter 的測試工具。
- 逾時一律用 `vi.useFakeTimers()`＋`vi.advanceTimersByTimeAsync`，不寫真實等待；每個測試結束還原計時器。
- WAV 輸入用 `parseWav16kMono` 解析自己組的 16 kHz mono 檔頭＋少量樣本得到 `Wav16kMono`，不用真的錄音。
- 測試裡的金鑰一律是假字串，不得像真的金鑰；樣本照 §5.6 與 ADR-015 參考網址的文件範例自己寫。

## 限制
- 不加依賴、不用 SDK（只用 `fetch`、`TextEncoder` 與內建 base64）；根目錄 `package.json` 與 `.dependency-cruiser.cjs` 不動，所以 `tooling/o010.test.mjs`（TC-15）、`tooling/arch-rules.test.ts`（TC-24）不在範圍內。dependency-cruiser 第 18、19 條已涵蓋 `providers/azure-speech`（§5.5），不加規則。
- 正式程式不 `throw`、一律回 `Result`；回應 schema 寬鬆解析；不用 `any`、`as unknown as`、非空斷言、`eslint-disable`、`@ts-ignore`；`it.skip`／`it.only`／`describe.only`／`test.only` 不得提交。相對 import 寫 `.ts` 副檔名。
- adapter 不檢查音訊長度與文字長度（§5.6.2、§5.6.3）；F0 同時只能 1 個請求由呼叫端（T-030）負責，adapter 不排隊。
- **QA 擁有的檔案不碰**：不得新增、修改、刪除或改名任何 `**/*.qa.test.ts` 與 `docs/qa/` 下的檔案。`docs/qa/**` 不列進「範圍外」：scope-check 先比對範圍外，列進去會讓 QA 自己的 commit 被判違規。既有的 QA 探針要照樣通過。
