## 目標
新增 `POST /checkins`：使用者身分（受 RLS）寫入一筆 `slot_checkin` 事件，成功回 204；同一事件重送視為成功（冪等）；`planDate` 只能是台北今天或昨天（AC-04、AC-21、AC-26、M1）。同時讓路由可以拿到 `UserDb` 與注入的時鐘，這是第一條需要資料庫的路由。

## 介面
TechLead 決定（檔名與型別名稱照此）：
```ts
// supabase/functions/api/router.ts（修改）
export type RouteDeps = { readonly userDb: (ctx: AuthContext) => UserDb; readonly now: () => Date };
export type Route = (req: Request, ctx: AuthContext, deps: RouteDeps) => Promise<Response>;
export type RouteKey = 'GET /health' | 'POST /checkins';
// RouterDeps 新增一欄（其餘不變）：
//   readonly routeDeps: Result<RouteDeps, AppError>;
// supabase/functions/api/checkins.ts（新增）
export const postCheckins: Route;
// supabase/functions/_shared/db/checkin.ts（新增）
export const SLOT_CHECKIN_COLUMNS: readonly ['user_id', 'plan_date', 'slot', 'step', 'status'];
export function insertCheckin(client: DbClient, userId: UserId, e: CheckinEvent): Promise<Result<null, AppError>>;
// supabase/functions/_shared/db/user-db.ts（修改）：UserDb 新增
//   readonly insertCheckin: (e: CheckinEvent) => Promise<Result<null, AppError>>;
```
- **路由**：`createRouter` 的順序不變（OPTIONS → `auth` → `requireUser` → 找路由）。找到路由後，`deps.routeDeps` 是 `err` 就回該錯誤；是 `ok` 才呼叫 `ROUTES[key](req, user.value, routeDeps.value)`。`GET /health` 不使用 `deps`，行為不變。
- **接線**（`index.ts`）：`routeDeps` 由 `loadSupabaseEnv(denoEnv)` 對應成 `{ userDb: (ctx) => createUserDb(ctx, env), now: () => new Date() }`；`api/**` 其他檔案不讀時鐘，一律用 `deps.now()`。
- **處理順序**（`postCheckins`）：
  1. 讀 JSON body；讀不到或不是 JSON → 400 `validation`，`issues: [{ path: 'body', message: … }]`。
  2. `CheckinEventSchema.safeParse`；失敗 → 400 `validation`，每個 zod issue 對應一個 `{ path: issue.path 以 '.' 連接, message: issue.message }`。body 多出的欄位（例如 `userId`）由 schema 去掉，不影響寫入。
  3. `today = toTaipeiPlanDate(deps.now())`、`yesterday = addDays(today, -1)`；`planDate` 不是這兩天之一（含未來日期）→ 400 `validation`，`issues: [{ path: 'planDate', message: … }]`。`toTaipeiPlanDate`／`addDays` 回 `err` → 500 `internal`。
  4. `deps.userDb(ctx).insertCheckin(event)`；`ok` → 204、沒有 body；`err` → `httpStatusOf` 對應的狀態與 `toApiErrorBody`。
- **寫入**（`insertCheckin`）：一列，欄位剛好是 `SLOT_CHECKIN_COLUMNS`；`user_id` 一律取參數 `userId`（來自 `AuthContext`），`plan_date`／`slot`／`step`／`status` 取自 event；不送 `id`、`recorded_at`。
- **冪等**（§4.8.3）：資料庫回 Postgres 錯誤碼 `23505`（唯一鍵衝突）→ `ok(null)`，第一次的 `recorded_at` 保留。其他錯誤 → `db_failed`，訊息格式同 `runDb`（只有操作名稱與錯誤碼，不含資料）。
- **不檢查的事**（§4.8.3 只要求上面兩項伺服器檢查）：時段的開始時間與範圍（「在時段內打開」由讀取端判定，T-044）、事件先後（例如沒有 `opened` 就 `completed`）、同一步驟同時有 `skipped` 與 `completed`。

## 驗收標準
- **AC-T53-1**（§5.1、ADR-010）`ROUTES` 有 `POST /checkins`；沒有 token、token 無效、`role` 不是 `authenticated` 時都回 401 `unauthenticated`，且不呼叫 `userDb`。
- **AC-T53-2**（§5.1、§6 第 2 點）body 不是 JSON，或不符合 `CheckinEventSchema`（步驟不屬於該時段、`opened` 配非 `slot` 步驟、非 `opened` 配 `slot`、未知時段或狀態、日期格式錯）→ 400，`ApiErrorBody.kind = 'validation'`，`issues` 的 `path` 照「介面」；不呼叫 `insertCheckin`。
- **AC-T53-3**（§4.8.3）`planDate` 只接受 `deps.now()` 換算的台北今天與昨天；台北午夜前後各一秒判定正確；前天、明天都回 400 `validation`（`path` 是 `planDate`），不呼叫 `insertCheckin`。
- **AC-T53-4**（§4.8.3、§5.1）合法事件 → `insertCheckin` 被呼叫一次，寫入的一列只有 `SLOT_CHECKIN_COLUMNS` 五欄，`user_id` 等於 `AuthContext.userId`（body 帶的 `userId` 不採用）；回 204、body 是空的、帶既有的 CORS 標頭。
- **AC-T53-5**（§4.8.3 冪等、§5.0.4）資料庫回 `23505` → `insertCheckin` 回 `ok`、端點回 204；回其他錯誤碼或 supabase-js 丟例外 → `db_failed`、端點回 500，訊息不含 event 的任何值。
- **AC-T53-6**（T-006 欄位權限）`SLOT_CHECKIN_COLUMNS` 與 T-006 migration 的 `grant insert (…) on table public.slot_checkin to authenticated` 欄位與順序相同（靜態比對；真實資料庫的權限與 RLS 已由 t006 pgTAP 在 PR CI 的 `db` job 驗證）。
- **AC-T53-7**（接線）`routeDeps` 是 `err` 時，`POST /checkins` 回該錯誤的狀態與 `ApiErrorBody`；`GET /health` 在 `routeDeps` 是 `ok` 或 `err` 時都照舊回 200 `{ ok: true }`。

## 測試的寫法
- 時鐘一律注入：`RouteDeps.now` 回固定的 `Date`；不讀系統時鐘，不寫任何固定等待或計時器。
- 資料庫一律用假的 `DbClient`／`UserDb`（記錄收到的列與呼叫次數）；不連網、不連資料庫。
- `router.test.ts` 的 harness 補上 `routeDeps`（假 `userDb`＋固定 `now`）；既有 T-003 測試的名稱與斷言不改。
- 端點測試經 `createRouter` 送 `Request`，路徑用 `/api/checkins`，`Authorization: Bearer` 配假驗證器。
