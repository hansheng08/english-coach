## 目標
派工編號可以帶一個小寫字母尾碼（`T-025a`、`T-025a-fix1`）；任何一個步驟在驗證失敗時，幕僚長都會收到 `claude-task-finished`（失敗），不必自己翻 run 列表。範圍最小：不改 outcome 的種類、不改權限、不改 Claude 的執行方式。

## 定義（本節凍結）
- 任務編號：`^[TQOAP]-[0-9]{3}[a-z]?(-fix[1-9][0-9]*)?$`。與幕僚長提的式子只差 `-fix` 後面「不以 0 開頭」，目的是和 `task-file.mjs` 一致。
- 分支名：`^(task/[TQOAP]-[0-9]{3}[a-z]?|fix/Q-[0-9]{3}[a-z]?)$`（`-fix` 輪次沿用基底編號的分支）。
- 基底編號：去掉 `-fix<n>` 後的編號（`T-025a-fix1` 的基底是 `T-025a`）；QA 突變檔是 `docs/qa/mutants/<基底>.json`。
- AC 前綴：沿用 `acPrefix`，只取字母與數字、忽略尾碼；`T-025a` 與 `T-025b` 同為 `AC-T25-`（現狀，不改）。
- 比對規則：整串比對、不允許換行、`LC_ALL=C`；編號只經環境變數進入 shell，不寫進命令字串。驗證失敗的訊息不得回顯原始值（只印替換掉非 `[A-Za-z0-9._/-]` 字元後、最多 40 字元的版本）。
- 順序：workflow 第一步是 checkout（預設分支，`persist-credentials: false`、`fetch-depth: 0` 不變），第二步是 Validate（呼叫驗證腳本），其後才有任何使用編號的步驟。Validate 失敗：後續非 `always()` 步驟略過；`always()` 步驟照跑；Notify 送 `claude-task-finished`，`outcome` 依既有規則為 `failure`（`run-task-outcome.sh` 對全部被略過的輸入回 `failure`），不新增 outcome 值。

## 驗收標準
- AC-O32-1：`baseTaskId`、`mutantsPathFor`、`branchId` 依「定義」接受一個小寫字母尾碼，`-fix` 輪次回到基底編號；不合格的輸入（非字串、空字串、含換行、大小寫或位數不對、`-fix0`、`-fix01`、路徑跳脫）一律回 null。
- AC-O32-2：字母尾碼的任務單走完既有工具：`acPrefix` 對 `T-025a`、`T-025b`、`T-025a-fix1` 回 `T25`；`parseTaskFile` 讀得到分支 `task/T-025a` 與 `AC-T25-n`；`lintTask` 不報 `TL-TITLE`；`scope-check` 允許清單內的檔與 `docs/reports/T-025a.md`，`docs/reports/T-025.md` 與清單外的檔仍是 `SC-OUT`；分支 `task/T-025` 對不到 `T-025a` 的任務單。
- AC-O32-3：沒有放寬其他形狀：`T-025A`、`T-025ab`、`T-25a`、`T-025-a`、`X-025`、`task/T-025ab`、`task/T-025a/x`、`task/T-025a-fix1`、`fix/T-025a` 都是 null。
- AC-O32-4（SRE）：`run-task-validate-id.sh` 依「定義」判斷；編號只經環境變數；`LC_ALL=C`；失敗訊息不含控制字元、不以 `::` 開頭、不超過 200 字元。
- AC-O32-5（SRE）：`run-task-pre-head.sh`、`run-task-post-check.sh`、`run-task-usage-limit.sh`、`taskcheck.sh` 接受 `T-025a`、`T-025a-fix1`、`task/T-025a`，仍拒絕 AC-O32-3 的壞值；`.github/` 底下每個含 `[TQOAP]` 的正規式都必須是「定義」兩式之一（不得留舊式）。
- AC-O32-6（SRE）：`claude-run-task.yml` 第一步是無 `if` 的 checkout，第二步是 Validate；`Task lint`、`Record branch head before Claude`、Claude 與所有用到編號的步驟都在 Validate 之後；`Notify`、`Upload run-task outcome` 仍是 `if: always()`；concurrency 群組與 artifact 名稱不變。
- AC-O32-7（SRE）：把 `Notify` 的 `run:` 原文抽出，在含真實 `.github/scripts` 的暫存目錄裡執行（假 `curl`、真 `jq`）：Validate 失敗的輸入（Task lint、Claude、Verify、Summary 被略過）送出恰好一次 POST，`event` 是 `claude-task-finished`、`outcome` 是 `failure`、`claude_outcome` 是 `skipped`、`task` 是 JSON 轉義後的原值；未設 `WEBHOOK_URL` 時結束碼 0 且不送；在沒有腳本的目錄執行必失敗（證明 checkout 必須在前）；全部被略過的輸入絕不得算成 `success`。
- AC-O32-8（SRE）：`claude-permission-check.mjs` 凍結 AC-O32-5、AC-O32-6 的靜態規則；新的測試接進 `ci.yml` 現有的測試步驟（不新增 job），並由 `tooling/o032.test.mjs` 包進 ac-coverage。
- AC-O32-9：突變必須被抓到：Validate 正規式退回舊式；尾碼改成大寫或多個字母；`-fix0` 重新允許；Validate 移到 checkout 前；checkout 加 `if`；`persist-credentials` 被移除；`Notify` 失去 `always()`；驗證腳本回顯原始值；任一腳本的分支式退回舊式；`baseTaskId` 忽略尾碼。削弱後仍通過任何測試，本 AC 失敗。
- AC-O32-10：本單新增或修改的檔案沒有未允許的 `|| true`、`continue-on-error`；驗證腳本失敗必須是非 0。
- AC-O32-11（SRE）：`docs/RUNBOOK.md` 派工段落用一句話寫明可接受的編號格式與驗證順序；[G3] PR 的「Actions 分鐘數影響」寫「無新增 job；Validate 失敗時多跑一次 checkout，約數秒」。

## 限制
- 只用既有工具與 Node 內建模組；不新增套件、不連網。
- Claude 不得修改 `.github/workflows/**`、`.github/scripts/**`。
- `task-id.test.mjs` 的暫存任務單寫在暫存目錄，不寫進 `docs/tasks/`；測試不得需要網路、Docker。
- 讀檔、搜尋一律用內建 Read／Grep／Glob 工具；不要用 Bash 的 `cat`、`grep`、`head`、`ls`、`sed`。
- 每一個 git 指令都是一次獨立的 Bash 呼叫，依序為：`git fetch origin`、`git switch -c task/O-032 origin/main`、`git add <明確檔案路徑…>`、`git commit -m "[Claude] O-032 …"`、`git push -u origin task/O-032`；每一次都不得含 `&&`、`;`、`|`、`2>&1` 或其他指令。

## 驗證方式
`pnpm check` 跑到通過；任務單不另列指令。

## 結束時
1. 在指定的分支上 commit 並 push，不得動 main。
2. 把結果寫到 `docs/reports/O-032.md`：完成摘要、變更檔案、測試結果、未完成事項、需要人類決定的問題。
3. 測試結果、權限被拒以 workflow 自動產生的摘要與 PR 觸發的 CI run 為準，報告不重貼。
