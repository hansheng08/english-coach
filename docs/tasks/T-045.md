## 介面
```ts
// apps/web/src/api/client.ts：ApiClient 加
//   listWeeklyMetrics(): Promise<Result<readonly WeeklyMetric[], AppError>>;   // weekly_metric view，取最後 12 列
//   listPracticeLog(from: PlanDate, to: PlanDate): Promise<Result<readonly PracticeLogDay[], AppError>>;
//   getEveningAnswer(id: EveningAnswerId): Promise<Result<EveningAnswerDetail, AppError>>;
//   audioSignedUrl(path: StoragePath): Promise<Result<string, AppError>>;      // audio bucket，3600 秒
// apps/web/src/features/growth/chart.ts（新增；純函式）
export function chartPoints(rows: readonly WeeklyMetric[], pick: (r: WeeklyMetric) => number | null, box: ChartBox): readonly (Point | null)[];
```
- **`PracticeLogDay`**（前端型別，`api/` 裡組好）：`planDate` 與當天的列；每列是 `{slot, step, status, summary}`，`status` 取當天該步驟的 `slot_checkin`（`completed`／`skipped`／沒有）。各步驟的摘要來源：晚上首答＝`evening_answer`（`kind = 'first'`）的題目與停頓＋贅詞；無稿重答＝`chunk_full_hit_count`／`chunk_target_count` 與加分（每個 +10）；早上跟讀＝當天 `shadow_attempt` 每句最後一次的正確率與語速平均；早上讀新聞＝當天計畫的類別；中午＝`card_review` 當天筆數與打卡的開始到完成分鐘數。缺資料的欄位不顯示，不猜。
- **`weekly_metric`**：讀 view 後轉 camelCase、用 `WeeklyMetricSchema` 解析；不合格 → `internal`（不默默略過）。不到 12 列時照實際列數畫。
- **曲線**（`growth.md` §1）：inline SVG、`role="img"`＋`aria-label` 一句總結；手機與電腦各一個 viewBox；null 的週不畫點、線斷開、表格寫「—」；Mastered 圖加 15、60 兩條 `gold-text` 虛線，講出率圖加 60% 虛線；每張圖下方 `<details>`「看每週數字」表格。
- **一次晚上練習**（`growth.md` §3）：題目卡、逐字稿卡（`audio_path` 不是 null 時用 `audio/player` 播 signed URL，並寫「錄音保存到 {`audio_expires_at` 的日期}（90 天），之後只剩文字。」；null 時只寫「錄音已超過 90 天，只保留文字」）、診斷（重用 T-039 的唯讀版）、Senior 版、右欄分數、講出清單、`ProviderMeta`。
- 路由：`/records/growth`、`/records/log`、`/records/log/:answerId`，放進 T-044 的「紀錄」分頁；`ApiClient` 照 §9.1.7（組成根注入 `fetch` 與 token、畫面經 `useApi()`、測試用 `makeTestApiClient`）。
