## 驗收標準
- **AC-T16-1**（§5.5 `loadGroqKey`）只讀 `GROQ_API_KEY`；沒有、空字串、只有空白 → `not_configured`（`provider: 'groq'`、`capability: 'stt'`、`message: 'missing env GROQ_API_KEY'`）；有值 → `ok`（**trim 後的值**；前後有空白或換行的金鑰照樣能用，`[redacted]` 遮蔽也用 trim 後的值，和 T-017b 同一條規則）。
- **AC-T16-2**（§5.7.1）`createGroqProvider` 回傳的物件 `id: 'groq'`、`tier: 'free'`、`displayName: 'Groq Whisper'`、`capability: 'stt'`；建立時不呼叫 `fetch`。
- **AC-T16-3**（§5.7.2）請求：`POST https://api.groq.com/openai/v1/audio/transcriptions`；標頭有 `Authorization: Bearer <apiKey>`、沒有自設的 `Content-Type`；body 是 `FormData`，欄位照 §5.7.2 表（`file` 的 MIME 與檔名依 `AudioPayload.format`；`model`、`language`、`response_format: verbose_json`；`timestamp_granularities[]` 只在 `wordTimestamps === true` 時有一個 `word`；`prompt` 只在 `opts.prompt` 有值時原樣送出）；沒有 `temperature`、`url` 欄位。金鑰不在網址裡。`fetch` 一律帶 `redirect: 'manual'`：不跟著轉址（金鑰標頭不會被送到 `Location` 指的網址），3xx 回應照 §5.7.4 表回 `unavailable`；`status` 是 0 的回應（`opaqueredirect`）也回 `unavailable`。
- **AC-T16-4**（§5.7.3）回應對應：`text` trim；`language: 'en'`、`provider: 'groq'`、`model: 'whisper-large-v3-turbo'`；`durationMs` 依序取 `duration`、`words`／`segments` 最大的 `end`、`0`；`wordTimestamps === true` 時 `timing: 'words'`，每個字 trim、空的跳過、毫秒照 §5.5 第 7 點、`confidence: null`；`false` 時 `timing: 'none'`。結果通過 `TranscriptSchema`。
- **AC-T16-5**（§5.7.3）要求了時間戳記、`text` 不是空的但 `words` 沒有或是空陣列 → `invalid_response`；`text` 與 `words` 都是空的 → `ok`、`words: []`；2xx 但不是 JSON 或結構不符 → `invalid_response`。
- **AC-T16-6**（v1.12 §5.7.4；ADR-018 決定 8）`classifyGroqError` 照表由上往下、用第一列符合的：408／504 → `timeout`；429＋`x-ratelimit-remaining-requests: 0` → `quota_exhausted`；429＋`isGroqDailyQuotaMessage(error.message)` 是 `true` → `quota_exhausted`；其他 429 → `rate_limited`；401／403 → `auth`；404 → `not_configured`（訊息含模型名稱）；422 → `invalid_response`；400、413、498、其他 4xx、3xx、5xx → `unavailable`（訊息含 HTTP 狀態與 `error.type`）。錯誤內容不是 JSON 時只依狀態判斷。`isGroqDailyQuotaMessage` 照 §5.7.4 表下的規則：片語 `per day`、`audio seconds` 不分大小寫、要有字邊界；縮寫 `RPD`、`ASD`、`ASH` 要大寫、要有字邊界（括號、冒號、空白都算邊界）；只看 `error.message`，不看 `error.type`、`error.code`。**不再**用「不分大小寫的子字串」（v1.0 的寫法會讓 `hash`、`crash` 命中 `ASH`）。
- **AC-T16-7**（§5.5 第 6 點）兩種 429 的 `retryAfterSec`：`retry-after`（大小寫不拘）是十進位秒數 → 無條件進位成整數；HTTP 日期、空字串、格式不符、沒有 → `null`。
- **AC-T16-8**（§5.5 第 2 點）`AbortController` 在 `opts.timeoutMs` 中止請求，回 `timeout`；`fetch` 不理會 signal 時也在 `timeoutMs` 回 `timeout`；`timeoutMs` 涵蓋讀取回應內容；`fetch` 丟出網路錯誤（不是自己中止的）→ `unavailable`。
- **AC-T16-9**（§5.5 第 3 點）任何 `ProviderError.message` 都不含 `apiKey` 字串（錯誤內容、例外訊息原樣帶出金鑰時換成 `[redacted]`）。
- **AC-T16-10**（§5.5 第 4 點）任何結果（成功、每一種錯誤、逾時）`fetch` 都剛好被呼叫一次。
- **AC-T16-11**（§5.5「沒有實測樣本」）依文件做的樣本放在 `groq/test/`，內容沒有 `gsk_` 開頭或其他金鑰樣子的字串；用到這些樣本的測試名稱含「未驗證」。

## 測試的寫法
- 只用注入的假 `fetch`（每個 adapter 在自己的 `groq/test/` 寫一個，記錄網址、標頭、`FormData` 欄位）；不連網、不讀環境變數、不 import `gemini/` 的測試工具。
- 逾時一律用 `vi.useFakeTimers()`＋`vi.advanceTimersByTimeAsync`，不寫真實等待、不用很小的真實 `timeoutMs` 等時間經過；每個測試結束還原計時器。
- 測試裡的金鑰一律是假字串（例如 `test-key`），不得像真的金鑰。
- 樣本照 §5.7.3、§5.7.4 與 ADR-015 參考網址的文件範例自己寫，不貼任何真實回應。

- adapter 不檢查檔案大小（5 MB 由 T-037 的端點檢查，§5.7.2）；沒有預設 `prompt`（`EVENING_STT_PROMPT` 屬 T-037）。
- **QA 擁有的檔案不碰**：不得新增、修改、刪除或改名任何 `**/*.qa.test.ts` 與 `docs/qa/` 下的檔案。`docs/qa/**` 不列進「範圍外」：scope-check 先比對範圍外，列進去會讓 QA 自己的 commit 被判違規。既有的 QA 探針要照樣通過。

## 不在本單
- `wiring.ts` 與 registry 接線（第一張需要供應商的端點單建立，§5.5 檔案表）。
- `EVENING_STT_PROMPT`、端點的 5 MB 上限（T-037）。
- 真實回應的驗證（A-002：贅詞保留效果、`duration` 是否存在、429 的實際內容）；格式不同時另開修正單。

## 驗證方式
`pnpm check` 跑到通過；任務單不另列指令。標「未驗證」的測試只證明「照文件實作」，真實格式由 A-002 驗證；報告照實寫「沒有真實樣本」。

## 結束時
1. 在指定的分支上 commit 並 push，不得動 main。
2. 把結果寫到 docs/reports/T-016.md：完成摘要、變更檔案、測試結果、未完成事項、需要人類決定的問題。
3. 測試結果、突變結果、權限被拒以 workflow 自動產生的摘要與 PR 觸發的 CI run 為準，報告不重貼。
