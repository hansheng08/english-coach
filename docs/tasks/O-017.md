## 背景（開始前先讀）
- `docs/tasks/O-016.md` 的「actions-usage 規則」與 `docs/RUNBOOK.md` §6.5：本單只加重試，其餘輸出、門檻、規則代碼都不變。

- `gh` 的 HTTP 錯誤格式（box 的 gh 2.103.0 實測 404）：exit 1、stderr 為 `gh: <訊息> (HTTP <三位數>)`、stdout 是錯誤 JSON。網路中斷、逾時之類沒有 HTTP 回應的失敗，stderr 沒有 `(HTTP nnn)`。
- 既有測試 `tooling/actions-usage.test.mjs`：TC-1～TC-15、TC-22（AC-O16-1～4、6）；CLI 測試用 `GH_BIN` 指向的假 gh（`FAKE_GH_ROUTES` 檔決定回應）。

## 目標
`gh api` 遇到 5xx 或暫時性錯誤時，同一個呼叫最多試 3 次、中間退避；4xx 與其他錯誤不重試。重試用完仍失敗就照舊 fail-closed（exit 1、stdout 空）。讓每天的 routine 不會因為一次偶發 502 就回報「用量查詢失敗」。

## 介面
```js
// tooling/actions-usage.mjs 新增的匯出常數；CLI 參數與輸出 JSON 不變
export const GH_MAX_ATTEMPTS = 3;    // 同一個 gh api 呼叫最多 3 次（含第一次）
export const GH_RETRY_BASE_MS = 1000; // 第 n 次重試前等 base × 2^(n−1)：1 秒、2 秒
// 環境變數 ACTIONS_USAGE_RETRY_BASE_MS：覆寫 base（非負整數，測試設 0）
```

### 重試規則
- 每個 `gh api` 呼叫（runs 與 jobs、每一頁）各自計次；成功後下一個呼叫重新從第 1 次算。
- 判斷依據只有 `gh` 的 exit code 與 stderr 裡的 `(HTTP nnn)`（取最後一個）：
  - **可重試**：狀態碼 500～599；或 exit 1 且 stderr 沒有任何 `(HTTP nnn)`（視為網路／逾時等暫時性錯誤）。
  - **不重試，立刻失敗**：狀態碼 400～499（含 403、429）；exit 不是 0 也不是 1 且沒有狀態碼；`gh` 無法執行（spawn 錯誤）；exit 0 但輸出不是 JSON。
- 等待：第 2 次前等 base、第 3 次前等 2 × base；最後一次失敗後不再等。
- 重試成功：結果與第一次就成功完全相同（exit 0、stdout 一行 JSON、stderr 空）；重試過程不寫 stdout、不寫 stderr。
- 重試用完或遇到不重試的錯誤：exit 1、stdout 空、stderr 一行 `usage: API …`，訊息含路徑、已試次數、最後的 exit code 與狀態碼（沒有就寫「無」）。已收到的頁一律不輸出。
- `ACTIONS_USAGE_RETRY_BASE_MS` 不是非負整數（例如 `-1`、`1.5`、`abc`、空字串）→ `usage: USAGE …`、exit 1、stdout 空，且不呼叫 gh；沒設 → 1000。

## 驗收標準
- AC-O17-1：5xx 會重試；同一呼叫最多 3 次，第 2、3 次成功時輸出與從未失敗完全相同，runs 與 jobs 查詢都適用。
- AC-O17-2：exit 1 且 stderr 沒有 `(HTTP nnn)` 視為暫時性錯誤，同樣重試。
- AC-O17-3：4xx 不重試，第一次就以 `API` 失敗。
- AC-O17-4：spawn 錯誤、exit 不是 0／1 且沒有狀態碼、exit 0 但不是 JSON 都不重試。
- AC-O17-5：重試用完仍失敗 → exit 1、stdout 空、stderr `usage: API`，含次數與最後狀態碼；不輸出部分 JSON、不呼叫第 4 次。
- AC-O17-6：退避依 `ACTIONS_USAGE_RETRY_BASE_MS`（預設 1000）為 base、2 × base；值不合法 → `USAGE` 失敗且不呼叫 gh。
