## 背景（開始前先讀）
- `docs/tasks/O-016.md` 的「actions-usage 規則」、`docs/tasks/O-017.md` 的「重試規則」、`docs/RUNBOOK.md` §6.5。本單只改 `billedMinutes`／`summarize` 對 skipped job 的處理；CLI 參數、輸出 JSON 欄位、規則代碼、重試都不變。
- 現況（main 上的 `tooling/actions-usage.mjs`，含 O-017）：`summarize` 對 `status === "completed"` 的 job 一律呼叫 `billedMinutes`；`billedMinutes` 要求 `started_at`、`completed_at` 都是合法時間且 `completed_at ≥ started_at`，否則 `DATA` 失敗。jobs API 的 `conclusion` 欄位目前完全沒有讀。
- 實測：O-017 的兩次 box 實跑都 exit 1，stderr `usage: DATA job 的 completed_at 早於 started_at`。GitHub 對被略過（`conclusion: "skipped"`）的 job 常回 `started_at` 比 `completed_at` 晚 1～10 秒；有多個 skipped job（見 RUNBOOK §6.5 實測），全部是 skipped（docs／light 模式略過的 `check`、`bundle`、`db`、`e2e`，以及沒有 @claude 的 `claude`）。box 抽查 11/25 的 skipped job：`status` 都是 `completed`、時間都有值、`labels` 是 `ubuntu-latest`。
- 既有測試 `tooling/actions-usage.test.mjs`：O-016 的 TC-1～TC-15、TC-22（AC-O16-1～4、6）與 O-017 的 TC-1～TC-12（AC-O17-1～7）。單元測試用檔內的 `job(sec, over)` 產生 job；CLI 測試用 `GH_BIN` 指向的假 gh。既有 fixture 都沒有 `conclusion` 欄位。

## 目標
被略過的 job 不花計費分鐘，GitHub 給的時間也不可靠：`status === "completed"` 且 `conclusion === "skipped"` 的 job 一律算 0 分鐘、不驗時間。其他 job 的檢查照舊 fail-closed。讓每天的 routine 不再因為 skipped job 的時間顛倒而回報「用量查詢失敗」。

## 介面
```js
// tooling/actions-usage.mjs；簽名與回傳形狀不變，只多讀 job.conclusion
export function billedMinutes(job) // → { minutes, rawSeconds } | { rule, error }
// status === 'completed' 且 conclusion === 'skipped' → { minutes: 0, rawSeconds: 0 }
```

### skipped 規則
- 判斷：`job.status === "completed"` 且 `job.conclusion === "skipped"`（字串全等；大小寫不同、`null`、缺欄位、其他值都**不是** skipped）。
- skipped 的 job：`billedMinutes` 回 `{ minutes: 0, rawSeconds: 0 }`，不看 `started_at`、`completed_at`（顛倒、`null`、缺欄位、不是合法時間都不失敗）。
- `labels` 檢查不變：skipped 的 job 一樣要有 `ubuntu-` 開頭的標籤，否則 `RUNNER` 失敗（實測 skipped job 都有 `ubuntu-latest`；放寬不在本單）。
- 歸日：`started_at` 是合法時間 → 照舊依它歸日、計入該日與週期的 `jobs`、`runs` 與 `by_workflow`（分鐘 0）；`started_at` 是 `null`、缺欄位或不是合法時間 → 不歸任何一天、不計入 `day` 或 `cycle` 的任何數字，也不失敗。
- `status` 不是 `"completed"` 的 job 照舊算 `in_progress_jobs`，不論 `conclusion`。
- 不是 skipped 的 completed job：時間檢查與錯誤訊息完全照舊（顛倒、`null`、缺欄位、不是合法時間 → `DATA`，CLI exit 1、stdout 空）。
- job 的 `conclusion` 不在 `fetchAll` 的必填欄位裡（`validJob` 不變）。

## 驗收標準
- AC-O18-1：completed＋skipped 的 job 算 0 分鐘、`rawSeconds` 0，時間顛倒、`null`、缺欄位、不合法都不失敗；時間正常但相差數十秒的 skipped job 也是 0 分鐘。
- AC-O18-2：不是 skipped 的 completed job（`conclusion` 為 `success`、`failure`、`cancelled`、`null`、缺欄位、`"Skipped"`）時間顛倒或不合法 → 照舊 `DATA` 失敗；CLI exit 1、stdout 空、stderr `usage: DATA`。
- AC-O18-3：skipped job 依合法的 `started_at` 歸日並計入 `jobs`、`runs`；沒有合法 `started_at` 的 skipped job 不計入任何數字。
- AC-O18-4：skipped job 的 `labels` 檢查不變（非 ubuntu → `RUNNER`）；未完成的 job 不論 `conclusion` 都算 `in_progress_jobs`。
- AC-O18-5：CLI 用假 gh 跑含 skipped 顛倒時間 job 的資料 → exit 0、stdout 一行 JSON，分鐘數與移除那些 job 時相同。
- AC-O18-6：O-016（TC-1～TC-15、TC-22）與 O-017（TC-1～TC-12）的既有測試斷言不改、全部通過；import 只用 `node:` 與 `./`、沒有吞錯。
