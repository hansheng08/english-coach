## 介面
照 ARCHITECTURE §11.3.2 的簽章與名稱實作（`news.ts` 的 3 個常數、2 個型別、`NewsChunkSchema`、`NewsArticleContentSchema`、`newsWords`、`stripBreaks`、`chunkAppearsIn`、`NewsJudgeResponseSchema`、`NewsRewriteResponseSchema`；`rewrite.ts` 的下列 3 項），並從 `packages/contracts/src/index.ts` 匯出 `news.ts` 的全部公開名稱：
```ts
export type RewriteDeps = { readonly llm: LlmProvider; readonly model: LlmModelId };
export function createCategoryJudge(deps: RewriteDeps): IngestDeps['judge'];
export function rewriteArticle(deps: RewriteDeps, candidate: Candidate): Promise<Result<NewsArticleContent, AppError>>;
```
行為一律照 §11.3.3～§11.3.5，本單不重述。只補下列 TechLead 決定（§11.3 沒有固定的實作細節）：
- **分隔標記**：判定與改寫的 `prompt` 用同一組固定的開始／結束標記包住正文（例如 `<<<ARTICLE>>>`／`<<<END ARTICLE>>>`），定義成 `rewrite.ts` 內的常數；兩段 prompt 也是 `rewrite.ts` 內的常數 `JUDGE_PROMPT`、`REWRITE_PROMPT`（§11.3.4），可以 export 給同資料夾的測試用。
- **假 LLM**：測試用的假 `LlmProvider` 放在 `supabase/functions/_shared/news/test/fake-llm.ts`：記錄每次 `generate` 收到的請求與次數；依測試設定回傳原始 JSON 物件時，用請求帶的 `schema` 做 `safeParse`，失敗回 `err` 且 `kind` 是 `invalid_response`（模擬 adapter，但**不重試**）；也能直接回指定的 `ProviderError`。
- **樣本**：改寫樣本自己寫（不用真的新聞原文），放在 `supabase/functions/_shared/news/test/` 的新檔案；至少包含 TASKS 列的四種：合格、字數不足、chunk 數錯、類別不符。
- `NewsRewriteResponseSchema` 用 `.transform` 或另寫函式，由你決定（§11.3.4 已授權），寫進報告的「設計決定」。

## 驗收標準
- **AC-T23-1**（AC-02；§11.3.2、ADR-013 決定 3）`newsWords`、`stripBreaks` 與 3 個常數照 §11.3.2；`newsWords` 和 `html.ts` 的 `wordCount` 在同一份沒有「/」的文字上算出相同數字。
- **AC-T23-2**（§11.3.2）`chunkAppearsIn` 照 §11.3.2：忽略「/」、字間對應任意空白、regex 特殊字元照字面、前後不緊接字母／數字／撇號／連字號、不分大小寫。
- **AC-T23-3**（AC-05；§11.3.3）`NewsArticleContentSchema` 的句子規則 S1～S4 各自成立：不合格的輸入被拒，剛好在邊界上的輸入通過。
- **AC-T23-4**（AC-02；§11.3.3）全文規則 T1、T2：`rewritten_text` 必須等於各句去掉「/」後以一個空白接起；`newsWords` 字數 250～300（含兩端）。
- **AC-T23-5**（AC-02；§11.3.3）chunk 規則 C1～C4：剛好 5 個且（小寫、壓空白後）不重複、2～6 字且符合格式、`meaning_zh` 1～30 字元含漢字、`sentence_index` 在範圍內且 chunk 出現在該句；物件不 strict，多出的鍵被去掉。
- **AC-T23-6**（§11.3.4）`NewsRewriteResponseSchema`：原始形狀照 §11.3.4；轉換做 trim、壓空白、`’`／`‘` 換成 `'`，`sentence_index` 取第一個符合的句子，`rewritten_text` 依 T1 產生，結果再經 `NewsArticleContentSchema`，任一規則失敗都讓整個 schema 失敗。`NewsJudgeResponseSchema` 是 `{ category_match: boolean }`。
- **AC-T23-7**（Q-16；§11.3.4、§11.3.5）`createCategoryJudge` 送出的請求：`model` 是 `deps.model`、`system` 是 `JUDGE_PROMPT`（含三類定義，`software` 寫明主題主要是 AI 時判 `false`）、`prompt` 依序含類別代號、標題、分隔標記內的正文前 300 字（第 301 字之後不出現）、`schema` 是 `NewsJudgeResponseSchema`、`maxOutputTokens` 64、`timeoutMs` 8000；回 `ok(category_match)`；`false` 不重試；`err` 原樣回傳；每次判定只呼叫 `generate` 1 次。
- **AC-T23-8**（AC-02；§11.3.4、§11.3.5）`rewriteArticle` 送出的請求：`model` 是 `deps.model`、`system` 是 `REWRITE_PROMPT`（含 §11.3.4 列出的 4 項要求）、`prompt` 含標題與分隔標記內的正文前 2,000 字、`schema` 是 `NewsRewriteResponseSchema`、`maxOutputTokens` 2048、`timeoutMs` 30000；成功回 `NewsArticleContent`；任何 `err` 原樣回傳；每次只呼叫 `generate` 1 次（CLAUDE.md 第 18 條）。
- **AC-T23-9**（AC-02、AC-05；TASKS T-023 測試欄）四種樣本經假 LLM：合格 → `ok`；字數不足、chunk 數錯 → `err invalid_response`；類別不符 → 判定 `ok(false)`。
- **AC-T23-10**（CLAUDE.md §5 第 7 條；§11.3.3、§11.3.4）不記內容：`rewrite.ts` 沒有任何 log 呼叫；schema 的 issue 訊息與 `rewrite.ts` 回傳的錯誤訊息不含文章、句子或 chunk 的文字。
- **AC-T23-11**（ADR-008 修訂 6）dependency-cruiser 有第 20 條（`_shared/news/**` 正式程式不得 import `_shared/providers/**`、`_shared/db/**`），用修訂 6 的 4 個範例做 fixture 測試；真實程式樹 `pnpm arch` 0 違規。
- **AC-T23-12**（CLAUDE.md §7）測試不連網：只用注入的假 `LlmProvider`；全域 `fetch` 被替換成一呼叫就失敗的函式，且呼叫次數為 0。

- 不連網、沒有金鑰：只用假 `LlmProvider`；樣本自己寫，不放真實新聞原文。
- 本單不涵蓋（**未驗證**，§11.3.6）：真實模型能否穩定產出合格格式、token 數與延遲、判定只看前 300 字的準確度、15 RPM 下的 429。
