## 背景

## 目標
在 T-018 之前落地守衛與 CI 接線：`bundle` 以 `VITE_DATA_MODE=mock` 建置；mock 模式下出現任何 `VITE_SUPABASE_*`（含空字串），或缺少／非法的 `VITE_DATA_MODE`，都必須失敗。`has_web=false` 時 `bundle` 仍正確略過。

## 介面

### 守衛放哪裡（雙層；憲章 v7 §5）
1. **工具層（本單，Claude 寫）**：`tooling/data-mode-guard.mjs`（測試在 `tooling/data-mode-guard.test.mjs`）。`check` 的 `pnpm test` 已包含 `tooling/**/*.test.mjs`，不依賴 `apps/web`。
2. **產品層（T-018，本單不改 `apps/`）**：ARCH 規定 `vite.config.ts` 在沒設／值不對，或 mock 帶 `VITE_SUPABASE_*` 時讓建置失敗。T-018 的 `validateBuildEnv` 必須與本模組規則等價（可 import 本模組，或同等實作）。本單不建立 `apps/web`。
3. **CI 接線（SRE，Claude 不做）**：在既有 `bundle` job 的建置步驟設 `VITE_DATA_MODE=mock`、不設任何 `VITE_SUPABASE_*`；在 `pnpm build` 之前跑 `node tooling/data-mode-guard.mjs`。不改 job 的 `if`（必須仍要求 `has_web == 'true'`），不改 `has_web` 偵測，不新增 job，不調高 `timeout-minutes: 10`，不改 `ci-budget.json`。

為何兩層都要：Cloudflare Pages（O-022）與本機建置不走 `bundle` job，只靠 Vite 守衛。CI 預檢可在 `vite.config.ts` 漏接時仍擋下，也可擋住 Actions／org 環境被注入的 `VITE_SUPABASE_*`。CI 必須把 `VITE_DATA_MODE` 設成 `mock`，否則 T-018 之後 `bundle` 必紅。

### 規則
```js
// tooling/data-mode-guard.mjs
// assertDataModeEnv(env) → { ok: true, mode: 'mock' | 'supabase' } | { ok: false, reason }
// CLI：node tooling/data-mode-guard.mjs
// 讀 process.env；成功 exit 0；失敗 exit 1，reason 寫到 stderr，不輸出變數值
export function assertDataModeEnv(env)
```
- 「鍵存在」＝出現在傳入的 env 物件（空字串、只含空白也算；未設定的鍵不算）。
- `VITE_DATA_MODE` 沒有，或不是恰好 `mock`／`supabase`（含 `MOCK`、`staging`、空字串）→ 失敗。沒有預設值。
- `mock`：任何名稱以 `VITE_SUPABASE_` 開頭的鍵（含 `URL`、`PUBLISHABLE_KEY`、`ANON_KEY` 及尚未使用的名稱；值非空或空字串）→ 失敗。
- `supabase`：`VITE_SUPABASE_URL` 與 `VITE_SUPABASE_PUBLISHABLE_KEY` 必須存在且非空、不可只含空白。CI `bundle` 只用 mock，job 不得設這兩個變數。
- 失敗理由可寫鍵名，禁止寫出變數值。不得先去掉違規鍵再當通過。

## 驗收標準
- AC-O23-1：`VITE_DATA_MODE=mock` 且沒有任何 `VITE_SUPABASE_*` → `ok`、`mode` 為 `mock`，CLI exit 0。`supabase` 且兩個必填非空（測試用假值）→ `ok`、`mode` 為 `supabase`。
- AC-O23-2：`mock` 加上非空的 `VITE_SUPABASE_URL` → 失敗；`mock` 加上空字串的 `VITE_SUPABASE_URL`／`VITE_SUPABASE_PUBLISHABLE_KEY`／其他 `VITE_SUPABASE_*` → 失敗。stderr 不含變數值。
- AC-O23-3：`VITE_DATA_MODE` 缺漏、空字串或非法值（`MOCK`、`staging`）→ 失敗，不得當成 mock。`supabase` 缺必填或必填為空／空白 → 失敗。
- AC-O23-4：守衛與測試不依賴 `apps/web` 是否存在。解析目前（及接線後）的 `ci.yml`／`ci-budget.json`：`bundle` 的 `if` 仍要求 `has_web == 'true'`，`timeout-minutes` 仍為 10，`ci.yml` job 數 ≤ 7，`max_jobs['ci.yml']` 仍為 7。
- AC-O23-5：本單新增或修改的檔案沒有未允許的 `|| true`、`continue-on-error`。env 不是物件、或無法判斷時必須失敗，不得當成通過。
- AC-O23-6：突變必須被抓到：把空字串當成未設定、缺 `VITE_DATA_MODE` 時改預設 `mock`、只擋非空的 supabase 變數、接受 `MOCK` 這種大小寫。上述削弱若仍能通過測試，本 AC 失敗。
