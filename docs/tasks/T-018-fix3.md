## 介面
- **E2E 伺服器（D1）**：`webServer` 用 Playwright 的 `env` 設定 `VITE_DATA_MODE=mock`，讓 build 與 preview 兩個程序都拿到它；`command` 裡不再寫 `VITE_DATA_MODE=`。不設任何 `VITE_SUPABASE_*`。資料模式的檢查不放寬：`apps/web/vite.config.ts`、`apps/web/vite.data-mode.ts`、`tooling/data-mode-guard.mjs` 不改；不得依 `command`、`isPreview` 或其他條件略過檢查。
- **焦點測試（D2）**：TC-36 的兩個焦點測試在第一次按 Tab 前，先用 Playwright 的 web-first 斷言等到「登入」按鈕可見；深色那一個也要先斷言按鈕已取得焦點，再比對外框顏色。不用 `waitForTimeout` 或任何固定等待，不設 `retries`、不加 `test.slow`／`test.fixme`，原有的斷言（外框寬 2px、位移 2px、顏色、hover 底色）一個都不改。
- **css-literals（D3、低）**：只檢查宣告的值，值從 `:` 之後到同一層的 `;` 或 `}` 為止，可以跨行；報告字面值所在的那一行，同一行只報一次；巢狀在 `@media` 等 at-rule 的區塊裡照樣檢查。選擇器（含 `:not(#…)`、`#id`）與 at-rule 的前導（例如 `@media (min-width: 900px)`）不檢查。掃描範圍、色碼與 `rgb(`／`rgba(`／`hsl(`／`hsla(` 的判斷、先去註解且行號不變、`tokens.css` 不掃，都照原單。
- **tokens-css（低）**：輸出順序照 `tokens.json` **原文**裡鍵出現的順序（含 `"10"`、`"2"` 這類鍵，任何一層都一樣）；同一物件裡重複的鍵 → 失敗（攤平後名稱重複，規則 4）。群組或子類別去掉 `$` 鍵後沒有任何鍵 → 失敗，原因寫出路徑（幕僚長決定：不默默略過，同規則 2 的理由）。失敗時照原單：stdout 空、stderr 寫原因、exit 1。只用 Node 內建模組。
