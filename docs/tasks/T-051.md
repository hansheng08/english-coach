> 名詞
> - **品牌型別（branded type）**：結構和 `string`／`number` 一樣，但型別系統不讓它們互相混用（例如 `CardId` 不能當 `AnswerId` 用）。只能由 zod schema 或指定的建立函式產生。
> - **`Result<T, E>`**：成功回 `{ ok: true, value }`、失敗回 `{ ok: false, error }`，用回傳值表示錯誤，不丟例外。
> - **workspace 套件**：pnpm 把 `packages/contracts` 當成名叫 `@english-coach/contracts` 的套件，其他套件用 `workspace:*` 依賴它，不經過 npm。
> - **lockfile 變更**：`pnpm-lock.yaml` 記錄實際安裝的版本；新增依賴一定會改它。

// packages/domain/package.json

  "exports": { ".": "./src/index.ts" },

### B. 實作 §5.0 的注意事項
- **只照 §5.0 寫**。§5.0 沒寫清楚的地方（例如某函式的邊界行為）不要自己決定：寫進報告「需要人類決定的問題」，該項用最保守的寫法並在測試名稱標 `UNDECIDED`。
- **已知缺口**：§5.0.4 錯誤碼對照表中 `news_unavailable` 的 HTTP 狀態與「可重試」是「（不回前端）／—」，但 `httpStatusOf` 的回傳型別要求每一種 `kind` 都有值。**開始實作前先看 main 上的 ARCHITECTURE**：若 Architect 已補上，就照寫；若仍沒有，**停下寫報告**，不要自己挑一個數字。
- `Result` helper 的行為以 §5.0.2 的註解為準：`all` 回第一個 `err`；`tryCatch`／`tryCatchAsync` 只用 `try/catch`，把例外交給 `onThrow`。
- `httpStatusOf`、`isRetryable` 用 `switch`＋`const unreachable: never = x; return unreachable;`（CLAUDE.md §6）。
- `parseWav16kMono` 檢查：RIFF/WAVE 標頭、PCM 格式、16-bit、16 000 Hz、單聲道、長度 ≤ `maxDurationMs`（預設 30 000）；不符就回 `err({ kind: 'validation', ... })`。只有 `audio.ts` 可以 `as Wav16kMono`；只有 `ids.ts` 可以 `as Ntd`。
- 跨網路的型別一律 `z.infer`，不手寫第二份（CLAUDE.md §6）。
- 相對 import 一律寫 `.ts`（ADR-009；第 13 條會擋）。contracts 自己的測試引用 `/testing` 時，優先用 `@english-coach/contracts/testing`（套件自我引用）；如果解析不到，用 `../test/index.ts` 並在報告說明。

### C. dependency-cruiser
- 只把 `TEST` 換成修訂 2 的 regex；10 條規則的名稱與其他條件不變（修訂 2 決定 4：不新增規則）。
- 確認 `@english-coach/contracts` 在真實專案中解析為 `packages/contracts/src/index.ts`（`preserveSymlinks` 維持預設 `false`）；在報告貼 `pnpm exec depcruise --config .dependency-cruiser.cjs --output-type text packages` 中相關的幾行。

### D. ESLint 與範例
- `no-restricted-imports` 與 `no-restricted-syntax` 一個檔案只會套用最後一個符合的設定：每個路徑區塊都要包含**全部**適用的 patterns／selectors（網址前綴、跨套件、副檔名；`as unknown as`、`Deno.env`、domain 禁令、品牌型別 `as`），並用測試證明合併後每一項仍有效（第 4 節最後幾列）。
- 規則 12、13 的 regex 照 ADR-008 修訂 2 決定 4 原文；規則 14 的型別名稱清單與允許檔案照決定 5 原文。
- 範例無法解析 `@english-coach/*` 時（`tooling/fixtures/arch/` 沒有 workspace 連結），可以在 `tooling/fixtures/arch/tsconfig.json` 用 `paths` 對應到範例內的 `packages/contracts/src/index.ts`、`packages/contracts/test/index.ts`，並在測試裡把它傳給 dependency-cruiser；做不到就停下寫報告，不放寬規則。
- `vitest.config.ts` 的 `include` 加上 `*.test.tsx`（修訂 2：`.test.tsx` 是測試）；`*.test-d.ts` 不需要被 Vitest 執行（由 `tsc -b` 檢查）。

## 驗證方式

### 1. 執行期單元測試（contracts，至少要有）
| # | 對象 | 案例 |
|---|---|---|
| 1 | `ok`／`err`／`isOk`／`isErr` | 形狀與判斷 |
| 2 | `map`／`mapErr`／`andThen`／`unwrapOr` | 成功與失敗兩條路各一 |
| 3 | `all` | 全部成功回陣列；有兩個 `err` 時回**第一個** |
| 4 | `tryCatch`／`tryCatchAsync` | 函式丟例外 → `err(onThrow(cause))`；正常 → `ok` |
| 5 | `httpStatusOf` | `APP_ERROR_KINDS` 18 項逐項對照錯誤碼對照表（表格驅動，一項一個測試名稱） |
| 6 | `isRetryable` | 同上 |
| 7 | `toApiErrorBody` | 每種 `kind` 一個樣本，輸出通過 `ApiErrorBodySchema.safeParse`；`retryable` 等於 `isRetryable`；`retryAfterSec: null` 不出現在輸出 |
| 8 | `parseWav16kMono` | 16 kHz 單聲道 16-bit 1 s → `ok`；8 kHz、雙聲道、> 30 s、非 RIFF 各回 `err` 且 `kind === 'validation'`；`maxDurationMs` 參數生效（測試用的 WAV 由測試程式在記憶體中組出，不放二進位檔） |
| 9 | `addNtd`／`subNtdFloor0` | 加法；相減小於 0 時回 0 |
