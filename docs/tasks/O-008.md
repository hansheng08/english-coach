## 目標
新增三支只用 Node 內建模組的檢查腳本：`task-lint`（任務單格式）、`scope-check`（分支變更只能落在任務單檔案範圍）、`ac-coverage`（每個 AC、TC 編號都有通過的測試），全部 fail-closed，並以 Vitest 測試證明正面、負面與邊界行為。

## 介面
共用解析模組 `tooling/task-file.mjs` 與三支 CLI；每支 CLI 同時 export 純函式供測試呼叫。
```ts
type Finding = { file: string; line: number; rule: string; message: string };
type TaskFile = { id: string; path: string; text: string };
type ParsedTask = { id: string; branch: string | null; acIds: string[]; tcRows: Array<{ tc: string; acs: string[] }>; allow: string[]; deny: string[] };
export function parseTaskFile(task: TaskFile): ParsedTask;                       // task-file.mjs
export function acPrefix(id: string): string;                                     // task-file.mjs："T-023"→"T23"、"T-012-fix1"→"T12"、"O-008"→"O8"
export function matchGlob(pattern: string, path: string): boolean;                // task-file.mjs
export function lintTask(task: TaskFile): Finding[];                              // task-lint.mjs
export function checkScope(o: { branch: string; tasks: TaskFile[]; changed: string[] }): Finding[];   // scope-check.mjs
export function checkCoverage(o: { branch: string; tasks: TaskFile[]; results: unknown }): Finding[]; // ac-coverage.mjs
```
CLI（工作目錄為 repo 根目錄；`--tasks-dir` 預設 `docs/tasks`）：
```text
node tooling/task-lint.mjs <task.md> [<task.md> ...]
node tooling/scope-check.mjs --branch <name> --changed <file-list.txt> [--tasks-dir <dir>]
node tooling/ac-coverage.mjs --branch <name> --results <vitest.json> [--tasks-dir <dir>]
```
輸出（逐字固定）：通過時 stdout 每個目標一行 `<tool>: OK <目標>`，exit 0。失敗時 stderr 每個 Finding 一行 `<tool>: FAIL <file>:<line>: <rule>: <message>`，最後一行 `<tool>: <N> error(s)`，exit 1。`<tool>` 為 `task-lint`／`scope-check`／`ac-coverage`。參數錯誤、檔案讀不到、JSON 解析失敗、未知選項一律 exit 1（rule `USAGE` 或 `INPUT`），不得有 exit 0 以外的「通過」。

### task-lint 規則（rule id：條件 → 失敗）
- `TL-TITLE`：第 1 行不是 `# <編號>：`，或編號與檔名（去掉 `.md`）不同。
- `TL-RULES`：第一個 `## ` 標題之前沒有以 `> ## ⚠️ 強制工作規則` 開頭的行，或其後引用區塊沒有依序各出現一次的 `> 1.`～`> 12.`。
- `TL-SECTION`：缺少以下任一個二級標題（以標題開頭比對）：`## 分支`、`## 背景`、`## 目標`、`## 介面`、`## 驗收標準`、`## 測試案例`、`## 檔案範圍`、`## 限制`、`## 驗證方式`、`## 結束時`。
- `TL-HEADING`：任何標題行（`#` 開頭）含「特別規則」或「突變表」。
- `TL-LINES`：全文超過 250 行。
- `TL-FENCE`：程式碼區塊未關閉。區塊開關行＝行首（最多 3 個空白後）為三個以上反引號或波浪號的行。
- `TL-BLOCK-SIZE`：單一區塊內容超過 15 行；`TL-BLOCK-TOTAL`：所有區塊內容合計超過 40 行（不含開關行）。
- `TL-SQL`：區塊語言標記為 `sql`、`pgsql`、`plpgsql`、`psql`（不分大小寫）。
- `TL-CODE`：任何區塊（不論語言）內容符合下列任一正規式：`\breturn\s`、`=>\s*\{`、`\bif\s*\(`、`\bfor\s*\(`、`\bwhile\s*\(`、`\bdescribe\s*\(`、`\bit\s*\(`、`\btest\s*\(`、`\bexpect\s*\(`、`\binsert\s+into\b`（不分大小寫）、`\bcreate\s+(table|function|policy|index|view|trigger|schema|extension|or)\b`（不分大小寫）。
- `TL-PHRASE`：全文（含區塊外）出現禁用詞。清單在本單以「・」分隔字元書寫，以免本單自己觸發；實作時比對去掉「・」後的連續字串：照・抄、逐字・寫出、逐位・元組、逐字・照貼、自核・數字。
- `TL-AC`：`## 驗收標準` 一節沒有任何 AC 定義，或 AC 定義重複，或該節出現其他任務前綴的 `AC-<字母><數字>-<數字>`。AC 定義＝本節列表項（`- ` 或 `- [ ] ` 開頭）中第一個 `AC-<前綴>-<數字>`（前綴＝`acPrefix(編號)`）；列表項內其他位置的 AC 編號只是引用，不算定義。
- `TL-TC`：`## 測試案例` 一節沒有表頭為 `| TC | 對應 AC | 情境 | 輸入 | 預期輸出／錯誤 |` 的表格；或資料列的 TC 欄不是 `TC-<數字>`、TC 重複、對應 AC 欄為空或引用未定義的 AC；或有 AC 沒有出現在任何資料列。
- `TL-SCOPE`：`## 檔案範圍` 一節沒有 `### 要做` 子標題，或其下沒有任何以反引號路徑開頭的列表項。

### 檔案範圍與分支的解析（scope-check、ac-coverage 共用）
- 分支：`## 分支` 一節中第一個反引號內容。對 `--branch X`，任務集合＝`--tasks-dir` 下所有分支等於 X 的任務單（例如本體與 `-fix1` 修正單）；集合為空 → `SC-NOTASK`／`CV-NOTASK`。
- 允許清單：`### 要做` 與 `### 其他角色（Claude Code 不改）` 底下每個列表項的第一個反引號內容；另隱含允許 `docs/reports/<編號>.md` 與 `docs/qa/mutants/<編號>.json`（每個任務集合中的編號）。禁止清單：`### 範圍外` 底下每個列表項的第一個反引號內容。
- glob：`**` 可跨 `/`（含零層），`*`、`?` 不跨 `/`，其餘字元逐字比對；不支援結尾 `/` 縮寫。

## 驗收標準
- **AC-O8-1** task-lint 正面：符合全部規則的任務單 exit 0、stdout 為 `task-lint: OK <path>`；本 repo 的 `docs/tasks/O-008.md` 本身也 exit 0。
- **AC-O8-2** task-lint 結構：`TL-TITLE`、`TL-RULES`、`TL-SECTION`、`TL-HEADING` 各自在對應的壞輸入上 exit 1，stderr 含該 rule id 與正確行號。
- **AC-O8-3** task-lint 程式碼區塊：`TL-FENCE`、`TL-BLOCK-SIZE`、`TL-BLOCK-TOTAL`、`TL-SQL`、`TL-CODE`、`TL-LINES` 各自在壞輸入上 exit 1；邊界值 15／40／250 行通過，16／41／251 行失敗。
- **AC-O8-4** task-lint 內容：`TL-PHRASE`、`TL-AC`、`TL-TC`、`TL-SCOPE` 各自在壞輸入上 exit 1；一個檔案有多個錯誤時全部列出，最後一行錯誤數正確。
- **AC-O8-5** scope-check：變更檔全在允許清單（含隱含允許）→ exit 0；任一檔不在允許清單 → `SC-OUT`；符合禁止清單 → `SC-DENY`（即使也在允許清單）；變更清單為空 → `SC-EMPTY`；找不到任務單 → `SC-NOTASK`；任務單缺 `### 要做` → `SC-PARSE`；以上皆 exit 1。glob 的 `*` 不跨 `/`、`**` 跨 `/`。
- **AC-O8-6** ac-coverage：讀 `vitest run --reporter=json` 的 JSON（`testResults[].assertionResults[]` 的 `fullName`、`status`）。每個 AC 至少有一個 `status` 為 `passed` 且 `fullName` 含 `(AC-…)`（含括號，避免 `AC-O8-1` 誤配 `AC-O8-10`）的測試；每個 TC 至少有一個通過的測試同時含 `(TC-n)` 與該列任一 `(AC-…)` → exit 0。缺少 → `CV-MISSING`；含該編號的測試有任何 `failed` → `CV-FAILED`；`skipped`／`pending`／`todo` 不算覆蓋；以上皆 exit 1。
- **AC-O8-7** fail-closed：三支 CLI 在缺參數、未知選項、檔案不存在、JSON 無法解析或缺 `testResults` 時 exit 1（`USAGE`／`INPUT`），不印 `OK`；未捕捉的例外也必須 exit 1。腳本不含 `|| true`、`continue-on-error`，也沒有吞掉錯誤後 exit 0 的 `catch`。
- **AC-O8-8** 只用 Node 內建模組（`node:` 開頭的 import），不新增套件、不改 `package.json`／`pnpm-lock.yaml`；不連網。

## 限制
- 只用 Node 內建模組；不新增套件、不連網、不讀環境變數以外的祕密。腳本是 ESM（`.mjs`），在 Node 24 直接執行，不需要 `pnpm install`。
- 測試寫成 `tooling/*.test.mjs`（`tooling/tsconfig.json` 沒有 Node 型別，`.test.ts` 無法 import `node:child_process`）；CLI 的 exit code 以 `child_process.spawnSync(process.execPath, …)` 實際執行斷言。
- 測試所需的 git 狀態一律用 fixture 檔表示；scope-check 只讀 `--changed` 清單，不自己呼叫 git。
- pgTAP 結果（TAP 輸出）不在本單範圍；只有 pgTAP 測試的 AC 在 ac-coverage 會判 `CV-MISSING`，由 O-010 擴充。
- 舊任務單（O-001～O-007、T-001～T-900）不需要通過 task-lint；本單不改它們。

## 驗證方式
`pnpm check` 跑到通過；任務單不另列指令。

## 結束時
1. 在指定的分支上 commit 並 push，不得動 main。
2. 把結果寫到 docs/reports/O-008.md：完成摘要、變更檔案、測試結果、未完成事項、需要人類決定的問題。
3. 測試結果、突變結果、權限被拒以 workflow 自動產生的摘要與 PR 觸發的 CI run 為準，報告不重貼。

## SRE 接線（Claude Code 不做；不是 AC；Claude 的 run 成功後由 SRE 在同一分支加 commit）
- `claude-run-task.yml`：Claude 步驟之前加 `Task lint` 步驟執行 `node tooling/task-lint.mjs docs/tasks/$TASK.md`；失敗則 Claude 不啟動，Notify 送 `outcome=task_lint_failed`（`run-task-outcome.sh` 與其測試一併更新）。

- `.github/pull_request_template.md`：依憲章 v6 §9 改版（拿掉 TechLead Review 勾選；加「自動驗證摘要（O-009 後）」與「QA 驗收留言（含 head SHA）」）；`docs/RUNBOOK.md` 記錄接線與實測。
