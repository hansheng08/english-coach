## 介面
`dataModeOrThrow` 的簽章與 T-018 的行為都不變（見 `docs/tasks/T-018.md`「介面」）。

TechLead 決定（②：資料模式規則改成單一來源，`apps/web/vite.data-mode.ts` 直接 import `tooling/data-mode-guard.mjs`）。理由：
- 沒有規則禁止：ESLint 的 `crossPackagePatterns`（ADR-008 修訂 2 決定 4）只擋相對路徑進 `packages/`；`.dependency-cruiser.cjs` 沒有任何規則管 `apps/web` → `tooling/`，`tooling/` 在 `options.exclude` 裡不會被追蹤；`adr008-11` 只管 import 測試碼，`data-mode-guard.mjs` 不是測試檔。
- 明文允許：O-023「介面」第 2 點「`validateBuildEnv` 必須與本模組規則等價（可 import 本模組，或同等實作）」；ADR-014 決定 1 只要求建置失敗。
- `vite.data-mode.ts` 只給 `vite.config.ts` 在建置時用，不進瀏覽器程式（不在 `apps/web/src/`，ADR-001 修訂 1 的「正式程式」指 `apps/web/src/**`）。
- 上一輪改用同等實作的原因是型別：`.mjs` 沒有型別宣告。做法是在 `tooling/` 加一份宣告檔 `tooling/data-mode-guard.d.mts`（TypeScript 對 `.mjs` 會找同名 `.d.mts`；宣告檔不會被輸出，不受 `apps/web` 的 `rootDir` 限制）。不改 `data-mode-guard.mjs` 本身，不在 `apps/web` 開 `allowJs`。

要求：
- `tooling/data-mode-guard.d.mts`：只宣告 `assertDataModeEnv`，參數型別 `unknown`，回傳 `{ ok: true; mode: 'mock' | 'supabase' }` 或 `{ ok: false; reason: string }`（照 O-023「規則」的註解），全部 `readonly`；不宣告實作裡沒有的匯出。
- `apps/web/vite.data-mode.ts`：呼叫 `assertDataModeEnv`；`ok: true` 回傳 `mode`，`ok: false` 丟 `Error`，訊息就是 `reason`。檔案裡不再有自己的規則（`VITE_SUPABASE_` 前綴、必填清單、模式清單、空白判斷都刪掉）。
- 如果照上面做仍要用 `@ts-ignore`、`any`、`allowJs` 或放寬設定才能通過 typecheck／lint，就**停下**，不要改回同等實作，寫進報告。
