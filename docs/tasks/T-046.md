## 目標
每天台北 03:30，`pg_cron` 經 `pg_net` 呼叫 `purge-audio`；函式用 secret 金鑰刪掉 `audio_expires_at` 已到的錄音檔，並把兩張表的 `audio_path` 設成 null，逐字稿與分數保留（AC-22、Q-06）；同一次執行再刪掉建立已超過 24 小時、沒有任何 `audio_path` 指到的孤兒錄音（§4.12.2.1）。

## 介面
`audio-purge.ts` 的型別照 ARCH v1.17 §4.12.2 的程式區塊（`OrphanObject`、`OrphanCursor`、`PurgeDeps` 的 `listOrphanCandidates`／`pathsInUse`、`PurgeDbClient`、`PurgeStats.orphan`、`PurgeRun`、`PURGE_ORPHAN_MAX_CALLS`、`purgeExpiredAudio`、`purgeOrphans`；ARCH v1.17），本單不另改名或改形狀。以下是 TechLead 補的決定：
```ts
// supabase/functions/_shared/db/service-db.ts：回傳型別同時滿足 DbClient 與 PurgeDbClient（§4.12.1、§4.12.2）
export function createServiceClient(env: SupabaseSecretEnv): DbClient & PurgeDbClient;
// supabase/functions/purge-audio/handler.ts（新增）；index.ts 只做組裝（見下）
export type PurgeHandlerDeps = { readonly env: Result<SupabaseSecretEnv, AppError>;
  readonly purge: (env: SupabaseSecretEnv) => Promise<PurgeRun>;   // v1.17：取代 Result<PurgeStats, AppError>
  readonly now: () => Date; readonly log: (line: string) => void };
export function createPurgeHandler(deps: PurgeHandlerDeps): (req: Request) => Promise<Response>;
```
- **`loadSupabaseSecretEnv`**：`SUPABASE_URL` 必填；金鑰先讀 `SUPABASE_SECRET_KEYS`（JSON，取 `default`，寫法同 `PublishableKeysSchema`），不能用時才讀 `SUPABASE_SECRET_KEY`；缺少 → `internal`，`message` 只有變數名稱。既有 `loadSupabaseEnv` 不改。
- **`requireServiceKey`**：只看 `apikey` 標頭，和 `env.secretKey` 做固定時間比較（不因第一個不同字元提早結束；長度不同直接算不符）；缺少或不符 → `unauthenticated`，`message` 不含任何金鑰。
- **`createServiceClient`**：`createClient(env.url, env.secretKey, …)`，`auth` 選項同 `createUserClient`（不保存 session）。**只在** `purge-audio/index.ts` 建立（組裝時呼叫一次、交給 `purgeDepsFrom`）；`handler.ts` 與 `audio-purge.ts` 都不呼叫、也都不 import `service-db.ts`（`audio-purge.ts` 只做 `PurgeDbClient` 的 type import）。§4.12.5 允許出現 `createServiceClient` 的檔案清單由 AC-T46-12 的測試固定。
- **`index.ts` 與 `handler.ts` 的分工**（§4.12.2，ARCH v1.17）：`index.ts` 只做組裝（讀 env、呼叫 `createServiceClient`、把 client 交給 `purgeDepsFrom`、把 `createPurgeHandler` 接上 `Deno.serve`）。不寫 log、不決定 HTTP 狀態、不直接呼叫 `purgeExpiredAudio`。`handler.ts` 的 `createPurgeHandler` 呼叫 `requireServiceKey` 與 `purge`（＝`purgeExpiredAudio`）、寫一行 log、依 `PurgeRun` 決定 200 或錯誤狀態碼；不建立 secret client。
- **`createPurgeHandler`** 處理順序：`env` 是 `err` → 500 `internal`；`requireServiceKey` 不過 → 401 `unauthenticated`；都不呼叫 `purge`，也不寫統計 log。之後呼叫 `purge` 拿到 `PurgeRun`：`error` 是 null → 200，body 是 `stats`（`failed > 0` 也是 200）；`error` 非 null → HTTP 狀態與 body 一律來自 `toApiErrorBody(error)`（不含統計；ARCH v1.18，Q5）：列出失敗是 `storage_failed` → 502；複查失敗是 `db_failed` → 500；到期階段用該階段自己的 kind（查詢／update 是 `db_failed`、`remove` 是 `storage_failed`），同樣走 `toApiErrorBody`。不把 `error` 非 null 一律寫成 500。每次執行**只寫一行** log：`purge-audio shadow=<s>/<p>/<f> evening=<s>/<p>/<f> orphan=<s>/<p>/<f>`，有錯時尾端加 ` error=<kind> phase=<shadow|evening|orphan>`（第一個錯誤的階段）；不含路徑、id、金鑰、錯誤 `message`（§4.12.2，ARCH v1.17）。
- **`purgeExpiredAudio`**（§4.12.2 刪除行為 1～4；回 `PurgeRun`，不丟例外、不寫 log，ARCH v1.17）補充：
  - 依序做 shadow 到期、evening 到期、孤兒（`purgeOrphans`）三個階段，彼此獨立；任一階段出錯其他照做，`error` 是第一個錯誤，`stats` 永遠完整（沒跑到的部分是 0）。
  - `selected` 是選出的筆數；`remove` 成功後，`clearAudioPath` 成功的列算 `purged`、回錯的列算 `failed`；`remove` 回錯時整批算 `failed`、不呼叫 `clearAudioPath`。選出 0 筆時不呼叫 `remove`。
  - `limit` 沒給時用 `PURGE_BATCH_LIMIT`；到期與孤兒共用同一個 `limit`。
- **孤兒清除**（§4.12.2.1；`purgeOrphans` 在兩張表的到期階段之後跑；QA 的 `docs/qa/orphan-audio-test-cases.md` v4 當驗收參考，本單的 TC 自己寫、不複製）：
  - **列出**：`listOrphanCandidates(now − 24 小時, limit, after)` → RPC `list_orphan_audio_objects`（`p_cutoff` 是 ISO 字串、`p_limit` 等於 `limit`）；不用 Storage list、不分前綴、應用層不再做「有列就拿掉」的初篩（M1，#123 已定案）。SQL 已排除有列物件、只看 `created_at` 且嚴格小於 `p_cutoff`、缺值不入選、排序 `created_at` 再 `name`。RPC 回傳不是預期形狀也算失敗。
  - **游標與次數**（Q1，ARCH v1.17）：第一次 `after` 是 null；之後是上一次回傳最後一列的 `{ createdAt, name: path }`，`createdAt` 用 RPC 回來的 ISO 字串原樣傳回（不經 `Date`，避免微秒被截斷而重複列出）；不論該批刪成功、`remove` 失敗或被複查拿光，游標都推進。停止條件：列出回傳 **0 筆**（不呼叫 `pathsInUse`／`removeObjects`，游標不推進，立刻結束迴圈）、或回傳少於 `limit` 但仍大於 0（以列出筆數判斷，不看複查後剩幾筆，游標推進後結束）、或已呼叫 `PURGE_ORPHAN_MAX_CALLS`（5）次、或列出／複查失敗。某次列出剛好回 `limit` 筆 → 一定再呼叫一次（用來確認有沒有下一頁；ARCH v1.18，Q6）；若下一次回 0 筆，套用上面的 0 筆規則，這次空的列出仍計入 `PURGE_ORPHAN_MAX_CALLS`。不存狀態，下次排程從頭開始。
  - **刪前複查**：列出回傳 **1 筆以上** 才對該批路徑呼叫一次 `pathsInUse`（RPC `audio_paths_in_use`，POST 帶陣列，不用 GET `in=(…)`），回傳的路徑從本批拿掉；剩下的才送 `removeObjects`（重用到期那個方法），剩 0 個不呼叫、游標照推；若列出筆數已小於 `limit` 就結束，否則繼續下一次。列出 0 筆見上，不跑複查。
  - **統計**：`selected` 是所有呼叫回傳筆數的總和（含複查拿掉的）；`remove` 成功算 `purged`、回錯整批算 `failed` 且不設 `error`；`selected >= purged + failed`。
  - **複查失敗**（Q3，ARCH v1.17）：`pathsInUse` 回 `err` → 這批不刪、`removeObjects` 0 次、不計 `purged`／`failed`；孤兒階段立刻停止，`error` 是 `db_failed`，`stats` 是當下的累計；不重試；不另寫 log（由 handler 那一行帶 `error=db_failed phase=orphan`）。
  - **錯誤**：列出失敗（含第 2～5 次）→ 孤兒階段停止、`error` 是 `storage_failed`（`op: 'list'`），已刪的不回復；`removeObjects` 的錯誤轉 `storage_failed`（`op: 'delete'`）；`pathsInUse` 的錯誤轉 `db_failed`；`message` 都不含路徑。
  - **contracts**：`packages/contracts/src/errors.ts` 的 `storage_failed.op` 加 `'list'`（§5.0.4），只加這個值。
  - **不碰的**：`tts`、`resume` bucket；只刪 `audio` bucket；不新增 Edge Function、`cron.schedule`、Storage `delete` policy；`audio-purge.ts` 只 type import `PurgeDbClient` 相關型別，不 import `service-db.ts`。
  - **未驗證的部分**：正式環境 `remove` 一次能送幾個路徑、5 批的耗時（G4 實測）；單元測試只用假 RPC 回應。
- **`purgeDepsFrom`** 的查詢：`listExpired` 照 §4.12.2 第 1 步（`audio_path` 不是 null、`audio_expires_at <= now`、依 `audio_expires_at` 遞增、`limit`），只選 `id`、`audio_path`、`audio_expires_at` 三欄（§4.12.5 例外表）；`clearAudioPath` 只送 `{ audio_path: null }`，條件是 `id` 與 `audio_path` 兩個都相等；`removeObjects` 對 `audio` bucket 一次送整批路徑。查詢與 update 的錯誤轉成 `db_failed`（訊息格式同 `runDb`，不含路徑）；`removeObjects` 的錯誤轉成 `storage_failed`（`op: 'delete'`，§5.0.4 的 `AppError`，訊息不含路徑）。
- **migration**（一個檔，`supabase/migrations/<時間戳記>_t046_audio_bucket_purge_cron.sql`；時間戳記取寫檔時的台北時間，必須比 `supabase/migrations/` 最新的檔案晚）：
  1. `audio` bucket：照 §4.12.1「建立方式」，`public = false`、`file_size_limit = 5242880`（5 MB），不設 `allowed_mime_types`。
  2. `storage.objects` 兩個 policy：`audio_select_own`（`select`）、`audio_insert_own`（`insert`），對象 `authenticated`，條件照 §4.12.1；不建 `update`、`delete` policy。
  3. 照 §4.12.3：兩個 `create extension if not exists`、`cron.schedule('purge-audio-daily', '30 19 * * *', …)`，呼叫內容照 §4.12.3。不寫任何 secret 值。
  4. 照 §4.12.2.1 的 SQL：`public.list_orphan_audio_objects(p_cutoff, p_limit, p_after_created_at, p_after_name)`（`plpgsql`；游標只給一個時 `raise` 錯誤碼 `22023`；給了就只回 `(created_at, name)` 嚴格大於游標的列；ARCH v1.17）與 `public.audio_paths_in_use(p_paths text[])`：`stable`、`security definer`、`set search_path = ''`、物件寫完整 schema 名、路徑用 `bucket_id = 'audio'` 加 `storage.foldername(name)` 比對每一段；兩支都 `revoke all` from `public, anon, authenticated`，只 `grant execute` 給 `service_role`。
  5. 部分索引 `shadow_attempt_audio_path_idx`、`evening_answer_audio_path_idx`（`where audio_path is not null`）。
- **`config.toml`**：在 `[functions.api]` 那段之後加 `[functions.purge-audio]`，兩行 `verify_jwt = false`、`import_map = "./functions/deno.json"`（CLAUDE.md §5 第 16 條）。

## 驗收標準
- **AC-T46-1**（§4.12.1）`loadSupabaseSecretEnv` 讀 `SUPABASE_SECRET_KEYS` 的 `default`；JSON 不能用或沒有 `default` 時改讀 `SUPABASE_SECRET_KEY`；缺 `SUPABASE_URL` 或兩個金鑰名稱都不能用 → `internal`，`message` 不含任何提供的值。
- **AC-T46-2**（§4.12.1）`requireServiceKey`：`apikey` 等於 `secretKey` → `ok`；缺少、不同、長度不同、只放在 `Authorization` → `unauthenticated`，`message` 不含任何金鑰。
