## 決定紀錄
- 版本：pnpm **12.21.0**（`packageManager`）、TypeScript **5.9.3**（5.x 最新）、ESLint **10.15.0**、typescript-eslint **8.73.0**（peer 支援 ESLint 10、TS `<6.1`）、dependency-cruiser **18.8.0**、Vitest **5.1.1**。`package.json` 用 `^`，lockfile 鎖實際版本。我是用 `npm view` 查最新版。
- 7 條 depcruise 規則名稱：
  1. `adr008-01-domain-imports-contracts-only`
  2. `adr008-02-contracts-imports-zod-only`
  3. `adr008-03-features-isolated`
  4. `adr008-04-supabase-js-only-in-api`
  5. `adr008-05-endpoints-via-registry`
  6. `adr008-06-paid-config-only-registry`
  7. `adr008-10-no-circular`
- `skipLibCheck: true`：**有用**（寫在 `tsconfig.base.json`）。原因：vitest 與 eslint 的 `.d.ts` 會參考 Node 型別，而我們不安裝 `@types/node`。`tooling/` 測試程式沒有 import 任何 `node:*`。`tsconfig` 另有 `"types": []`。
- `tsconfig.base.json`：`target ES2022`、`lib ES2023`、`module ESNext`、`moduleResolution Bundler`、`verbatimModuleSyntax`、`isolatedModules`、`noImplicitReturns`、`forceConsistentCasingInFileNames`、`esModuleInterop`。理由：純 ESM、由 Vite／Deno 打包，不需要 tsc 輸出 JS；DOM lib 留給 T-002 起的 `apps/web` 自己加。
- `tooling/tsconfig.json`：`composite`＋`emitDeclarationOnly`，輸出到 `dist/tooling`（`dist/` 已被忽略）。`rootDir` 設為 `..`，因為要 import `tsconfig.base.json`（`resolveJsonModule`）。
- `pnpm arch` 在資料夾不存在時怎麼不失敗：指令是 `depcruise --config .dependency-cruiser.cjs .`（掃根目錄），用設定檔的 `options.exclude` 排除 `tooling`、`docs`、`dist`、`coverage`、`.claude`、`.github`、`.git` 以及根目錄的設定檔，所以實際只會看到 `apps`、`packages`、`supabase` 的程式；沒有這些資料夾時輸出 `0 modules` 而成功。任務單寫「掃 `apps packages supabase`」，我是用這個方式達到同樣效果，不是把三個資料夾名稱放進指令。
- 測試用 dependency-cruiser：同一份設定經 `extractDepcruiseOptions` 取得，`cruise(['.'], { baseDir: 'tooling/fixtures/arch' })`，規則路徑完全沒有為了測試放寬。範例裡 import 的 `zod`、`@supabase/supabase-js`、`lodash` 沒有安裝，dependency-cruiser 把它們當成「無法解析的套件」並仍以套件名稱比對，規則照常觸發，不需要替代寫法。
- ESLint：
  - `strictTypeChecked`＋`projectService`；忽略清單除了任務單列的 6 項，還額外忽略 `eslint.config.js`、`.dependency-cruiser.cjs`、`vitest.config.ts`，因為它們不在任何 tsconfig 專案內，無法做型別檢查規則。
  - 為了避免 `no-restricted-syntax` 在重疊路徑上互相覆蓋，設定分成三個互不重疊的區塊（一般、`_shared/config/**`、`packages/domain/**`）。`fetch` 用 `no-restricted-globals`，已用測試證明沒宣告全域也能擋。
  - `@ts-expect-error` 一律禁止，除了 `**/*.test-d.ts`（CLAUDE.md §6「只能出現在型別測試」）；這個檔名慣例是我自己訂的，之後的型別測試單請沿用或調整。
  - 測試用 ESLint Node API 時疊加 `tseslint.configs.disableTypeChecked`，因為假檔名不屬於任何 tsconfig 專案；另有一個測試確認正式設定仍啟用型別感知規則。
- `.gitignore` 除了必備項目，另加 `.DS_Store`（這台機器每個資料夾都有，之前一直是未追蹤檔案）。
- `vitest.config.ts`（任務單說需要時才建）：有建。預設的 `include` 會撈到 `.claude/hooks/pushguard/*.test.mjs`（它們用 `node:test`，在 Vitest 下會壞），所以明確限定為 `tooling`、`packages`、`apps`、`supabase` 底下的 `*.test.ts`。

## 需要人類決定的問題
1. **額外依賴**：目前不需要 `@types/node`、`@eslint/js`、`globals`。`eslint.config.js` 與 `.dependency-cruiser.cjs` 被排除在 lint 之外，換取不裝這些。若 Architect 希望 lint 設定檔本身，才需要 `@eslint/js`／`globals`。後續單若要用 `node:*` 或 `process`，就會需要 `@types/node`。
2. **規則 #4 的範圍**：任務單表格寫「只有 `apps/web/src/api/**` 可以 import `@supabase/supabase-js`」，我照字面實作，也就包含 `supabase/functions/**`。如果 Edge Function 的 `_shared/db` 要用 supabase-js，這條規則會誤擋，請 Architect 在寫 `_shared/db` 之前確認。
3. **規則 #1 的範圍**：`packages/domain` 連 `node:*` 與 npm 套件都不能 import（只能 `contracts` 與自己），照 CLAUDE.md §4 字面。
4. **Deno 型別**：`supabase/functions/**` 的型別檢查方式仍待 T-003；目前 `Deno.env` 規則是純語法檢查，不依賴型別。
5. **規則可能的盲點**：`fetch` 規則只擋全域 `fetch` 與裸識別字；`globalThis.fetch(...)` 或 `const f = fetch` 這種寫法（後者會擋，前者不會）沒有額外覆蓋。`domain` 的 `throw` 規則也擋 `throw` 在測試檔裡的使用（`*.test.ts` 位於 `packages/domain/**` 時）；之後 T-002 起若 domain 測試需要 `throw`，請決定是否為 `*.test.ts` 放寬。
6. **pnpm 12**：任務單說用當下最新穩定版，所以是 12.21.0；`pnpm install` 的輸出有「supply-chain policies」檢查，行為與較舊版本的 pnpm 可能不同，請 TechLead 知悉。
