## 設計決定
- 「沒有 results」的解讀：`results: []`（未跑）算 skipped，得到 `CV-MISSING`。`results` 欄位整個不存在則算 `INPUT`。任務單 TC-3 與 TC-8 的說法有重疊，我取較嚴格（fail-closed）的讀法。
- 同一測試在多個 project 出現時，沿用現有 Vitest 規則：任一筆 `CV-FAILED` 優先，其次是任一筆通過。
- TC-10 的突變用具體輸入驗證，沒有真的改寫原始碼：每種削弱（skipped 或 expected-fail 當通過、壞 JSON 當無發現、不走巢狀 suites、取第一筆 result）都對應一個會變紅的斷言。
- 測試要讀暫存檔，所以用 `node:os` 的 `tmpdir` 在測試內建檔，沒有啟動 Playwright。
