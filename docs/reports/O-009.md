# O-009 報告

## 完成摘要
新增四支只用 `node:` 內建模組、fail-closed 的工具，並讓 `scope-check` 支援 `fix/Q-xxx` 分支：
- `run-mutants`：套用 QA 的 mutants.json 並以執行器驗證，每筆突變後立即還原目標檔。
- `verify-summary`：由 Vitest JSON、mutants 報告、execution 紀錄產生自動驗證摘要 Markdown。
- `report-lint`：檢查 `docs/reports/*.md`（標題、必要節、行數、貼上輸出、手打數字）。
- `comment-lint`：G3 PR 留言違規（TechLead Review、QA 本機重跑）。
- `task-file.mjs` 新增 `branchId`；`scope-check` 隱含允許 `docs/qa/mutants/<branchId>.json`。

## 設計決定
- 每支 CLI 都把 `run(argv)` 做成回傳 `{code, stdout, stderr}` 的純函式，沿用 O-008 的 `runCli`、`failure`、`parseArgs`。
- `run-mutants` 另外匯出 `execute`（回傳報告與 Finding），`runMutants` 只回傳 `MutantsReport`。可選參數 `timeoutMs`、`spawn` 供測試注入，CLI 不提供。
- 錨點錯誤（`MU-ANCHOR`）與執行器錯誤（`MU-RUNNER`）在報告裡記為 `unexpected`，讓摘要看得到非 `killed` 的 id。
- 還原只寫回該筆突變自己的目標檔，所以別的目標檔被改動時最後的 SHA-256 比對會抓到 `MU-RESTORE`；偵測到後再寫回原始內容。
- 測試的假執行器放在 `tooling/fixtures/o009/fake-runner.mjs`，所有突變都在 `os.tmpdir()` 的副本進行，測試沒有呼叫 vitest 或 pnpm。
- 現有 `docs/reports/O-008.md` 經 `report-lint` 的結果：通過（沒有任何 rule id），由測試固定。
- `ac-coverage` 本來就以分支字串比對任務單，對 `fix/Q-012` 不需修改，TC-24 以測試證明。
