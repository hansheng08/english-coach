## 設計決定
- `dataModeOrThrow`：`tooling/data-mode-guard.mjs` 是 `.mjs`，不在 `apps/web` 的 tsconfig 內，所以在 `vite.data-mode.ts` **同等實作**同一組規則（任務單允許）。
- jsdom：選「檔頭 `// @vitest-environment jsdom`」，不用 `projects`。原因：根目錄 `vitest.config.ts` 的 include 有 O-012 的測試守著，改成 `projects` 會讓它失敗。所以根目錄 `vitest.config.ts` 沒有修改；每個 DOM 測試自己 import `test/setup.ts`（`afterEach(cleanup)`＋可控的 `matchMedia` stub）。
- `apps/web/vitest.config.ts` 只在 `apps/web` 內直接執行 vitest 時使用，`pnpm test` 不經過它（我沒有刪檔權限，所以保留並加註解）。
- 下列元件測試以外的檔案以 `?raw`／`node:fs` 讀：`.env.example` 被 Vite 擋 `?raw`，所以 `static.test.ts` 用 `node:fs`，型別由 `apps/web/test/node-fs.d.ts` 只宣告 `readFileSync`（專案沒有 `@types/node`）。
- mock 的 `getSession` 一律回示範身分，所以閘門不需要判斷資料模式；畫面只看 `LoadedApi.preview` 是否為 `null` 來顯示「預覽：假資料」。
- E2E 用每個 spec 檔對應專案的 `testMatch` 區分視窗，沒有用 `test.skip`。
- `test/e2e/tsconfig.json` 把根目錄 `playwright.config.ts` 納入型別檢查與 ESLint，因此沒有改 `eslint.config.js`。
