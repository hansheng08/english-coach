## 4. 決定紀錄
- **tsconfig 輸出位置**：兩個套件都是 `outDir: ../../dist/<套件>`、`rootDir: "."`、`composite`＋`emitDeclarationOnly`＋`allowImportingTsExtensions`、`types: []`；`include` 為 `src/**/*.ts`、`test/**/*.ts`。輸出在 `dist/`，已被 `.gitignore` 的 `dist/` 忽略（`git status --short` 乾淨，§6 其他）。domain 另有 `references` 指向 contracts。
- **`/testing` 引用方式**：套件自我引用 `@english-coach/contracts/testing` 在 tsc、Vitest、dependency-cruiser 都解析得到（depcruise 解析成 `packages/contracts/test/index.ts`，見 §6 depcruise 輸出的 `result.test.ts`）。`result.test.ts` 用這個寫法；`testing.test.ts`、`audio.test.ts`、`ids.test.ts` 用 `../test/index.ts`（`testing.test.ts` 本來就在測那個檔案；後兩者行為相同，沒有統一是我的疏漏）。
- **範例怎麼解析 `@english-coach/*`**：新增 `tooling/fixtures/arch/tsconfig.json`（`paths` 對應到範例內的 `packages/contracts/src/index.ts` 與 `test/index.ts`），`arch-rules.test.ts` 用 `tsConfig: { fileName }` 傳給 `cruise`。沒有放寬任何規則。
- **ESLint 各區塊怎麼合併**（每個檔案只落在一個區塊）：
  - `no-restricted-imports`：①`packages/**`＋`supabase/functions/**`＝網址前綴＋跨套件＋副檔名；②其他 `.ts`／`.tsx`＝網址前綴＋跨套件。
  - `no-restricted-syntax`：A（domain 正式程式，含品牌型別）、A′（`taipei-date.ts`，不含品牌型別）、B（domain 測試）、C（`_shared/{providers,db,news}` 正式程式，含品牌型別）、C′（`registry.ts`，不含品牌型別）、D（`_shared/config` 正式程式，`asUnknownAs`＋品牌型別）、D′（config 測試，只有 `asUnknownAs`）、E（其餘正式程式，含品牌型別）、E-sub（`contracts/src/ids.ts`、`audio.ts`，不含品牌型別）、E′（其餘所有測試程式，可以 throw、不含品牌型別）。
  - 品牌型別選擇器：`TSAsExpression`／`TSTypeAssertion` 的 `typeAnnotation.typeName.name` 比對決定 5 的 10 個名稱。
- **其他實作決定**
  - `providers.ts`：T-002 的 `Tier`、`Capability`、`ProviderErrorKind` 三段逐字不變；只在檔案最上面加了 `import`，其餘接在後面。`index.ts` 保留 T-002 那一行（只改 `.ts`），其餘另外匯出。
  - 新增的架構範例 `packages/domain/src/x-testing.test.ts`（任務單第 3 節 #5 寫的是 `x.test.ts`）：我另開新檔而不是改 T-002 的 `x.test.ts`，以免 T-002 的範例結果變動。

## 11. 需要人類決定的問題
1. **WAV 邊界行為（§5.0.5 沒寫清楚；測試名稱標 `UNDECIDED`）**：(a) `maxDurationMs` 當成「含」（剛好 30 s 通過）；(b) `data` chunk 的大小大於檔案實際長度時，用實際長度算 `durationMs`（不拒絕）；(c) `WAVE_FORMAT_EXTENSIBLE`（格式碼 `0xFFFE`）一律當成非 PCM 拒絕——有些錄音工具會輸出這種 16-bit 單聲道檔，做 `/shadow/attempts` 的前端錄音時要確認瀏覽器實際輸出。
2. **`toApiErrorBody` 丟掉了 `entity`、`op`、`category`**：`ApiErrorBodySchema` 沒有這三個欄位，所以 `not_found`、`conflict`、`storage_failed`、`news_unavailable` 回前端時只剩 `kind`／`message`／`retryable`。畫面文字範本（「找不到這筆{項目}」）需要 `entity`——要不要在 schema 加 `entity`？這會改 §5.0.4，所以我沒有做。
3. **ADR-008 `adr008-02t`**：contracts 測試不能 import `zod`，所以 schema 型別測試只能用 `schema['_output']`；如果之後要在測試裡用 `z.infer`，需要 Architect 放寬 `02t`。
4. **T-002 留下的盲點沒有處理**：動態 `import('npm:…')`、`Promise.reject` 繞過 `throw` 規則（不在本單範圍）。
5. **`packages/domain` 還沒有 `test/` 輔助檔**：`@english-coach/contracts/testing` 目前只有 contracts 自己的測試與 arch 範例用到；`packages/domain/test/` 等 T-008 再建。
