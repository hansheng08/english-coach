# T-019 報告

## 完成摘要
目標：讓 App 可安裝、SW 只快取外殼、有新版時顯示卡片、斷線時顯示提示、`theme-color` 跟著主題。
- manifest 與圖示：`apps/web/vite.pwa.ts` 從 `docs/design/tokens.json` 讀 `color.hero.light` 當 `theme_color`／`background_color`；四張圖示建置時從 `docs/design/assets/icons/` 原樣輸出到 `icons/`（不 commit PNG）；缺任何一張建置就失敗，錯誤訊息列出每個缺的檔名，且一張都不輸出。
- SW：`registerType: 'prompt'`、`generateSW`、precache 只含 html／js／css／webmanifest 與 `icons/*.png`，沒有 runtime caching。
- 斷線條、離線開啟面板、新版卡片、`.sysbars`（sticky、z-index 45）都在 `apps/web/src/pwa/`，由 `App.tsx` 的 `Layout` 組起來。
- `theme-color`：`index.html` 加兩個帶 `media` 的 meta；`ui/theme.ts` 加 `applyThemeColor`（`system` 恢復兩個、`light`／`dark` 只留一個不帶 `media`，重複呼叫不增加）與 `syncThemeColor`，啟動（`main.tsx`）和 `setThemePreference` 之後都會呼叫。
- `pnpm check` 在本機通過。

## 設計決定
- **不用 `virtual:pwa-register`**：它需要 `workbox-window`，在 pnpm 嚴格模式下 `apps/web` 解析不到（建置失敗，實測）；任務單與 CLAUDE.md 第 5 條不准加 workbox 相關依賴。改在 `pwa/register.ts` 自己註冊 `/sw.js`，偵測等待中的 SW，按「更新」時送 `SKIP_WAITING`、接手後重新載入一次（generateSW 的 `sw.js` 本來就處理這個訊息）。任務單寫「`register` 預設是 `registerSW`」，所以 `watchForUpdate` 沒傳 `register` 時什麼都不註冊，`main.tsx` 傳 `registerServiceWorker`。原因之二：`apps/web/vitest.config.ts` 在範圍外，vitest 沒有 PWA 外掛，解析不到虛擬模組。
- **E2E 如何注入新版**：只有預覽（mock）建置認 `?pwa=update`（`main.tsx` 以 `runtime.preview !== null` 判斷，畫面元件不判斷資料模式），用 `previewUpdateRegister` 一註冊就當成有新版；正式建置的 `preview` 為 null，這個參數無效。
- 「要不要顯示新版卡片」只在 `pwa/update.ts` 的 `shouldShowUpdatePrompt()`，目前恆為 `true`。
- 離線面板只在「開啟 App 時就離線」才出現（`Layout` 的 `openedOffline`）；開著時才斷線，內容照舊，只多斷線條。連線恢復後面板換回頁面。
- `.sysbars` 的 `padding-top` 用 `env(safe-area-inset-top)`，預覽條元件沒改。
- 手機上卡片出現時，內容區包一層 `padding-bottom: 184px`（只在 <900px）。
- Node 內建模組的型別（`fs`、`path`、`os`、`url`）只宣告用到的函式，放 `apps/web/test/node-builtins.d.ts`，沒有裝 `@types/node`。
