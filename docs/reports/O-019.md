## 設計決定
- 解析方法：預設 `resolveRelated` 呼叫 `pnpm exec vitest related <檔> --run --reporter=json --outputFile=…`。它用 Vitest 的 import graph，所以能涵蓋 barrel re-export 與 QA 探針。結果取 `testResults[].name` 轉成 repo 相對路徑。
- 快取：每個不重複的 `file` 在乾淨樹上（套用突變之前）解析一次。
- 非空清單：把測試檔路徑附加在 runner 後面（既有 runner argv 加上檔名），不再跑完整套件。
- 0 個相關測試：該筆用與 baseline 相同的 runner 跑完整套件，不會因 `passWithNoTests` 的 exit 0 或空報告而判 KILLED。
- 解析失敗（resolver 回 `{ rule: 'MU-RELATED', error }`、丟例外、逾時、輸出不可用、格式不符）：該筆 `unexpected`、finding `MU-RELATED`，不套用突變，目標檔因此不變。
- 注入點：`execute({ …, resolveRelated })`。未注入時，只有預設 runner 會用 import graph 解析；CLI `--` 之後的自訂 runner 維持 O-009 的完整套件行為。所以 O-009 既有測試不需要改動。
- CLI 參數、報告 JSON 形狀與既有規則代碼都不變，只新增 `MU-RELATED`。
