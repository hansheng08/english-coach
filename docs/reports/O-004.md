## ADR-009 (2) staging 部署實驗計畫（只列，不建立任何資源、不加 secret）

目的：在 T-003 之前證明「部署包含 `packages/contracts`」。CLI 3.2.0 沒有 `functions deploy --dry-run`、本機也找不到 eszip，CI 不得對正式專案部署。前端 Vite／T-018 `bundle` job **不算**。

### Hansheng 需要提供的（名稱與權限，不是密鑰值）
- 一個**專用 staging** Supabase 專案（或明確授權新建），與正式環境分開。
- 要寫入 GitHub Environments／Secrets 的**名稱**建議：`SUPABASE_ACCESS_TOKEN`（或官方 CLI 當下要求的 token 名稱）、`SUPABASE_PROJECT_REF`（project ref，不是 token）。本單不寫入、不請人把值貼到聊天。
- 權限／角色：能在該 staging 專案部署 Edge Function、並能刪除該 Function 或整個專案；token 範圍盡量只限該專案。核准人：Hansheng（必要時幕僚長轉達）。
- 明確一句核准：允許在 staging 跑一次 `supabase functions deploy`（僅此專案、可回滾）。

### 實驗步驟（核准並提供 secret 名稱／專案後才由後續單執行）
1. 用探針或 T-003 最小 `api`（import `@english-coach/contracts`）對 **staging** 部署，不要對正式專案。
2. 部署後證明含 contracts：呼叫 health（或同等路徑）確認 contracts 型別／錯誤本體可用；若平台提供部署產物／bundle 下載，再搜尋 `english-coach/contracts` 或 `packages/contracts`。
3. 把 CLI 原始輸出與 run 連結寫進報告。成功才能關閉 ADR-009 (2) 的 UNCONFIRMED。
4. 不把此次部署當正式發佈。

### 回滾
- 刪除 staging 上該 Function（或刪除整個實驗專案）。
- 撤銷／輪換此次使用的 access token。
- 從 GitHub Environment 移除對應 secret（若已加上）。
- 文件標明實驗結束，不把 staging URL 當正式環境。
