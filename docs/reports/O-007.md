## 1. 完成摘要
- `verify-push.sh` 不再 `git fetch`。改用 Verify 步驟的 `GH_TOKEN`（`github.token`）：`gh api repos/<repo>/git/ref/heads/<branch>` 嚴格取單一 ref 物件與 40 位 SHA，再用 `gh run list --event push` 輪詢同 SHA、同分支的 push run。所有錯誤都 exit 1，並把 `verify_reason` 寫進 `GITHUB_OUTPUT`。
- `run-task-outcome.sh` 新增 `verify_failed`（Claude 成功、Verify 失敗）與 `summary_failed`，以及 `--json` 模式。Notify 的 `claude-task-finished` payload 保留原欄位，另加 `claude_outcome`、`verify_outcome`、`summary_outcome`、`verify_reason`。只有三步全 success 才是 `success`；Verify 失敗時該步驟與 job 仍是紅燈。
- `claude-run-task.yml` 的 `anthropics/claude-code-action@v1` 釘到 `eb56b6666facdbd501035f4a0269d8caee2e7a8b`（`# v1 (v1.0.289)`）。這正是 run 45323782247 實際下載的 SHA，程式碼與當時的 `@v1` 相同。
- `claude-permission-check.mjs` 新增三項檢查：checkout 必須 `persist-credentials: false`；verify-push 不得 `git fetch`，且 Verify 步驟要帶 `GH_TOKEN`；action 必須釘 SHA。另附 M19～M25 突變測試。
