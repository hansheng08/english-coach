## 設計決定
- `NewsRewriteResponseSchema` 用 `.transform`：先做原始形狀驗證，再正規化（trim、壓空白、`’`／`‘` → `'`）、取第一個符合的句子、依 T1 產生 `rewritten_text`，最後交給 `NewsArticleContentSchema.safeParse`，其 issue 併入 transform 的 issue。這樣 adapter 的那 1 次自動重試涵蓋所有規則。
- `NewsChunkSchema` 負責單一 chunk 的 C2、C3；`NewsArticleContentSchema` 的 `superRefine` 負責 S、T、C1、C4。issue 訊息只有規則代號與索引（例如 `C4 chunk 2`）。
- 正文放進 prompt 前，先把正文裡出現的分隔標記字串移除，避免正文自己結束資料區塊（提示注入的基本防護，超出 §11.3 的最小要求但不改變介面）。
- 假 LLM 依請求自帶的 `schema` 做 `safeParse`，失敗回 `invalid_response` 且不重試；也可直接回指定的 `ProviderError`。
- 判定 prompt 的使用者段格式：`Category: <代號>`、`Title: <標題>`、分隔標記包住的正文前 300 字。
- 與 ARCHITECTURE §11.3 沒有不一致之處。
