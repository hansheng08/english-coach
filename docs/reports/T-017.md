- 新增 `loadAzureSpeechConfig`（`provider-keys.ts`）：讀 `AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`，缺少時訊息只列變數名稱，region 先 trim、轉小寫再用 `^[a-z0-9]+$` 檢查。

- TC-1～TC-20 都有測試，測試名稱含 AC 與 TC 編號。用到依文件樣本的測試名稱含「未驗證」。
- 沒有真實 Azure 回應樣本：Azure 帳號還沒開，所有回應格式都只是照文件，要等 A-004 驗證。

## 設計決定
- `classifyAzureError` 加了第三個選用參數 `apiKey`（預設空字串），讓它能在截斷前先遮蔽金鑰。只傳兩個參數時行為和任務單介面相同。
- 回應的 `Display`、`Words` 缺少時分別當 `''`、空陣列，只有 `RecognitionStatus` 與 `PronScore` 缺少才算 `invalid_response`，任務單沒有規定這兩個欄位。
- `Words` 裡某個字缺 `Offset` 或 `Duration` 時整個回應算 `invalid_response`。
- 送出 WAV 位元組時用 `slice()` 複製一份，因為 `BodyInit` 的型別只收 ArrayBuffer 底層的位元組。
- TC-20 要用 `node:fs`，但 `supabase/functions` 沒有 `@types/node`，所以在 `azure-speech/test/node-fs.d.ts` 只宣告用到的兩個函式（比照 `apps/web/test/node-fs.d.ts`）。
