## 決定紀錄

### 10 條 depcruise 規則的實際寫法（`.dependency-cruiser.cjs`）
- 共用常數：`TEST = '(^|/)test/|\\.test(-d)?\\.ts$'`；`VITEST = '^(@?vitest)($|/)|^@vitest/|node_modules/(vitest|@vitest)/'`；`ZOD = '^zod($|/)|node_modules/zod/'`。
- `01`：`from { path: ^packages/domain/, pathNot: TEST }`，`to { pathNot: ^packages/(domain|contracts)/ }`。
- `01t`：`from { path: testOf('packages/domain') }`，`to { pathNot: [^packages/(domain|contracts)/, VITEST] }`。
- `02`：`from { path: ^packages/contracts/, pathNot: TEST }`，`to { pathNot: [^packages/contracts/, ZOD] }`。
- `02t`：`from { path: testOf('packages/contracts') }`，`to { pathNot: [^packages/contracts/, VITEST] }`。
- `03`、`05`、`06`、`10`：不變。
- `04`：`from { pathNot: ^(apps/web/src/api|supabase/functions/_shared/db)/ }`，`to { path: [^(npm:|jsr:)?@supabase/, node_modules/@supabase/] }`。
- `11`：`from { pathNot: TEST }`，`to { path: TEST, pathNot: node_modules/ }`。
- **偏差**：任務單的規則是「`from` 是 `^packages/domain/` 的測試檔」。dependency-cruiser 的 `path` 只有一個 regex，無法寫「且」，所以用 `testOf(dir)` 產生 `^dir/test/|^dir/.*/test/|^dir/.*\.test(-d)?\.ts$`，與 `TEST` 的比對結果相同。我原本寫成 `^dir/(.*/)?test/`，被 dependency-cruiser 以「unsafe regular expression」拒絕（巢狀量詞），所以拆成兩個選項。

### `npm:`／`jsr:` 範例在 dependency-cruiser 裡被記成什麼
`supabase/functions/api/bad-npm.ts` 的依賴被記成（`modules[].dependencies[]`）：
```
{"module":"npm:@supabase/supabase-js@2","resolved":"npm:@supabase/supabase-js@2","couldNotResolve":true,"dependencyTypes":["unknown"]}
```
也就是 `to` 是原字串 `npm:@supabase/supabase-js@2`，規則裡的 `^(npm:|jsr:)?@supabase/` 抓得到。範例裡的 `vitest`、`zod`、`@supabase/supabase-js` 因為 `tooling/fixtures/arch` 下沒有 `node_modules`，也以裸名稱（`couldNotResolve: true`）出現；真實專案裡 `vitest` 會解析到 `node_modules/.pnpm/vitest@…/node_modules/vitest/…`，兩種寫法 regex 都涵蓋（真實專案的情況由 `providers.test.ts` 的 import 驗證，`pnpm arch` 沒有違規）。

### ESLint 各區塊怎麼避免互相覆蓋
`no-restricted-syntax` 的區塊互不重疊（每個檔案只落在一個區塊）：
- A：`packages/domain/**` 正式程式 → `as unknown as`、`Deno.env`、時鐘／亂數、`throw`。
- B：`packages/domain/**` 測試程式 → 同 A 但沒有 `throw`。
- C：`_shared/{providers,db,news}/**` 正式程式 → `as unknown as`、`Deno.env`、`throw`。
- D：`_shared/config/**` → 只有 `as unknown as`。
- E：其餘所有檔案（`ignores` 排除 domain、config、`_shared/{providers,db,news}`）→ `as unknown as`、`Deno.env`。
- E'：`_shared/{providers,db,news}/**` 的測試程式 → 同 E。

其他規則（`no-restricted-imports`、`no-restricted-globals`、`no-restricted-properties`）各自是獨立規則，沒有和上面競爭。測試程式的路徑用 `**/*.test.ts`、`**/*.test-d.ts`、`**/test/**`，與 depcruise 的 `TEST` 同義。

## 需要人類決定的問題
1. **`.tsx` 測試檔**（TASKS §5 第 20 點）：依任務單沒有改測試檔 regex，所以 `x.test.tsx` 目前被當成**正式程式**（不能 `throw`、不能 import `vitest`；depcruise 的 `01t`、`02t`、`11` 也不認它）。若前端要寫 `.test.tsx`，要先決定怎麼算。
2. **`no-restricted-imports` 的盲點**：只擋靜態 `import`／`export … from`，不擋動態 `import('npm:…')` 與 `require`。depcruise 的 `04` 只對 `@supabase/*` 有效；其他 `npm:`／`jsr:` 套件只靠 ESLint 擋。
3. **`throw` 規則的盲點**：只擋 `throw` 陳述式；`Promise.reject(...)`、`async` 函式內被拒絕的 Promise、呼叫會 `throw` 的外部函式，ESLint 都擋不到（那要靠「外部呼叫在模組內 `catch`」的約定與 code review）。
4. **pushguard 與 `$(…)`**：我用 `gh run list` 查 CI 時，一度想用 `$(gh …)` 把 run id 放進變數，被 pushguard 的「子殼層內的 `gh`」規則擋下（這是 O-001 的設計，符合預期）。只是提醒：之後單的 CI 輪詢要分兩步寫，不能在同一行用命令替換。
5. **規則 `04` 與前端 `apps/web`**：現在 `04` 對整個 repo 都適用（除了兩個出入口），包含 `tooling/`；`tooling/` 被設定檔 `exclude` 排除，所以目前不受影響，之後若 `tooling/` 需要 `@supabase/*`，要另外決定。
