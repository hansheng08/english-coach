## 設計決定
- migration 命名前自查：`origin/main` 的 `supabase/migrations` 有 6 個檔，最大時間戳記是 `20261128100001`（T-032），小於 `20261129000101`，所以照任務單用這個檔名。
- 用量參數：`sumPaidUsageThisMonthNtd`（T-020）還不在 main，`api/plan.ts` 與 `daily-prep/index.ts` 各有一個呼叫點暫傳字面 `0`，程式註解已記；T-020 的用量接線要把這兩處換成函式。
- 租約判斷用 `deps.now()` 減 180 秒；重新認領時 `claimed_at` 也寫 `deps.now()`；`reclaim`、`insertPending`、`complete`、`fail` 回 `boolean`。
- `PlanStore` 需要鏈式查詢，所以在 `client.ts` 新增 `PlanQuery`／`PlanDbClient`／`planDbClientFrom`，`createUserClient`、`createServiceClient` 的回傳型別多一個 `plan` 欄位（`DbClient` 介面沒改）。
- `readFallbackArticle` 的回傳多帶 `sentences`、`chunks`，因為退回舊文章時跟讀句要從它來。
- `runPrepare` 回 `{ plan, existing }`（`preparePlan` 包它），daily-prep 才分得出 ready／existing／failed 三種筆數。
- ESLint 禁止在 index.ts 直接用 `fetch` 或 `globalThis.fetch`；真的 fetch 改由 `providers/wiring.ts` 匯出 `realFetch`，兩個 index.ts 從那裡拿。
- 失敗原因：只有供應商類錯誤（判定、改寫、`deps.llm`）退回舊文章；`db_failed` 這類錯誤直接寫 `failed`（`step: news`）。
- 因 tooling 專案不能 import contracts，migration 的 `error` 清單與 `APP_ERROR_KINDS` 的比對拆成兩半：tooling 比對 migration 與寫死的清單，`plan.test.ts` 把 `APP_ERROR_KINDS` 釘在同一份清單。
